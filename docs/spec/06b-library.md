## 0. Поправки к `SWIFT_SPEC.md` §9.2 и §15

1. §9.2 «фильтры по виду (переводы, словари, толкования, параллельные места, подстрочники, аудио, карты)»: во Flutter **7 видов**: «Переводы · Комментарии · Словари · Карты · Иллюстрации · Аудиокниги · Параллельные места». «Подстрочников» и «Толкований» как видов нет (подстрочники — переводы с `features.interlinear`; толкования называются «Комментарии»).
2. §9.2 «переключатель включения небиблейских модулей (и свайп)»: на iPhone это системный переключатель; **свайп отдельно не реализован** (`RowSwitch` с жестом работает только вне нативного стекла iOS 26).
3. §9.2 «Сетевые переводы… главы по одной, хранятся недолго»: точнее — не более **480 стихов** и не дольше **14 суток** (§6.3). «helloao» — это **не** чтение по сети: перевод скачивается целиком одним файлом и становится обычным (§6.5).
4. §15 «основной перевод языка интерфейса (для кириллических — Синодальный, иначе BSB)»: точнее — таблица по языкам (§8.2): для `cs, de, en, es, fr, hi, it, ja, ko, pl, pt, sr, sw, zh` — свой полный перевод; для `ru, uk, be, bg` — `rst-plus` (Синодальный); для `hy, id, ro` и всех остальных — `bsb`; а для `uk, be, hy, id, ro` (полной Библии на языке нет) дополнительно ставится Новый Завет на родном языке.
5. §15 «Одно уведомление «Добавлено для изучения: …»» верно для первого запуска; у пользователей, начавших раньше, есть ещё три отдельных (§8.5).

## 1. Что такое модуль и где он лежит

### 1.1. Файлы
Каждый установленный модуль — **один файл SQLite** `modules/<id>.db` в «Application Support» приложения (папка `modules`). Установка идёт во временный `<id>.db.part`, затем файл **переименовывается** (атомарно; оборванная установка оставляет `.part`, который при просмотре папки игнорируется — берутся только `*.db`).
Рядом — `modules/disabled.json`: JSON-список `id` **выключенных небиблейских** модулей (§3.10); повреждён → все включены.
В базе модуля таблица `meta(key TEXT PRIMARY KEY, value TEXT)`; строка `json` — описание модуля (JSON без тяжёлых полей `books/entries/refs/places/wordIndex/chapters`), для переводов в нём ещё `bookList: [{id, name, short, chapters:N}]`; для модулей из каталога — `catalogVersion` (строка версии из каталога); для импортированных файлов — `origin: "file"`, `stats` (§5.5) и **нет** `catalogVersion`.
Сканирование (`_scan`) читает `meta.json` у каждого `*.db`; файл без этого или битый пропускается молча.

### 1.2. Типы модулей (`type`)
`bible` · `commentary` · `dictionary` · `maps` · `illustrations` · `audio` · `crossrefs`. Для словарей ещё `dictionaryKind`: `strongs` (ключи — номера Стронга) или `words` (ключи — слова).
Названия (`moduleTypeNames`, единственное число): «Перевод Библии», «Комментарий», «Словарь», «Карты», «Параллельные места», «Аудиокнига», «Иллюстрации».
Группы в окне (`moduleSections`, множественное число и порядок показа): «Переводы», «Комментарии», «Словари», «Карты», «Иллюстрации», «Аудиокниги», «Параллельные места».
Особые признаки (`features`): `strongs`, `morphology`, `headings`, `italics`, `interlinear` (подстрочник), `helper: true` (служебный: сейчас только `vulg-interlinear`; в списках переводов, поиске, выборе основного скрыт, но в библиотеке виден).
Короткие имена-исключения (`shortModuleNames`): `desp-notes → «Десницкий»`, `otnt-notes → «Откр. НЗ»` — подменяют `name` и в каталоге, и у установленных.

### 1.3. «Включён» / «выключен»
- **Переводы выключить нельзя.** Остальные виды — можно (`setEnabled`): выключенный модуль остаётся в библиотеке (строка бледнеет), но **исчезает** из `ModuleStore.installed` — словари, комментарии, карты, поиск и т. п. его не видят (`allInstalled` его возвращает — только для библиотеки).
- Решение хранится по `id` и **переживает обновление и переустановку**; при удалении записи убирается.
- Любая установка, удаление, импорт, включение/выключение увеличивает `ModuleStore.changes` (счётчик): окна, зависящие от списка модулей, перечитывают его.
- После изменения `HomeScreen._repair()` вызывает `panes.repairModules()`: панель, чей перевод исчез (удалён/недоступен), переходит на **основной** перевод (если он есть, иначе первый установленный) — **место чтения сохраняется** (`PaneState.ref` ← живая позиция).

### 1.4. Ключи prefs этой области
| Ключ | Тип | Что |
|---|---|---|
| `settings` → `primaryModule` | строка в JSON настроек | основной перевод; по умолчанию `rst-plus`; на самом первом запуске ставится `homeBible()` (§8.2) |
| `bootstrapped` | bool | стартовая установка уже начиналась (§8.3) |
| `lateStarter` | JSON-список id | модули, по которым доустановка уже пробовалась (§8.3) |
| `welcomePending` | bool | показать приветствие (`06c-shell.md` §1) |
| `newsSeen` | строка | id последней виденной записи «Что нового» |

Служебные ключи `bootstrapped`, `lateStarter`, `errorLog` в файл «Мои данные» не попадают (`serviceKeys`); `newsSeen` (строка) — попадает вместе с остальными пользовательскими; `welcomePending` (bool) не попадает: в файл идут только строковые значения.

## 2. Каталог

### 2.1. Источники (`ModuleStore.catalog`)
**Встроенный каталог** — три файла сайта, скачиваются одновременно (`download`: сначала `https://aobible.app/`, при любом сбое — зеркало `https://dubossarets-wq.github.io/ao-bible/`; после первого успеха с зеркала дальше всё идёт с него до перезапуска; таймаут соединения 20 с, «встала» загрузка на 30 с → ошибка):
- `modules/catalog.json` — обязателен: `{format: "aob-catalog", formatVersion: 1, modules: [...]}` (118 модулей: bible 78, dictionary 20, commentary 9, audio 5, crossrefs 3, maps 2, illustrations 1);
- `modules/catalog-more.json` — **необязателен** (нет — молча пусто): те же записи для переводов **API.Bible** (164, поле `online`) и **bible.helloao.org** (1423, поле `helloao`); старые версии приложения его не читают;
- `modules/lang-names.json` — необязателен: `{код_языка: {язык_интерфейса: название}}` (названия языков модулей на 22 языках; собирает сайт по ICU, редкие — запасное английское `languageEnglish` из записи).
Результат (список) **запоминается на 2 минуты** (окно перевода, библиотека, «О приложении» просили его при каждом открытии); при ошибке запоминание сбрасывается.
Разбор JSON — в отдельном потоке.

**Свой каталог** («Источник каталога», §3.12): `catalog(url: …)` скачивает адрес напрямую (без зеркала), понимает gzip (по сигнатуре `1f 8b`). Ошибки (тексты точные):
- не скачалось → **«Не удалось подключиться к {url}. Проверьте адрес и интернет.»**
- сервер ответил не 200 → **«Сервер ответил ошибкой {status} для {url}.»**
- не JSON / нет `format == "aob-catalog"` / `modules` не список → **«По этому адресу нет каталога в формате aob-catalog.»**
Адреса `url`/`urlGz` в записях разрешаются **относительно адреса каталога**, запись помечается `_abs` (полный адрес, без зеркала).

### 2.2. Запись каталога (`CatalogEntry`)
| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | идентификатор (имя файла `<id>.db`) |
| `type` | строка | по умолчанию `bible` |
| `name` | строка | короткое имя (подменяется `shortModuleNames`), по умолчанию `id` |
| `title` | строка | полное название, по умолчанию = `name` |
| `description`, `author`, `source`, `license` | строка | в подробностях; `source` — адрес или описание |
| `language` | строка | код языка (`ru`, `en`, `grc`, `la`…), по умолчанию `ru`; пустой — в группу «Другие» |
| `version` | строка | версия в каталоге; **сравнивается с установленной** (§3.8) |
| `features` | объект | см. §1.2 |
| `versification` | строка | нумерация стихов (все — `synodal`, §7) |
| `url`, `urlGz` | строка | файл модуля, относительно `modules/` сайта (или полный адрес); если есть `urlGz` — берётся он (gzip) |
| `size`, `sizeGz` | число (байт) | размер (показывается `sizeGz`, иначе `size`) |
| `dictionaryKind` | `strongs`/`words` | у словарей |
| `unavailable` | bool | `true` — нет свободной электронной версии: скачать нельзя |
| `translation` | строка | у аудио — к какому переводу относится |
| `scope` | список из `ot`/`nt`/`dc` | что в переводе (для фильтра «Что в переводе» в окне выбора перевода) |
| `added` | дата `ГГГГ-ММ-ДД` | когда появился в каталоге; если с тех пор прошло **< 7 суток** — значок «Новый» |
| `languageName`, `languageEnglish` | строка | у helloao: название языка → запасное название |
| `replaces` | — | в приложении **не используется** (подсказка для сайта: `lopukhin` заменяет `lopukhin-1…3`) |
| `online` | `{api, dbl}` | **перевод по сети** (API.Bible, §6): не скачивается, а «добавляется»; `url` = `api/<api>.json` (список книг) |
| `helloao` | `{id, sha, verses}` | перевод bible.helloao.org: `url` — полный адрес `https://bible.helloao.org/api/<id>/complete.json` (§6.5) |

Название языка модуля (`langName(code)`): пусто → «Другие»; **не русский интерфейс** → `langDisplayNames[интерфейс][код]` (таблица `intl_data.dart`, ~41 язык × 22 интерфейса, пример: в немецком `ru → «Russisch»`); иначе (в русском интерфейсе) → русские названия `_langNames` («Русский», «English», «Китайский», «Хинди», «Испанский», «Арабский», «Французский», «Португальский», «Индонезийский», «Немецкий», «Японский», «Турецкий», «Суахили», «Вьетнамский», «Тагальский», «Корейский», «Персидский», «Итальянский», «Польский», «Українська», «Румынский», «Нидерландский», «Новогреческий», «Шведский», «Чешский», «Сербский», «Албанский», «Армянский», «Хорватский», «Датский», «Норвежский», «Белорусский», «Эсперанто», «Иврит», «Греческий» (`grc`), «Латынь», «Церковнославянский», «Сирийский»), затем `lang-names.json` (в языке интерфейса → английский → английское из каталога), затем сам код **заглавными** (`XYZ`). В нерусских интерфейсах порядок такой: `langDisplayNames` → `lang-names.json` (язык интерфейса → английский → из каталога) → русская таблица `_langNames` → код заглавными.
Порядок языков (`langRank`): в том же порядке, что список `_langNames` (русский, English, китайский, хинди, … древние языки в конце), неизвестные — после известных, пустой код — последним.

## 3. Окно «Библиотека модулей» (`LibrarySheet`)

### 3.1. Откуда открывается и куда ведёт
- «Ещё» → **«Библиотека модулей»** (пункт всегда есть, лист «Ещё» остаётся под ним, назад — крестик возвращает); «Настройки» → «Библиотека модулей» («Переводы, словари, аудиокниги»); экран первой установки при ошибке (кнопка «Библиотека модулей»); окно выбора перевода → «Другие переводы» (сразу вкладка «Каталог»: `Hub.openLibraryTab(context, 'catalog')`); инструкция «Переводы и словари».
- Заголовок окна: **«Библиотека модулей»**; подзаголовка нет. Каталог загружается **сразу при открытии** (на любой вкладке), независимо от выбранной вкладки.

### 3.2. Шапка (закреплена, при прокрутке не уезжает)
1. **Вкладки**: «Установленные» · «Каталог» · «Импорт». Начальная — `installed` (кроме вызова из окна перевода — `catalog`).
2. (кроме «Импорта») **Поиск** — поле с подсказкой **«Поиск: Лопухин, Стронг, KJV…»**. Ищет подстроку (нижний регистр, `ё=е`) по склейке: `name`, `title`, `description`, `author`, название языка (на языке интерфейса). Строка склейки кэшируется на модуль и язык интерфейса (каталог ~1500 модулей).
3. Ряд чипов **вида**: «Все» и по одному на каждый из 7 видов (подписи — множественное число из §1.2); чип показывает число модулей (`count`, скрыт при 0); **виды отсортированы по убыванию числа модулей** (равные — в порядке `moduleSections`). Число считается с учётом **выбранного языка и поиска**, но не вида. Одна строка, прокручивается вбок.
4. Ряд чипов **языка** — только если языков ≥ 2 (после фильтра по виду и поиску; языки без модулей не показываются): «**Все языки**», первые **10** по числу модулей (убывание; равные — по `langRank`, затем по коду), выбранный язык (если не попал в десятку), и чип **«Ещё языки»** (с числом оставшихся и стрелкой) → диалог со списком остальных языков **по алфавиту** (название языка, справа число модулей); выбор закрывает диалог.
   Если выбранный язык после смены вида/поиска пропал из списка — выбор сбрасывается на «Все языки».
Фильтры (вид, язык, поиск) действуют на обе вкладки, но **запоминаются только пока окно открыто** (в prefs не пишутся).

### 3.3. Содержимое вкладок «Установленные» и «Каталог»
- **«Установленные»**: все установленные (`allInstalled`, включая выключенные); описание строки = `{...запись каталога (если есть), ...meta установленного}` (поверх каталога лежит то, что записано в базе модуля).
- **«Каталог»**: все записи каталога (в том числе уже установленные — у них вместо «Скачать» подпись «Установлен», либо «Обновить»).
- Строки **группируются по видам** в порядке `moduleSections`; сразу после «Переводы» идёт отдельная группа **«Переводы по сети»** (записи `online`; в группе «Переводы» их нет). Чип «Переводы» включает обе группы. Пустые группы не показываются.
- Заголовок группы: название + число модулей в ней (мелко, `  N`).
- Внутри всей выборки строки **отсортированы по `langRank`** (русские первыми, затем английские…; порядок внутри языка не гарантирован — это неустойчивая сортировка; **[уточнить]** разумно задать по алфавиту).
- В группе сначала **первые 60** строк; если больше — кнопка **«Показать ещё {n}»** (n = `min(200, осталось)`), добавляет по 200.
- Пустые состояния (значок книги + заголовок + пояснение):
  - выборка (вид/язык/поиск) пуста, а модули есть → **«Ничего не найдено.»** (без пояснения);
  - модулей нет совсем: заголовок **«Модулей нет»** и пояснение — «Установленные»: **«Скачайте из каталога или импортируйте JSON-файл.»**; «Каталог»: **«В каталоге пока нет модулей.»**
- Каталог ещё грузится (вкладка «Каталог»): **«Загружаю каталог…»** со спиннером; список пуст.
- Ошибка загрузки (вкладка «Каталог»): красный текст — для встроенного каталога **«Не удалось подключиться к серверу. Проверьте интернет.»** + перенос строки + текст ошибки (`aobible.app: …; github.io: …` или иная причина), для своего — только текст ошибки (§2.1); под ним кнопка **«Повторить»** (значок обновления) — повторная загрузка.

### 3.4. Строка модуля (всё нажатие по строке раскрывает подробности)
Слева: **имя** (жирно) + значок **«Новый»** (если `added` < 7 суток), под ним **полное название** (`title`, до 2 строк; если пустое или равно `name` — нет), под ним мелко **«{язык} · {по сети | размер}»** (размер — только у не установленных; у API.Bible вместо размера — **«по сети»**).
Строка бледнеет (непрозрачность 0,72) у **выключенного** модуля («Установленные», не перевод) и (0,6 для текста) у модуля с `unavailable`.
Справа, слева направо:
- кнопка **«Перейти»** (контурная капсула; подсказка «Перейти к {name}») — для **установленных** переводов (не `helper`), комментариев и карт, пока не идёт загрузка (§3.11);
- **главное действие** — выбирается по порядку (первое подходящее):

| № | Условие | Что показано |
|---|---|---|
| 1 | идёт загрузка этого модуля | кольцо прогресса и проценты акцентом (`Загрузка {pct}%` для чтения вслух) |
| 2 | вкладка «Каталог» и `unavailable` | значок «запрещено» (подсказка «Нет свободной электронной версии»), нажатий нет |
| 3 | есть обновление (§3.8) | контурная капсула **«Обновить»** (подсказка «Есть новая версия») |
| 4 | вкладка «Установленные», это перевод (не `helper`) | **звезда**: закрашенная акцентом — основной (подсказка «Основной перевод», нажатие ничего не делает); контурная — нажатие «Сделать основным» (§3.9) |
| 5 | вкладка «Установленные», установленный **не перевод** | **переключатель** вкл/выкл (подсказка «Включён»/«Отключён»; §3.10) |
| 6 | установлен | тихая подпись с галочкой: **«Установлен»** (для API.Bible — **«Добавлен»**) |
| 7 | не установлен, `online` | заливная капсула **«Добавить»** (подсказка «Добавить {name}») |
| 8 | не установлен | заливная капсула **«Скачать»** (подсказка «Скачать · {размер}», если размер известен) |

  Так, в «Каталоге» установленный перевод показывает «Установлен» (звезды там нет), а установленный `helper`-перевод — всегда «Установлен».
- шеврон (стрелка вниз; при раскрытии переворачивается).

### 3.5. Подробности (раскрываются плавно; одновременно открыта одна строка)
Сверху `description` (если есть). Таблица «подпись — значение» (значение можно выделять и копировать), строки, у которых есть данные:
- **«Вид»**: название вида (§1.2) + для словарей « · по номерам Стронга» либо « · по словам»;
- **«Объём»**: статистика + размер, через « · ». Статистика (`stats` из описания; у модулей каталога **обычно нет** — тогда только размер): перевод — «{books} кн., {verses} стихов»; словарь/комментарий — «{n} статей»; карты — «{n} мест» (если `places` > 0) иначе «{n} карт»; аудио — «{n} глав»; прочее — «ссылки для {n} стихов». Числа с разделителем тысяч (`fmtNum`: пробел в русском, запятая в остальных). Размер: ≥ 1 МиБ — «{x.y} МБ» (одна цифра после запятой, при ≥ 10 МиБ — целое), иначе «{n} КБ» (минимум 1);
- **«Язык»**: название языка (§2.2);
- **«Чтение»** (только API.Bible): **«по сети (API.Bible): главы приходят, когда вы их открываете»**;
- **«Версия»**, **«Лицензия»**, **«Автор»**, **«Источник»** — из записи.
Если идёт загрузка: под таблицей подпись этапа (например «Загрузка») и линейный индикатор.
Кнопки (малые, в ряд с переносом; показаны только применимые):
- **«Сделать основным»** (звезда) — установленный перевод (не `helper`), если он ещё не основной;
- **«Добавить»** (заливная, значок «+») — не установлен, не `unavailable`, `online`; **«Скачать · {размер}»** (заливная, значок загрузки) — не установлен, не `unavailable`, не `online`; обе заблокированы, пока идёт загрузка;
- **«Обновить»** (если есть обновление) либо **«Переустановить»** — установлен, есть запись каталога, она не `unavailable`, модуль не `online`; заблокирована, пока идёт загрузка;
- **«Удалить»** (значок корзины) — установленный любой вид: нажатие требует подтверждения. На iPhone — системный лист действий (`CNActionSheet`): кнопка-действие **«Удалить»** (красная) и **«Отменить»**; вне iPhone — на месте кнопки «Удалить» (красная) + «Отмена».

### 3.6. Установка (кнопки «Скачать» / «Добавить» / «Обновить» / «Переустановить»)
`_install(entry)`: пока идёт — `busy[id] = (прогресс, подпись)`, начальная подпись **«Подготовка…»**. Сам конвейер — §4. Параллельно можно качать несколько модулей (у каждого своё кольцо).
Итог:
- успех → сообщение **«{name} установлен»** (для API.Bible — **«{name} добавлен»**);
- ошибка → сообщение **«{name}: {текст ошибки}»** (например «Сервер ответил ошибкой 404», «aobible.app: …; github.io: …»);
- в обоих случаях индикатор снимается; если окно закрыто — загрузка продолжается, сообщение не показывается.

### 3.7. Удаление
`ModuleStore.remove(id)`: закрывает базу, удаляет `<id>.db`, убирает `id` из `disabled.json`, увеличивает счётчик. Сообщение **«{name} удалён»**. Переводы тоже удаляются без ограничений (кроме подтверждения); панели, читавшие удалённый перевод, переходят на основной (§1.3). Модуль, удалённый вручную, **стартовая доустановка заново не ставит** (§8.3).

### 3.8. Когда есть обновление (`_updatable`)
`true`, если одновременно: есть запись каталога и установленный модуль; запись не `unavailable`; `version` записи не пуста; у установленного есть `catalogVersion` **и** `version` записи ≠ `catalogVersion` (сравнение строк). Модули без `catalogVersion` (из файла) не обновляются.
Нажатие «Обновить» — обычная установка поверх (тот же `id`, новый файл подменяет старый). Решение о включении/выключении сохраняется.

### 3.9. Основной перевод
Звезда в строке «Установленные» (и кнопка «Сделать основным» в подробностях) пишет `settings.primaryModule = id` и показывает **«{name} — основной перевод»**. Основной используется: как перевод первой панели при самом первом открытии и в `repairModules`, при выборе перевода для «Стиха дня», в окне выбора перевода (★ первым). Звезда есть только у установленных, не `helper`, и только на вкладке «Установленные».

### 3.10. Включение и выключение (не переводы)
Переключатель в строке (системный `AobSwitch`, подсказка «Включён»/«Отключён»): `ModuleStore.setEnabled(id, on)` → запись в `disabled.json`, увеличение счётчика. Выключенный: строка бледнеет, модуль пропадает из словарей, комментариев, карт, параллельных мест и т. д.; остаётся в «Установленные», его можно удалить или снова включить.

### 3.11. «Перейти» у установленного модуля
Закрывает библиотеку (`Navigator.pop`), затем:
- **перевод**: если панелей меньше двух — открывается вторая панель с этим переводом (`toggleSplit(moduleId: id)`); если уже две — **вторая** панель переключается на него (`setModule(1, id)`);
- **комментарий**: открывается окно комментариев к стиху первой панели (`Hub.openCommentary`);
- **карты**: открывается окно карт (`openMapsSheet`).
Словари, аудио, параллельные места, иллюстрации — кнопки «Перейти» нет.

### 3.12. «Источник каталога» (вкладка «Каталог», внизу списка)
Раскрывающийся блок «**Источник каталога**» (строка со стрелкой, линия сверху). Внутри:
- текст: **«Сейчас — встроенный каталог.»** либо **«Сейчас — {url}.»**, затем **«Можно подключить свой каталог aob-catalog: https://…/catalog.json (нужен CORS).»**;
- поле (подсказка `https://…/catalog.json`) и кнопка **«Подключить»** (то же — клавиша «Готово» на клавиатуре): `source = текст.trim()`, перезагрузка каталога (пустая строка = встроенный);
- малые кнопки: **«Встроенный каталог»** (только при своём адресе: очищает поле и возвращает встроенный) и **«Обновить список»** (значок обновления; повторная загрузка того же источника, в том числе после ошибки).
Источник **не сохраняется** между открытиями окна.
Установка из своего каталога: записи с `_abs` качаются напрямую (без зеркала); `online`/`helloao` в нём тоже работают.

### 3.13. Прочее
- Пока каталог перезагружается, `byCat` пуст: в «Установленные» обновления не предлагаются, пока каталог не пришёл.
- Выключенные модули не показываются в других местах, но в библиотеке видны.

## 4. Установка: конвейер (`ModuleStore.install`)

Входные данные — запись каталога. Прогресс (число 0…1 и подпись) сообщается обработчику окна:
1. Выбирается файл: `urlGz` (приоритетнее) либо `url`; если запись `_abs` или адрес начинается с `https://` — качается **по полному адресу** (`downloadUrl`, один раз, без зеркала), иначе — `modules/<файл>` сайта (`download`: основной адрес → зеркало). Заголовок `Cache-Control: no-cache`; подпись запроса — «мобильный браузер… AOBible/2». Прогресс 0…0,6 × доля байт, подпись **«Загрузка»**. Если размер ответа неизвестен — прогресс стоит на 0 до конца.
2. Прогресс **0,65**, подпись **«Подготовка»**.
3. Один из трёх путей (в **отдельном потоке**; интерфейс не замирает):
   - `online` (API.Bible): скачанный файл — `{books: {OSIS: число глав}}`; строится модуль **без текста** (`onlineModule`): книги по порядку Библии (порядок — по списку USFM→OSIS, неизвестные в конец), названия и сокращения из справочника на языке интерфейса, `chapters` — пустые массивы нужной длины; `online`, `license`, `source`, `versification: "synodal"`;
   - `helloao`: `complete.json` → `fromHelloao` (§6.5) → формат модуля;
   - обычный: JSON модуля (при `urlGz` — распакованный gzip) → SQLite.
4. Запись во временный `<id>.db.part`: таблица `meta`; для перевода — `verses(id, book, chapter, verse, text)`, `headings`, `xrefs`, виртуальная `verses_fts` (FTS5, `unicode61 remove_diacritics 2`), индексы; для словарей/комментариев/параллельных мест/иллюстраций — таблицы по `study_tables.dart`; для карт с `places` — таблицы мест; прочее (аудио и т. д.) — одна таблица `payload(json)`.
   Пустые стихи (`""`) не пишутся. К описанию добавляется `catalogVersion` (версия записи каталога).
5. Старая база закрывается, `.part` переименовывается в `<id>.db`, список модулей пересканируется, счётчик `changes` растёт. Прогресс **1**, подпись **«Готово»**.
Подписи этапов проходят через `t(...)`, окно показывает `t(l)`.
Из-за атомарной замены обновление безопасно: если установка оборвалась, прежний модуль остаётся; `.part` остаётся мусором до следующей установки.
Размер: перевод Синодальный `rst-plus` — ~2,4 МБ gzip (~10 МБ JSON); весь каталог — 0,9 МБ.

## 5. Вкладка «Импорт» (из файла)

### 5.1. Что видно
Столбец блоков (зазор 12):
1. Рамка («.dropzone»): значок загрузки, текст **«Перетащите JSON-файлы сюда или»** (на телефоне перетаскивать нечего — только кнопка), кнопка **«Выбрать файлы»**, пояснение **«Переводы, словари, параллельные места · .json или .json.gz»**.
2. Карточки выбранных файлов (§5.3), по одной на файл, новая — внизу.
3. Раскрывающийся блок **«Формат модуля»**: текст «Родной формат — `aob-module` (описание: docs/MODULE_SCHEMA.md в проекте). Также принимаются массив книг с полем `chapters`, список стихов `{book, chapter, verse, text}`, словарь `{"H1": {...}}` и список статей `[{word, definition}]`.» (моноширинные вставки), образец JSON (ниже), кнопка **«Скопировать пример»** → сообщение **«Пример скопирован»**.
Образец (`moduleSample`) — точный текст:
```json
{
  "format": "aob-module",
  "formatVersion": 1,
  "type": "dictionary",
  "dictionaryKind": "words",
  "id": "my-dictionary",
  "name": "Мой словарь",
  "language": "ru",
  "license": "CC BY 4.0",
  "entries": {
    "агнец": {
      "word": "Агнец",
      "text": "Ягнёнок; жертвенное животное…",
      "refs": ["John.1.29", "Rev.5.6"]
    }
  }
}
```

### 5.2. Выбор файла
«Выбрать файлы» → системный выбор файлов (любые файлы, один за раз; выбранные имя и байты читаются в память). Сбой выбора → сообщение **«Не удалось прочитать файл: {ошибка}»**. Для каждого файла сразу добавляется карточка в состоянии «Чтение…» (подпись **«Чтение…»**), идёт проверка (`previewImport`, в отдельном потоке).

### 5.3. Карточка файла (`.mod-card`)
Заголовок: значок файла + **название модуля** (после проверки; до — имя файла). Под ним мелко **«{имя файла} · {размер}»**.
Состояния (`state`): `reading` · `ready` · `error` · `installing` · `done`.
- `reading` / `installing`: индикатор с подписью («Чтение…» / «Установка…», затем «Сохранение…», «Готово»); прогресс проверки 0…0,5, установки 0,5…1.
- `error`: красный значок предупреждения и **сообщение об ошибке** (§5.6); кнопка **«Убрать»**.
- `ready`: сведения (мелко): **«Тип: {вид}[ (по номерам Стронга|по словам)] · id: {id}{статистика}»** и с новой строки **«Лицензия: {license}»**; статистика: перевод « · {books} кн., {verses} стихов[, есть номера Стронга]», словарь « · {n} статей», параллельные места « · ссылки для {n} стихов», остальные виды — пусто; затем список **предупреждений** (значок «!» и текст каждого; §5.6). Кнопки: **«Установить»** (заливная) — или **«Заменить установленный»**, если модуль с таким `id` уже стоит; **«Убрать»**.
- `done`: плашка **«Установлен»** (зелёная, с галочкой), кнопка **«К установленным»** (переключает окно на вкладку «Установленные»). «Убрать» нет.
Установка: `installPreview(p)` — `_convertJson(p.json, …)` без номера версии каталога; затем сообщение **«{name} установлен»**; ошибка → в карточке красным **«Не удалось сохранить: {ошибка}»** (состояние `error`; кнопки «Убрать»).

### 5.4. Определение формата (`detectFormat`) — проверки по порядку
Файл: gzip по сигнатуре (`1f 8b`) распаковывается; текст UTF-8 (повреждённые байты допускаются), BOM (`U+FEFF`) снимается; затем JSON. Ошибки: **«Файл не является корректным JSON: {ошибка}»** (для неудачной распаковки — `{ошибка}` = `gzip`).

| № | Условие | Формат / тип |
|---|---|---|
| 1 | объект с `format == "aob-module"` | `aob`, тип — из `type` (если `type` отсутствует — общая ошибка «Не удалось определить тип модуля…» ниже) |
| 2 | объект с `format == "aob-catalog"` | каталог → ошибка: **«Это файл каталога, а не модуль. Откройте его во вкладке «Онлайн-каталог».»** (вкладка на самом деле называется «Каталог» — несоответствие текста во Flutter) |
| 3 | массив, первый элемент — объект с массивом `chapters` | `books-array`, `bible` |
| 4 | массив (или `verses`-массив объекта), первый элемент — объект с ключами `chapter`, `verse`, `text` | `flat-verses`, `bible` |
| 5 | объект с массивом `books` | `aob`, `bible` |
| 6 | объект с объектом `entries`: ключи (первые 20) **все** вида OSIS-стих `^[1-4]?[A-Za-z]+\.\d+\.\d+(-(\d+\.)?\d+)?$` | `aob`, `commentary`; иначе `aob`, `dictionary` |
| 7 | объект с объектом `refs` | `aob`, `crossrefs` |
| 8 | объект с массивом `maps` или `places` | `aob`, `maps` |
| 9 | объект, первые 50 ключей все вида `^[HG]\d+[a-z]?$` (без учёта регистра) | `strongs-map`, `dictionary` (`dictionaryKind = strongs`) |
| 10 | массив объектов; у первого есть (`word`/`term`/`topic`) и (`definition`/`text`/`description`) | `word-list`, `dictionary` (`words`) |
| — | иначе | ошибка: **«Не удалось определить тип модуля. Нужен JSON в формате aob-module (поле "format": "aob-module") или один из поддерживаемых форматов: массив книг с "chapters", список стихов {book, chapter, verse, text}, словарь {"H1": {...}} или список статей [{word, definition}].»** |
Неизвестный `type` в `aob-module` → **«Неизвестный тип модуля «{type}». Допустимы: bible, commentary, dictionary, maps, crossrefs.»** (audio и illustrations разбираются, хотя в тексте не названы).

### 5.5. Описание модуля после проверки (`normalizeModule`)
`baseName` = имя файла без последних `.json`/`.gz` (любое число). `pick(a, b, …)` — первое непустое.
- `id` = `slug(pick(src.id, baseName, src.name))`: нижний регистр, всё кроме `a-z 0-9 а-я ё` → `-`, без `-` по краям, не длиннее 48, пусто → `module`.
- `name` = `pick(src.name, src.abbreviation, baseName, «Без названия»)`, не длиннее **40**.
- `title` = `pick(src.title, src.name, baseName)`; `description`; `language` = `pick(src.language, src.lang, "ru")`; `version`; `author`; `source` = `pick(src.source, «Файл {имя файла}»)`; `license` = `pick(src.license, «не указана»)`; `versification` = `pick(src.versification, "synodal")`; `features` = `src.features` (объект) или `{}`.
- `dictionaryKind` (словари) = `pick(src.dictionaryKind, strongs для strongs-map, иначе words)`.
- Перевод: если `features.strongs` не задано — `true`, когда хотя бы в одном стихе есть `{`.
- `stats`: перевод — `{books, verses}`; словарь/комментарий — `{entries}`; параллельные места — `{verses}`; карты — `{maps, places}`; иллюстрации — `{verses, images}`; аудио — `{chapters}` (+ `translation`, `chapterKeys` в описании).
- `origin = "file"`.
Итоговый JSON для установки: `{format: "aob-module", formatVersion: 1, …описание…, …данные…}`.

### 5.6. Проверки по видам и точные сообщения
**Ошибки** (карточка не готова к установке) и **предупреждения** (остаётся «Установить»):

*Перевод* (форматы `aob`, `books-array`, `flat-verses`):
- книги: массив пуст/не массив → ошибка **«В модуле нет книг (поле "books" пустое).»**; элементы-не-объекты пропускаются молча;
- код книги: `id`/`osis`, иначе `name`/`abbrev`; число (1…66) или строка из цифр → книга по номеру в **западном (протестантском) порядке** (Gen…Rev, 66 книг); известный OSIS-код — как есть; иначе `findBookId` (§2.4 из `06a`); книга без кода и названия — по порядку в массиве; неизвестный код (2–12 букв/цифр) с названием — **сохраняется как есть** (апокрифы); иначе предупреждение **«Книга №{n} («{name}») не распознана и пропущена.»**;
- у книги нет массива `chapters` → предупреждение **«У книги {id} нет массива "chapters" — пропущена.»**;
- элемент стиха: строка, либо объект (`text` или `t`), иначе пусто; пустая глава — `[]`;
- `name`/`short` книги — из файла, иначе из справочника (на языке интерфейса); `t` — из файла (`OT`/`NT`/`AP`), иначе по справочнику, неизвестная книга — `AP`;
- `flat-verses`: книга из `book`/`book_id`/`bookId`/`book_name`; глава и стих — числа > 0; иначе запись пропущена, итог **«Пропущено записей без распознанной книги/главы/стиха: {n}.»**; книги упорядочиваются по справочнику;
- после разбора: нет ни одной книги → ошибка **«Не найдено ни одной распознанной книги.»**; повтор книги → ошибка **«Книга {id} встречается в модуле дважды.»**; пустая книга → предупреждение **«В книге {name} нет глав.»**.

*Словарь*: нет статей (`entries` пуст / не объект) → ошибка **«В словаре нет статей (поле "entries" пустое).»**; `strongs`: ключи не вида `[HG]\d+[a-z]?` → предупреждение **«Ключи не похожи на номера Стронга и не будут найдены: {первые 5 через запятую[…]}»**; `words`: ключи приводятся к нижнему регистру и `ё→е`, значение-строка превращается в `{text}`, у записи `word` по умолчанию = ключу; `wordIndex` сохраняется. `word-list`: пустое слово пропускается; `refs` — список.

*Комментарий*: `entries` не объект → ошибка **«В комментарии нет поля "entries" вида {"Gen.1.1": "…"}.»**; ключи не по образцу OSIS → пропуск и предупреждение **«Пропущено статей с ключом не в формате "Книга.глава.стих": {n}.»**; пустые тексты отбрасываются; ничего не осталось → ошибка **«В комментарии нет ни одной статьи с ключом вида "Gen.1.1".»**.

*Параллельные места*: ключ `^[1-3]?[A-Za-z]+\.\d+\.\d+$`, значение — массив (элементы → строки); ничего не осталось → ошибка **«В модуле нет ссылок вида "Gen.1.1": ["John.1.1", …].»**.

*Карты*: у карты должен быть `image` — адрес `http(s):`, `data:image/…` или путь вида `^[\w./-]+\.(jpe?g|png|webp|gif|svg)$` без `..`; иначе предупреждение **«Карта №{n} пропущена: нет поля "image" (адрес, data:image или путь к картинке).»**; `id`/`title` («Карта {n}» по умолчанию)/`description`/`refs`. Места: нужны `name`, числовые `lat` (|lat| ≤ 90) и `lng`/`lon` (|lng| ≤ 180); иначе пропуск и предупреждение **«Пропущено мест без названия или координат: {n}.»**; `stems` (основы для поиска места в стихе) вычисляются, если не заданы (`placeStems`: слова от 3 букв без «гора, река, море, поток, долина, пустыня, земля, город, страна», основа = слово без последних 2 букв, длиной 3…5). Нет ни карт, ни мест → ошибка **«В модуле карт нет ни карт с изображением, ни мест с координатами.»**.

*Иллюстрации*: `entries` не объект → ошибка **«В модуле иллюстраций нет поля «entries» вида {"Gen.1.3": [{img, …}]}.»**; ключ `^[1-4]?[A-Za-z]+\.\d+\.\d+$`, значение — список; берутся записи с `img`, начинающимся с `https://`, **не более 2 на стих**; остальное → предупреждение **«Пропущено записей без адреса картинки или с неверным стихом: {n}.»**; ничего не осталось → ошибка **«В модуле иллюстраций нет ни одной картинки.»**.

*Аудио*: `chapters` не объект → ошибка **«В аудиомодуле нет поля "chapters" вида {"John.3": {url, verses}}.»**; глава: ключ `^[1-4]?[A-Za-z]+\.\d+$`, `url` (http(s) или имя файла `mp3/m4a/ogg/opus/aac/wav`), непустой `verses` (пары `[номер, секунда]`, сортируются по времени); пропущенные → **«Пропущено глав без адреса записи или разметки стихов: {n}.»**; ничего не осталось → ошибка **«В аудиомодуле нет ни одной главы с записью и разметкой стихов.»**; `files`+`segments` (сегменты по стихам) сохраняются, если корректны.

Все остальные ошибки чтения проходят как «{текст}» (или «Не удалось сохранить: …» при записи).

### 5.7. Что получает человек
После установки модуль виден в «Установленные» (там же его можно выключить/удалить), работает как модуль каталога, **но без обновлений** (нет `catalogVersion`). Совпавший `id` заменяет установленный модуль каталога (подтверждение — кнопка «Заменить установленный»).

## 6. Сетевые переводы и переводы helloao

### 6.1. Две разные вещи
- **API.Bible (`online`)** — перевод **читается по сети**. «Добавить» создаёт модуль **без текста** (только список книг и число глав); главы приходят, когда их открывают.
- **bible.helloao.org (`helloao`)** — перевод **скачивается целиком** одним файлом `complete.json` и превращается в обычный модуль (работает без сети).

### 6.2. Запрос главы API.Bible
Через посредника (ключ API.Bible — на сервере, в приложении ключа нет): основной `https://aobible.app/bapi`, запасной `https://aobible-apibible.apibible.workers.dev`.
`GET {base}/bibles/{api}/chapters/{USFM}.{номер главы KJV}?content-type=json&include-notes=false&include-titles=true&include-chapter-numbers=false&include-verse-numbers=true&include-verse-spans=false` (`api` из `online.api`; USFM-код книги — по таблице OSIS→USFM из `usfmToOsis`, обратной).
- HTTP 429 или 403 → `OnlineError('limit')` (исчерпан месячный лимит);
- любой другой не-200 → `OnlineError('net')`; сетевой сбой с первым адресом → пробуется второй; оба не ответили → `net`. Если сервер ответил — второй адрес не пробуется.
Учёт показов (FUMS) в приложении для телефона **не ведётся**.

### 6.3. Хранение глав
Пришедшая глава записывается в обычные таблицы базы перевода (`verses`, `headings`) и в служебную `online(book, chapter, at, n)`; `copyright` главы — в `meta('copyright')`. По условиям API.Bible **хранится не больше 480 стихов** и **не дольше 14 суток**: после каждой записи главы, идя от новых к старым, удаляются главы, у которых накопленная сумма стихов превысила 480 **или** возраст > 14 суток (только что записанная глава остаётся всегда). После удаления/записи кэш книги сбрасывается (`forgetBook`).

### 6.4. Разбор главы API.Bible (`parseChapter`)
Из JSON-содержимого главы: стихи по `verseId` в `attrs` (номер — последняя часть после точки); текст склеивается; пробелы нормализуются; сноски (`note`) и заголовки пропускаются; абзацы стилей `s, s1…, ms, mr, sr, d, sp, qa, r` — **заголовки разделов** (накапливаются и привязываются к следующему стиху); `d` до первого стиха — **надписание псалма**; слова, добавленные переводчиками (стили `add`, `it`), оборачиваются `‹…›` (курсив в приложении); символы `{}` из текста убираются; соседние `›‹` склеиваются.
Нумерация приводится к синодальной (§7): глава собирается из одной или двух глав API.

### 6.5. Переводы helloao
`fromHelloao(complete.json, запись, названия книг)`: для каждой книги (USFM→OSIS по `usfmToOsis`; неизвестные коды пропускаются) собираются главы KJV: стихи (`verse` с `number`), заголовки (`heading`, `hebrew_subtitle` до первого стиха — надписание псалма), содержимое — строки и `{text}` (сноски и разрывы пропускаются). Затем **каждая синодальная глава собирается из своих глав KJV** (§7); пустые главы в конце отбрасываются; книга без стихов пропускается. Итог — обычный `aob-module` (`versification: "synodal"`, без `features`), дальше — обычная установка в SQLite.

### 6.6. Что видит человек при чтении (напоминание, подробно — `01-reader-settings.md` §4.7)
Пока главы нет: «**Загрузка…**» (грузятся эта и следующая); ошибка — «Нет связи: этот перевод читается по сети. Подключитесь к интернету или выберите скачанный перевод.» либо (лимит) «Переводы по сети сейчас недоступны: исчерпан месячный лимит запросов. Выберите скачанный перевод или загляните позже.» и кнопка «Повторить». Права перевода (`copyright`) — мелким текстом под концом книги. Переводы по сети в **поиске** найдут только уже скачанные главы; в «Перейти» у нескачанной главы нет числа стихов.

## 7. Версификация (`core/versification.dart`)

Все модули каталога и конвертированные переводы helloao приведены к **синодальной** нумерации (Псалтирь на 1 меньше, чем в KJV, и т. д.). API.Bible и helloao отдают **западную (KJV)** нумерацию — модуль `versification.dart` переводит одну в другую (данные из `scripts/extra_lib.kjv2syn`, SWORD; файл создан скриптом, руками не править; то же — `src/core/versification.js` веба).

### 7.1. Данные
- `_k2s`: `{книга: {глава KJV: [[с, по, сдвиг_главы, сдвиг_стиха], …]}}` — только участки, где номера расходятся. Остальное совпадает. Книги: `Lev` (14:56), `Num` (13, 30), `Josh` (6), `1Sam` (24), `Job` (40, 41), `Ps` (почти все: 3–147), `Eccl` (5), `Song` (1, 7), `Isa` (3), `Dan` (3, 4), `Hos` (14), `Jonah` (2), `2Cor` (13).
- `_syn`, `_western`: число стихов в каждой главе каждой книги — синодальный счёт (по RST+) и западный (KJV). В `_western` нет `2Esd`. В приложении `synodalVerses(book)` отдаёт `_syn[book]`, иначе `_western[book]`, иначе `[]` — **вне самого файла сейчас не вызывается** (проверено поиском).

### 7.2. Функции
- `toSynodal(book, c, v)` → `(глава, стих)`: ищет участок `[с, по]`, куда попал `v`, и возвращает `(c + сдвиг_главы, v + сдвиг_стиха)`; нет участка — `(c, v)`.
  Примеры: `Ps 3:1` (KJV) → `3:2` (в синодальной 3:1 — надписание); `Ps 51:1` → `50:3`; `Ps 10:1` → `9:22`; `Dan 3:24` → `3:91`; `Dan 4:1` → `3:97`; `Josh 6:1` → `5:15`; `2Cor 13:13` → `13:12`.
- `westernChaptersFor(book, c)` → какие главы KJV нужны, чтобы собрать синодальную главу `c` (обычно одна; на стыках псалмов — две, например Пс 9 синодальный = Пс 9 + начало Пс 10 KJV). Сначала все главы KJV, чьи участки попадают в `c`; плюс сама глава `c`, если в ней остаётся хоть один стих, отображаемый в `c`. Результат отсортирован.
- `placeSynodal(book, kc, стихи, заголовки, целевая_глава, куда_стихи, куда_заголовки, [надписание])` — переносит стихи главы KJV `kc` в синодальную главу `целевая`: каждый стих проходит `toSynodal`; чужие главы пропускаются; стихи в одной ячейке склеиваются пробелом; заголовок раздела переносится к стиху (если ячейка без заголовка). **Надписание псалма** (заголовок над стихом 1 в западной нумерации) для `Ps` кладётся в **стих 1 синодальной главы** (если эта глава начинается с 2-го западного стиха и стих 1 ещё пуст).
Используется только при установке (`fromHelloao`) и при приёме главы API.Bible (`_load`). В читалке пересчёта нумерации **нет** — нумерация модулей уже синодальная.

## 8. Стартовые модули (`starter.dart`) и первая установка

### 8.1. Идея
На первом запуске нужен только один перевод — читать можно сразу. Остальное доустанавливается **в фоне**, по одному, без индикатора. Людям, пользовавшимся приложением раньше, один раз доставляются новые базовые модули.

### 8.2. Выбор основного перевода и словаря языка
- `homeBible()` по языку интерфейса: `cs → kralicka`, `de → luther1912`, `en → bsb`, `es → rv1909`, `fr → segond1910`, `hi → hin-irv`, `it → riveduta`, `ja → bungo`, `ko → korrv`, `pl → gdanska`, `pt → biblia-livre`, `sr → dk-cyr`, `sw → swh-ulb`, `zh → cuv-s`; иначе для кириллических `ru, uk, be, bg` — `rst-plus`, для остальных (`hy, id, ro` и любые другие) — `bsb`.
- Новый Завет на родном языке (если полной Библии нет): `hy → arm-nt1853`, `id → alkitab-gratis`, `ro → ronbl`, `uk → ukr-kulish`, `be → be-nt1931`.
- Словарь языка (`langDictionary()`): `ru, uk, be → nikifor`; все остальные → `easton`.
- Не кириллические языки получают ещё английские словари Стронга `strongs-hebrew`, `strongs-greek`.

### 8.3. Списки и правило доустановки
`starter()` (первый запуск) — множество с сохранением порядка:
`homeBible`, `rst-plus`, `xrefs-rst`, `rst-symphony`, `strongs-ru-hebrew`, `strongs-ru-greek`, `bible-places`, `bible-illustrations`, `oshb`, `byz-rp2018`, `langDictionary`, [`ntBible` языка], [для некириллических `strongs-hebrew`, `strongs-greek`], `study` = `bible-maps`, `lopukhin`, `vin-interlinear`, `rst-interlinear`, `lexicons` = `dvoretsky-gr`.
`lateStarter()` (для начавших раньше): `bible-places`, `bible-illustrations`, `strongs-ru-hebrew`, `strongs-ru-greek`, `oshb`, `byz-rp2018`, `langDictionary`, `study…`, `lexicons`.
`oshb` (иврит) и `byz-rp2018` (греческий) называются **оригиналами**.

**Самый первый запуск** (`prepareFirstRun`, до показа окна): если нет ни одного установленного перевода и `bootstrapped` не `true`: в настройках, если `primaryModule` не задан, пишется `primaryModule = homeBible()`; `welcomePending = true`; `newsSeen = id последней записи «Что нового»` (новому человеку «Что нового» не нужно).
Затем показывается экран первой установки (§8.4); после него — главный экран; после первого кадра выполняется `installStarterModules`:
1. ждёт, пока появится хотя бы один перевод (проверка раз в 0,5 с, до 1200 раз ≈ 10 минут — иначе выходит);
2. `first = bootstrapped != true`; `done = lateStarter` (список «уже пробовали»); `want = first ? starter() : lateStarter()`; `todo` = `want` без тех, что в `done` или уже установлены;
3. `todo` пуст → если `first`, `bootstrapped = true`; `lateStarter = done ∪ want`; конец;
4. иначе: каталог (`store.catalog()`); если `first` — `bootstrapped = true`; те из `todo`, которых **нет в каталоге**, не отмечаются как «пробовали» (повтор при следующем запуске); остальные **сразу записываются** в `lateStarter` («пробовали»);
5. по `todo` по одному: записи нет в каталоге или `unavailable` — пропуск; `install(e)`; **ошибка → id убирается из `lateStarter`** (при следующем запуске попробует снова), цикл продолжается;
6. нет сети/каталога (исключение при загрузке каталога) → `lateStarter` возвращается к прежнему `done` (повтор при следующем запуске).
Модуль, который человек **удалил**, попал в `lateStarter` («пробовали») и заново не ставится.

### 8.4. Экран первой установки (`BootstrapScreen`)
Показывается вместо главного экрана, пока нет **ни одного перевода** (при запуске `ModuleStore.bibles.isEmpty`).
Что видно (по центру, максимальная ширина 400): логотип приложения (чуть «дышит» вверх-вниз), текст **«Готовлю Синодальный перевод, словари и параллельные места…»** (одинаков для всех языков), карточка с тремя этапами и общим прогрессом, подпись **«Это нужно только один раз — дальше Библия работает без интернета.»**.
Этапы (`_Steps`): **«Каталог модулей»**, **«Загрузка перевода»**, **«Установка»** — у каждого отметка: ожидает (пустой круг), идёт (крутящийся), готово (галочка в круге). Этап вычисляется по прогрессу `p`: не начато (каталог ещё грузится) → 0; `p < 0,6` → 1; `p < 1` → 2; `p = 1` → все готовы. Внизу линейная полоса (минимум 2 %) и «{pct}%».
Что делает: каталог → запись с `id == primaryModule` (в настройках), иначе `rst-plus` → `install(e)` с прогрессом. **Один автоматический повтор** через 1,5 с при ошибке (если за это время перевод не появился); если после ошибки перевод всё же есть (поставил параллельный запуск) — это не ошибка, открывается Библия. Успех → `onReady` → `HomeScreen`.
Ошибка: красная плашка со значком «нет сети» и текстом **«Не удалось подключиться к серверу. Проверьте интернет.»**, под ней мелко (можно выделять) техническая причина (`aobible.app: …; github.io: …`), кнопки **«Повторить»** (значок) и **«Библиотека модулей»** (открывает библиотеку).

### 8.5. Уведомления о доустановленном
Все — всплывающие сообщения (`Hub.toast`):
- в конце доустановки, если были «учебные» модули — **«Добавлено для изучения: {имена через запятую}»** (имена — `name` записей). Первый запуск: перечисляются только `study` (`bible-maps`, `lopukhin`, `vin-interlinear`, `rst-interlinear`); не первый: `study` и словарь языка;
- не первый запуск, отдельные: `bible-illustrations` → **«Добавлены иллюстрации к стихам: нажмите на значок картинки в конце стиха»**; `strongs-ru-hebrew` → **«Добавлен словарь Стронга на русском: нажмите на слово или номер Стронга»**; `bible-places` (прочие модули карт) → **«Установлен «{name}»: нажмите на город в стихе — он покажется на карте»**;
- молча: `strongs-ru-greek`, оригиналы, `dvoretsky-gr`, и всё в первый запуск, кроме учебных.
Android-только: уведомление **«Вышла новая версия приложения»** с кнопкой «Обновить» (Google Play) — на iPhone **не нужно**.

## Расхождения со Swift

Проверено по: `Views/ModulesList.swift`, `Views/MoreView.swift`, `Views/ReaderView.swift` (окно «Переводы»), `Core/ModuleStore.swift`, `Core/Starter.swift`, `Views/InfoViews.swift` (импорт в `ModulesList`), `RootView.swift` (запуск), `Core/PanesStore.swift`.

### А. Библиотека (окно)
1. **Нет вкладок «Установленные / Каталог / Импорт».** Swift — один список: раздел «Установленные» (по выбранному виду и языку) + разделы каталога «по языкам» ниже; импорт — кнопка в панели («Установить из файла», `fileImporter`).
2. **Фильтры**: вместо поиска и рядов чипов — два меню-пикера «Тип модуля» и «Язык модуля»; видов 5 вместо 7 («Переводы, Словари, Толкования, Параллельные места, Аудио» — нет «Карты» и «Иллюстрации»; «Толкования» вместо «Комментарии»); нет поиска «Поиск: Лопухин, Стронг, KJV…»; нет счётчиков, нет чипа «Ещё языки» (меню со всем списком), нет сортировки видов по числу; язык-«Все языки» есть.
3. **Группировка**: Swift группирует каталог по **языкам** (русский первым, остальные по коду), Flutter — по **видам**, а внутри сортирует по `langRank` (порядок языков §2.2). Установленные из каталога скрыты (Flutter показывает их в «Каталоге» с подписью «Установлен»). Нет группы «Переводы по сети». Нет порционного показа (60 строк + «Показать ещё {n}»).
4. **Строка**: нет «Новый», нет сообщения «по сети», нет шеврона и **раскрытия подробностей** (вид, объём, язык, версия, лицензия, автор, источник, описание); лицензии и авторы Swift показывает только на экране «О приложении».
5. **Нет «Основного перевода»** (звезды, `primaryModule`, подсказок, сообщения «{name} — основной перевод»): в Swift «основной» = перевод первой панели (`PanesStore.primaryModule`), по нажатию на установленную строку (в режиме `bible`) `selected` меняется, рядом ставится галочка. Из-за этого нет и сохранения выбора независимо от панелей.
6. **Нет включения/выключения** небиблейских модулей (`disabled.json`, переключатель, бледная строка).
7. **Нет обновлений**: `catalogVersion` пишется при установке, но не сравнивается; нет кнопок «Обновить»/«Переустановить».
8. **Удаление** — свайп без подтверждения и без сообщения «{name} удалён»; во Flutter — кнопка «Удалить» в подробностях с подтверждением (системный лист действий) и сообщением.
9. **Нет кнопки «Перейти»** у установленных модулей (вторая панель / комментарии / карты).
10. **Прогресс установки**: Swift показывает спиннер и подпись («Загрузка…» / «Подготовка…»); нет кольца с процентами (`ModuleStore.install` не получает `onProgress`; `fetch` не считает байты). Нет этапа «Готово».
11. **Сообщения**: нет «{name} установлен / добавлен / удалён»; ошибка установки Swift кладёт в `catalogError` («Не удалось установить «{name}».») — текст виден в красной секции списка (во Flutter — «{name}: {причина}» в сообщении); нет причины (`aobible.app: …; github.io: …`).
12. **Каталог**: Swift читает только `modules/catalog.json` — **нет `catalog-more.json` (API.Bible, helloao) и `lang-names.json`**; записи `online`/`helloao`/`unavailable` просто скрываются (`downloadable`), поэтому нет значка «Нет свободной электронной версии»; ошибка загрузки — «Не удалось загрузить каталог. Проверьте интернет.» (Flutter: «Не удалось подключиться к серверу. Проверьте интернет.» + причина); нет кэша на 2 минуты; повтор кнопкой «Повторить» есть.
13. **Нет «Источника каталога»** (свой адрес aob-catalog, «Встроенный каталог», «Обновить список») и скачивания по `_abs`-адресу.
14. **Названия языков**: Swift — всегда русские `Locale("ru")` (`localizedString(forLanguageCode:)`), Flutter — на языке интерфейса (`langDisplayNames`, `lang-names.json`), в русском — собственная таблица `_langNames`, заглавными код как запасной вариант.
15. **Пустые состояния** («Ничего не найдено.», «Модулей нет» с пояснениями, «Загружаю каталог…» вместо «Загрузка каталога…») — формулировки и условия другие; в Swift «Загрузка каталога…» — со спиннером.
16. **Установленные**: сортировка Swift — русские, затем по имени (`scan`); Flutter — без сортировки по имени (по `langRank`, внутри языка порядок файловой системы).
17. **Сеть**: таймаут запроса Swift 60 с (Flutter: соединение 20 с, «встала» загрузка на 30 с → ошибка); зеркало GitHub Pages как запас есть, но переключение «до перезапуска» после первого успеха с зеркала (`_useMirror`) не запоминается. Запись во временный `.part` и атомарная замена — как во Flutter.

### Б. Импорт из файла
18. Swift принимает **только `aob-module`** (JSON или gzip) с `id` вида `^[A-Za-z0-9-]+$`; **нет определения других форматов** (массив книг с `chapters`, плоский список стихов, словарь Стронга `{"H1":…}`, список статей `[{word, definition}]`), нет нормализации метаданных (`slug`, `name ≤ 40`, `license «не указана»`…), нет проверки по видам и предупреждений (§5.6).
19. **Нет карточки предпросмотра**: Swift сразу устанавливает и показывает `alert` «Установка из файла» только при ошибке (двух текстов: «Это не модуль AO Bible (нужен файл формата aob-module).» / «Не удалось установить модуль из файла.» / «Не удалось прочитать файл.»); нет «Заменить установленный», «К установленным», «Убрать», статистики и лицензии до установки, сообщения «{name} установлен», образца формата и «Скопировать пример».
20. Типы: Swift-конвертер умеет `bible`, `dictionary/commentary/crossrefs/illustrations`, `maps` с `places`; остальное — `payload` (то же, что Flutter). Аудио-модуль из файла Swift не проверяет.

### В. Сетевые переводы и версификация
21. **Нет**: `Core/Versification`, `Core/ApiBible`, `Core/Helloao`, посредника `aobible.app/bapi`, таблицы `online`, лимитов (480 стихов / 14 дней), состояний «Загрузка…» / «Нет связи…» / «исчерпан месячный лимит» в читалке, авторских прав под концом книги. `ModuleStore.bibles` исключает `online` — такие модули (если случайно попадут) не читаются.
22. Следствие: переводы helloao (1423) и API.Bible (164) недоступны; нужно добавить `catalog-more.json`, установку из `complete.json` (§6.5) и перевод KJV→синодальная (§7) — данные для таблиц взять из `lib/core/versification.dart` (или сгенерировать из `scripts/extra_lib.kjv2syn`).

### Г. Стартовые модули и первая установка
23. Список `Starter.list` **совпадает** со `starter()` (порядок и условия: `homeBible`, `ntBible`, словарь языка, английские Стронги для некириллических), таблицы `fullBible` / `ntBible` / `dictionary` — те же.
24. **Нет различия «первый запуск / начавшие раньше»**: Swift всегда использует полный список (для старых пользователей Flutter ставит узкий `lateStarter`), хранит «уже ставили» в `starterDone` (и ставит id в список **только если модуль действительно появился**, Flutter помечает «пробовали» до установки и снимает при ошибке), нет `bootstrapped`, `lateStarter`, `prepareFirstRun` (запись `primaryModule`, `welcomePending`, `newsSeen`).
25. **Нет экрана первой установки** (`BootstrapScreen`: логотип, три этапа, процент, ошибка с «Повторить» и «Библиотека модулей»): Swift показывает над читалкой плашку «Устанавливаю модули: i из N» (в Flutter фоновая доустановка идёт молча); как себя ведёт Swift совсем без сети и без перевода **[проверить на устройстве]**. Нет автоповтора через 1,5 с.
26. Нет уведомлений «Добавлено для изучения: …», «Добавлены иллюстрации…», «Добавлен словарь Стронга на русском…», «Установлен «…»: нажмите на город…» (в Swift — только плашка). Нет ожидания «хотя бы один перевод» и проверки, что нет открытых окон (это для приветствия, `06c`).
27. Swift ещё ставит **аудиозаписи** к установленным переводам (`autoAudioList`) — во Flutter это делает функция аудио отдельно (`autoAudio`, в область `05a` не входит).
28. Языки интерфейса при первом запуске: Swift берёт `interfaceLanguage` (по умолчанию `ru`; перенос из `flutter.lang` один раз), **не** язык телефона (подробнее — `06c-shell.md`).

### Д. Что совпадает
Файлы модулей — те же `.db` (SQLite, `meta.json`, `bookList`, `catalogVersion`) в `Application Support/modules`, конвертер JSON→SQLite (таблицы перевода/словаря/комментария/иллюстраций/параллельных мест/мест), зеркало GitHub Pages как запас, gzip-распаковка, `CatalogEntry` с `url/urlGz/size`, отбор «скачать можно» (без `online`/`helloao`/`unavailable`).

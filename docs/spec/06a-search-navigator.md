# 06a. Поиск, «Перейти» (навигатор книг), разбор названий книг и ссылок — как работает Flutter-версия

Составлено по полному чтению: `lib/ui/search_screen.dart`, `lib/ui/navigator_sheet.dart`, `lib/core/books.dart`, `lib/core/bible.dart` (`queryRegex`, `searchText`, `warmSearch`, `verseAt`, `highlightWords`),
`lib/core/i18n.dart` (язык → названия книг), `lib/features/study/concordance_sheet.dart` (`StrongSearchCard`, `StrongPlaces`) и `lib/features/study/study.dart` (как карточка Стронга подключается к поиску),
`lib/core/panes.dart` (`navigate`, `setModule`). Для связей читались места вызова: `lib/ui/home_screen.dart` (кнопки шапки, вкладка «Поиск»), `lib/features/shell/tour.dart` (вход из инструкции).
Данные: `assets/books.json` (96 книг; тот же файл лежит в `swift/AOBible/Resources/books.json` — проверено `cmp`).
Дизайн (цвета, радиусы, тени) не нужен: только функциональность, расположение, значения, тексты.
**[уточнить]** — не видно из прочитанных файлов; смотреть другие файлы Flutter или телефон.
**[Swift]** — коротко о расхождении; полный список — в последнем разделе.

Все видимые строки во Flutter проходят через `t('русский текст')`; **ключ перевода — сама русская строка**, подстановки — `{имя}`; формы числа — `tn('{n} шаг|{n} шага|{n} шагов', n)` (подробнее — `06c-shell.md` §8). Ниже все тексты даны по-русски.
Всплывающие сообщения («тосты») во Flutter — плавающая «таблетка» снизу экрана: 2,6 с; если есть кнопка («Отменить») — 5 с (`aobSnackBar`); новое сообщение заменяет прежнее.

## 0. Поправки к `SWIFT_SPEC.md` §5 и §6

1. §6 «Поле + кнопка «Найти», закреплено; при прокрутке сжимается» — это вид **не iPhone** (Android/веб). На iPhone `iosStyle` всегда включён: **кнопки «Найти» нет**, поле — **капсула внизу окна**, над клавиатурой (или над нижними вкладками, когда клавиатуры нет), а выбор области, переключатели и результаты — в списке над ней (§3.2).
2. §6 «Метка модуля у результата — короткое имя (≤ 5 знаков)» — точнее: **≤ 6 знаков** целиком, иначе **первое слово, обрезанное до 6 знаков** (`shortName` в `search_screen.dart`; это не то же правило, что у шапки панели — там 5, см. `01-reader-settings.md` §3.3).
3. §6 «номер Стронга (`G26`, `H7225`, `Г26`, `Н7225`, `3056`)» верно, но есть детали: допустимы также `Е7225` (русская «Е»), пробел между буквой и числом, ведущие нули, не более 4 цифр, голое число даёт **две** карточки (§3.7).
4. Уточнение к §5 «Недавние книги»: берутся из истории **той панели**, из которой открыто окно, а текущая книга всегда первой (§4.4); не из всех панелей.
5. §5 «сегмент Ветхий / Новый Завет / Апокрифы»: на самом деле «Ветхий Завет / Новый Завет / **Неканон**», вкладка показывается, только если в переводе есть книги этого раздела (§4.4).
6. §15 «Перевод интерфейса… названия книг на языке интерфейса» — точнее: названия книг **латиницей (английские)** у всех языков интерфейса, кроме `ru, uk, be, bg, sr`; у них — русские (кириллические) названия справочника (§2.5).

## 1. Хранение и ключи

SharedPreferences (на iPhone — `UserDefaults` с префиксом `flutter.`), **каждое значение — строка с JSON** (кроме `searchQuery`). Ключи совпадают с веб-версией и входят в файл «Мои данные» (`03-bookmarks.md` §12);
`searchQuery` и `lang` обрабатываются отдельно (`userdata.dart`).

| Ключ | Тип JSON | Значения / по умолчанию | Что хранит |
|---|---|---|---|
| `searchQuery` | **обычная строка** (не JSON) | `""`; старый формат — JSON-строка в кавычках, при чтении кавычки снимаются | последний запрос; пишется при закрытии окна (как есть, без `trim`) |
| `searchScope` | строка | `"all"` \| `"OT"` \| `"NT"` \| `"book"`; по умолчанию `"all"` | часть Библии |
| `searchWhole` | bool | `false` | «Только целые слова» |
| `searchAllModules` | bool | `false` | «Во всех модулях» |
| `searchOriginals` | bool | `false` | «И в оригиналах» |
| `searchHistory` | список строк | `[]`, **не более 15**, новый — первым, без повторов | недавние запросы |

Повреждённое значение → значение по умолчанию (чтение обёрнуто в `try`).
Не сохраняются (живут до перезапуска приложения): **результаты последнего законченного поиска** вместе с «сколько показано» и позицией прокрутки (`_Memo`, §3.11); выбранные шаги «Перейти» (книга/глава), положение вкладки завета.

## 2. Названия книг, сокращения и разбор ссылок (`core/books.dart`)

Используется и в поиске, и в «Перейти», и при импорте модулей (`06b-library.md` §5.4), и в планах.

### 2.1. Справочник
`assets/books.json` — список из **96** записей `{id, name, short, t, dc?}` в порядке Библии:
`id` — код OSIS (`Gen`, `1Sam`, `Matt`, `1John`, `Ps151`, `1En`…); `name` — русское название («От Иоанна», «1-е Коринфянам», «1-я Царств», «3-я Царств» для `1Kgs`); `short` — русское сокращение с точкой («Ин.», «1Кор.», «Пс.»);
`t` — `OT` / `NT` (для всех 96 стоит `OT` или `NT`; `AP` в файле не встречается); `dc: true` — неканоническая (30 книг: Товит, Иудифь, Премудрость, Сирах, Маккавеи, Ездры 2–3, Молитва Манассии, Енох, Юбилеи, 12 Заветов и др.).
Порядок записей = «порядок Библии» (`Books.order(id)`, неизвестный код → 1000).
Английские названия — константа `_en` (id → [название, сокращение]), например `Matt → ['Matthew','Matt']`, `1Cor → ['1 Corinthians','1 Cor']`, `Ps → ['Psalms','Ps']`, `Song → ['Song of Songs','Song']`.

### 2.2. Названия на языке интерфейса (`Books.meta`)
`meta(id)`: язык интерфейса `ru, uk, be, bg, sr` — русские `name`/`short` из справочника; **любой другой** язык (`Books.latinNames`) — английские из `_en`, если для книги они есть (иначе русские).
Книга, которой нет в справочнике (неизвестный `id` из импортированного модуля): `meta(id, name:, short:)` отдаёт названия **из модуля** (или сам `id`), раздел `AP`, порядок 1000.
Язык переключается без перезапуска (`setLang` → `Books.instance.lang`).
`formatRef(book, chapter, verse)` → `«{short} {глава}:{стих}»` (по умолчанию короткое; `full: true` — полное): «Ин. 3:16», «John 3:16».

### 2.3. Как строится таблица сокращений (`Books.load`)
Все ключи приводятся к виду `_norm`: нижний регистр, **без пробелов и точек**, `ё` → `е`. Таблица `_aliases` (ключ → id книги) наполняется в таком порядке; в пунктах 1–2 **последний записавший побеждает** (присваивание), в пункте 3 — **первый** (`putIfAbsent`):
1. для каждой книги по порядку справочника: её `id` (`john`), русское `name` (`отиоанна`), русское `short` (`ин`), английские `name` и `short` (`john`, `john`; для `1John` — `1john`);
2. затем **дополнительные сокращения** (`_extraAliases`, они перекрывают пункт 1): `Gen: бт, бытия` · `Exod: исход` · `Num: чисел, числ` · `Deut: вт, второзак` · `Josh: иисуснавин, навин, ииснав` · `Judg: судей` · `1Sam: 1царств, 1цар, 1sam` · `2Sam: 2царств, 2цар` · `1Kgs: 3царств, 3цар` · `2Kgs: 4царств, 4цар` · `1Chr: 1пар, 1паралипоменон` · `2Chr: 2пар, 2паралипоменон` · `Ezra: ездр, ездры` · `Neh: неемии` · `Esth: есфири` · `Ps: псалом, псалмы, псалтирь, пс` · `Prov: притч, пр` · `Eccl: екл, еккл, екклесиаста` · `Song: песн, песнь, песньпесней` · `Isa: исаии, исаия` · `Jer: иеремии` · `Lam: плачиеремии` · `Ezek: иезекииля, иез` · `Dan: даниила` · `Hos: осии` · `Joel: иоиля` · `Jonah: ионы` · `Mic: михея` · `Hab: аввакума` · `Zeph: софонии` · `Hag: аггея` · `Zech: захарии` · `Mal: малахии` · `Matt: мф, мтф, матф, матфея, отматфея, мт` · `Mark: мк, мар, марк, марка, отмарка` · `Luke: лк, лук, луки, отлуки` · `John: ин, иоан, иоанна, отиоанна` · `Acts: деян, деяния` · `Jas: иак, иакова` · `1Pet: 1пет, 1петра` · `2Pet: 2пет, 2петра` · `1John: 1ин, 1иоан, 1иоанна` · `2John: 2ин, 2иоан` · `3John: 3ин, 3иоан` · `Jude: иуд, иуды` · `Rom: рим, римлянам` · `1Cor: 1кор` · `2Cor: 2кор` · `Gal: гал` · `Eph: еф, ефес` · `Phil: флп, фил, филип` · `Col: кол` · `1Thess: 1фес, 1фесс` · `2Thess: 2фес, 2фесс` · `1Tim: 1тим` · `2Tim: 2тим` · `Titus: тит` · `Phlm: флм, филим` · `Heb: евр` · `Rev: откр, апок, откровение, апокалипсис`;
3. затем **сгенерированные** (`_generated`), только для ключей длиной **≥ 2** и только если ключ ещё не занят. Книги берутся в порядке справочника, **неканонические — после канонических** (короткое сокращение достаётся канонической книге). Для каждой:
   - из `name` в нижнем регистре выделяется **номер** по `^([1-4])(?:-?[а-яё]{1,2})?\s*(.*)$` («1-е Коринфянам» → номер `1`, основа «коринфянам») и **основа** (без номера; `ё` → `е`, без пробелов, точек и дефисов). Если основа начинается с «от » («От Матфея»), добавляется вторая основа без «от » («матфея»);
   - **начала названия**: все префиксы основы от 2 букв («ко», «кор», «кори»…);
   - **сокращения по согласным**: первая буква + все согласные дальше (гласные `аеиоуыэюяйъь` выбрасываются): «фессалоникийцам» → «фсслнкцм» → префиксы от 2 букв («фс», «фсс», «фссл»…);
   - сначала **проход по началам** всех книг, **потом** проход по согласным («пр» скорее «Притчи», чем что-то по согласным). Ключ записывается как `{номер}{форма}`; **для номера 1 дополнительно и без номера** («фс» → 1 Фесс., «кор» → 1 Кор.), для остальных номеров — только с номером («2фс»). Книга без номера — просто `форма`.

### 2.4. `findBookId(text)` — какая это книга
1. `key = _norm(text)`; если `_aliases[key]` есть — готово.
2. Иначе, если `key` короче **3** знаков — `null`.
3. Иначе первая запись `_aliases` (в порядке добавления в таблицу: сначала id/названия/сокращения книг по Библии, потом дополнительные, потом сгенерированные), **ключ которой начинается с `key`** → её книга. Не нашлось — `null`.

### 2.5. `parseHuman(text)` — ссылка из строки
`text.trim()` должно целиком подойти под
`^((?:[1-4]\s*)?[^\d\s:.,][^\d:,]*?)\.?\s*(\d+)(?:(?:\s*[:.,]\s*|\s+)(\d+)(?:\s*[-–]\s*(\d+))?)?\s*$`:
1) название книги — необязательный номер 1–4, затем текст без цифр, двоеточий и запятых (внутри допускаются пробелы и точки, на конце точка отбрасывается);
2) глава (цифры); 3) необязательно стих — после `:`, `.`, `,` или просто пробела; 4) необязательно `-`/`–` и конечный стих (**отбрасывается**: возвращается только начало).
Книга ищется `findBookId(группа 1)`; нет — `null`. Результат: `VerseRef(книга, глава, стих)`, **без стиха → стих 1**. Проверок «есть ли такая глава/стих» здесь **нет**.

| Ввод | Результат |
|---|---|
| `Ин 3:16`, `ин3:16`, `Ин. 3.16`, `Ин 3 16`, `Ин 3,16` | John 3:16 |
| `1 кор 13`, `1Кор.13:4-7`, `1-е Коринфянам 13` | 1Cor 13:1 (диапазон 4–7 отброшен) |
| `Пс 22`, `псалом 22` | Ps 22:1 |
| `фс 1:1` | 1Thess 1:1 («без номера — первая книга»); `2фс 1:1` → 2Thess |
| `флп 2:5`, `Мф 5:3`, `Откр 1`, `Быт1.1` | Phil / Matt / Rev / Gen |
| `John 3:16`, `Rom 8:28`, `1 Cor 13` | английские названия понимаются при **любом** языке интерфейса |
| `Ин` (без цифр) | не ссылка (`null`) |

## 3. Окно «Поиск» (`SearchSheet`)

### 3.1. Как открывается и кто его вызывает
- Нижняя вкладка **«Поиск»** (`openSearch(context, 0, fromTab: true)`); при split-режиме (две панели) в шапке каждой панели есть значок лупы с подсказкой «Поиск» → `openSearch(context, номер_панели)`.
- Инструкция (`tour.dart`) открывает его через `openSearch(context, 0)`.
- Параметры `query`/`scope` (явный запрос и область, например из словаря) в коде есть, но **никто, кроме инструкции, их не передаёт** — открытие всегда с сохранённым запросом.
- Окно — «лист» поверх читалки, вкладка «Поиск» внизу подсвечена; повторное нажатие на вкладку закрывает окно (`01-reader-settings.md` §5). Повторное нажатие на вкладку при открытом поиске ещё и ставит курсор в поле (`Hub.focusSearch`).
- Заголовок окна: **«Поиск»**. Подзаголовка на iPhone нет (на других платформах: `«{короткое имя перевода} · {полное название}»` либо `«Во всех модулях · {число переводов}»`).
- Панель, к которой привязан поиск (`widget.pane`), задаёт: «открытый» перевод (`panes[pane].moduleId`, при отсутствии — первый из установленных переводов), книгу для области «Книга» (`panes[pane].ref.book`) и панель, в которой откроется результат.

### 3.2. Раскладка (iPhone)
Сверху вниз, в прокручиваемом списке (`CustomScrollView`, касание страницы или прокрутка убирают клавиатуру):
1. **Область**: сегмент из 4 кнопок — «Вся Библия» · «ВЗ» · «НЗ» · **короткое название книги панели** («Ин.»; в английском интерфейсе — «John»). Выбор записывается в `searchScope` (`all/OT/NT/book`) и перезапускает поиск.
2. Переключатель **«Только целые слова»** (`searchWhole`).
3. Переключатель **«Во всех модулях»** (`searchAllModules`) — виден, только если кроме открытого есть ещё хотя бы один **перевод, не являющийся оригиналом** (§3.4).
4. Переключатель **«И в оригиналах»** (`searchOriginals`) — виден, только если виден п. 3, в установленных есть оригинал (`oshb` или `byz-rp2018`) **и «Во всех модулях» включён**.
   Пояснений под переключателями на iPhone нет (на других платформах: «Иначе «свет» найдёт и «светильник»», «Искать во всех установленных переводах. У каждого места — метка перевода.», «Еврейский и греческий текст — для поиска слов на иврите и греческом.»).
5. **Карточка ссылки** (§3.6), если запрос — ссылка.
6. **Карточка(и) Стронга** (§3.7), если запрос — номер Стронга.
7. **Недавние** (§3.8) — только когда нет ни результатов, ни карточек (`hits == null`).
8. Строка **«Найдено: {n}»** — когда идёт или закончился текстовый поиск (`hits != null`); если результатов 0 и поиск закончен — продолжение в той же строке: **« — попробуйте другую форму слова или отключите «целые слова».»**.
9. **Результаты** (§3.9) и в конце — кнопка **«Показать ещё ({n})»**.
10. **Поле ввода — отдельно от списка, внизу окна** (над клавиатурой: отступ ≈ 8 pt от клавиатуры; без клавиатуры — над нижними вкладками): слева значок лупы, подсказка **«Слово, Ин 3:16 или G26»**, справа круглый крестик (подсказка **«Очистить»**) — только когда в поле есть текст. Клавиша клавиатуры — «Поиск» (`TextInputAction.search`).

Фокус: через 220 мс после открытия курсор ставится в поле, **если** окно открыто вкладкой «Поиск» **или** результаты не восстановлены (§3.11). Если же окно открыто иначе и прежние результаты восстановлены — клавиатура **не** открывается (закрыла бы список). Уход окна (смена вкладки, переход к найденному) убирает клавиатуру.
Нажатие мимо поля и касание страницы снимают фокус (поле опускается к вкладкам).

### 3.3. Что происходит при вводе (общий порядок)
На каждое изменение текста и каждый переключатель вызывается `_schedule()`: короткая пауза — **260 мс, если в запросе (после `trim`) меньше 3 знаков, иначе 150 мс**; предыдущая пауза отменяется. По её окончании `_update()` проверяет **по порядку** (первое сработавшее — единственное):
1. Ключ условий поиска `key = JSON[запрос, область, (книга панели, если область «Книга», иначе ""), целые слова, id переводов-целей через запятую]` совпал с ключом уже показанных результатов → ничего не делаем.
2. **Запрос — номер Стронга** (`strongQuery`, §3.7) → поиск текста останавливается (результаты очищены), показываются карточки Стронга; ссылка сбрасывается.
3. **Запрос содержит цифру и разбирается как ссылка** (`parseHuman`, §2.5), **и эта книга есть в переводе** (`bookList(открытый перевод)`) → поиск текста останавливается, показывается **карточка ссылки** с текстом стиха. Если книги в переводе нет (например, «Мф 5» при открытом Ветхом Завете), запрос **идёт дальше как обычный текст**.
4. Запрос короче **2** знаков → поиск остановлен, результатов нет (история снова видна).
5. Совпал с ключом последнего законченного поиска (`_memo`) → показываются прежние результаты без перебора (и прежнее «сколько показано»).
6. Иначе — **запуск поиска** (§3.5).

Номер поколения (`_gen`) отбрасывает результаты устаревшего поиска. Любой новый запуск сбрасывает «показано» до первых 200.

### 3.4. Переводы для поиска (`_targets`)
- **Открытый перевод** — всегда первым.
- «Во всех модулях» включено **и** `_canAll` (есть ещё хотя бы один не-оригинал-перевод) → далее все **включённые** переводы (`ModuleStore.bibles` без `features.helper`), кроме открытого; оригиналы (`oshb`, `byz-rp2018`) — только при «И в оригиналах». Остальные упорядочены: **сначала того же языка, что у открытого, потом прочие** (порядок внутри групп — как в списке установленных, стабильность сортировки не гарантируется).
- Иначе — только открытый.
- Переводы-«подстрочники» (`features.interlinear`) **не исключаются** (они обычные переводы с разметкой); исключены лишь `features.helper` (служебные, сейчас — `vulg-interlinear`).
- Перевод по сети (`online`) входит в список, но в его базе только скачанные главы — найдёт только по ним.
- Перед первым запросом при открытии окна для каждого перевода-цели вызывается `warmSearch(id)`: текст перевода (без разметки) готовится заранее в отдельном потоке и хранится в памяти (последние 4 перевода).

### 3.5. Алгоритм текстового поиска (`searchText`, `queryRegex`)
Ищется **регулярным выражением по тексту каждого стиха без разметки** (`plainText`), в порядке записи в модуле (= порядок Библии). Не FTS: нужна и середина слова.
Из запроса строится выражение (`queryRegex`):
- пробелы по краям убираются, любая серия пробелов → один пробел; знак ударения U+0301 из запроса удаляется;
- каждый пробел между словами → `[\s\p{P}]+` (между словами в стихе допускаются пробелы и знаки препинания); **все слова фразы — по порядку**;
- `е`/`ё` (любой регистр) → `[её]` + необязательный знак ударения; любая другая **буква** → она сама + необязательный знак ударения (ударение в тексте не мешает); остальные знаки — экранируются;
- флаги: без учёта регистра, Unicode;
- «Только целые слова»: выражение оборачивается в `(?<!\p{L})…(?!\p{L})` (с обеих сторон не буква). Без него **часть слова подходит**: «свет» найдёт «светильник» и «освещать».
Перебор идёт по переводам из §3.4 **по одному**; в каждом — все совпадения (число не ограничено); область: `all` — вся книжная часть перевода, `OT`/`NT` — книги этого завета **по справочнику** (`Books.meta(id).testament`; неканонические книги, у которых `t = OT`, считаются Ветхим Заветом), `book` — только книга панели.
Результаты добавляются в список по мере готовности каждого перевода (экран обновляется). Перевод, который не открылся (ошибка), пропускается молча.
Ошибки поиска не показываются. Индикатора «Поиск…» в интерфейсе **нет** (строка `Поиск…` внутри кода не отображается): пока идёт перебор, виден счётчик «Найдено: N», растущий по мере готовности переводов.

### 3.6. Карточка ссылки (`.ref-hit`)
Когда запрос — ссылка на существующую в переводе книгу (§3.3, п. 3).
Выглядит как плашка во всю ширину: значок «↩» и жирный акцентный заголовок **«Перейти: {полное название книги} {глава}:{стих}»** («Перейти: От Иоанна 3:16»; в английском интерфейсе «John 3:16»), ниже — **текст этого стиха** (шрифт читалки, 16) из **открытого перевода** (`verseAt`).
Если такого стиха в переводе нет (глава/стих за пределами книги) — вместо текста серое **«В переводе {название перевода} нет такого стиха.»**.
Нажатие на карточку и клавиша «Поиск» (если карточка видна) → **переход** (§3.10). Диапазон «3:16-18» показывается и открывается как «3:16».
Стих 1 по умолчанию: «Ин 3» → «Перейти: От Иоанна 3:1».

### 3.7. Номер Стронга в строке поиска (`strongQuery`)
Выражение: `^\s*([HGhgНнГгЕе]?)\s*0*(\d{1,4})\s*$`, число после ведущих нулей **не ноль**.
- буква `G`/`g`/`Г`/`г` → греческий: `["G{n}"]`;
- буква `H`/`h`/`Н`/`н`/`Е`/`е` (латинская H, русские «Н» и «Е») → еврейский: `["H{n}"]`;
- **без буквы** (просто число) → **оба**: `["H{n}", "G{n}"]` (карточки идут в этом порядке);
- примеры: `G26`, `g 26`, `Г26`, `G0026` → `G26`; `Н7225`, `Е7225`, `H7225` → `H7225`; `3056` → `H3056` и `G3056`; `12345`, `0`, `G0`, `26 26` — не Стронг.
Проверка идёт **раньше** проверки ссылки и минимальной длины: уже `3` даёт карточки `H3` и `G3`. Поэтому **искать в тексте голое число (до 4 цифр) нельзя**.
Для каждого номера показывается карточка (`Hub.strongSearchCard`, `StrongSearchCard`): шапка «Номер Стронга {номер}», лемма, транслитерация, значение (≤ 160 знаков), строка «Статья словаря →»; под ней «Ищу все места…», затем места слова с рядами фильтров (книги, главы, варианты перевода) и порцией 200, **ограниченные областью поиска** (`all` — без ограничения; `OT`/`NT` — книги этого завета; `book` — книга панели). Подробности (откуда статья, «Все места», пустые состояния «В переводе со Стронгом этого слова нет.» и «В этой части Библии мест нет.») — `02-study.md` §4.2–4.3.
Особенности, важные для Swift:
- нажатие на **шапку** карточки: запоминает запрос в истории и открывает **статью словаря на всю высоту** (`autoOpen`);
- нажатие на **место** в списке: запоминает запрос в истории, закрывает все окна и переходит к стиху в панели (`_goRef`);
- если номера нет ни в одном русском словаре Стронга (кроме симфонии) — карточка и места не показываются вовсе (пустое место);
- **обычный текстовый поиск при этом не выполняется**; история не показывается.

### 3.8. Недавние запросы
Показываются, когда нет результатов, карточки ссылки и карточки Стронга, и список не пуст.
**iPhone**: строка в одну линию — слева значок часов (подсказка «Недавние»), справа ряд капсул-запросов, прокручиваемый вбок (непоместившиеся уходят за край с затуханием).
- нажатие: запрос ставится в поле, запускается поиск, запрос поднимается в начало истории;
- **долгое нажатие**: лёгкая вибрация (`selectionClick`) и удаление запроса из истории → сообщение **«Убрано из истории»** с кнопкой **«Отменить»** (5 с) — возвращает запрос **на прежнее место** списка (если он за это время не появился снова).
- кнопки «Очистить историю» на iPhone **нет**.
(На других платформах: заголовок «Недавние», строки с часами, свайп влево — красная корзина, крестик «Убрать из истории», внизу малая кнопка «Очистить историю».)

**Когда запрос попадает в историю** (`_remember`: пустой не пишется; поднимается в начало; не более 15):
- нажатие на результат; нажатие на карточку ссылки; клавиша «Поиск» (если карточки ссылки нет; клавиатура при этом убирается);
- нажатие на шапку или место карточки Стронга; нажатие на элемент истории;
- **при закрытии окна**: если длина запроса > 1 **и** «последний законченный поиск» (`_memo`) содержит результаты — запрос записывается (даже если результат не открывали). Условие проверяется по `_memo`, то есть по последнему *текстовому* поиску в сеансе, а не по текущему запросу (мелкая особенность).

### 3.9. Результаты
- Плоский список **без группировки по книгам**, в порядке перевода: сначала все совпадения первого перевода (в порядке Библии), затем второго и т. д. (в режиме «Во всех модулях» одинаковые места разных переводов **не** склеиваются).
- Показываются первые **200**; внизу кнопка **«Показать ещё ({осталось})»** (на всю ширину) добавляет ещё 200.
- Строка результата (вся строка нажимаема):
  1) жирная акцентная ссылка `formatRef` — «Ин. 3:16»; если целей больше одной — рядом **метка перевода** (короткое имя: ≤ 6 знаков целиком, иначе первое слово до 6 знаков);
  2) под ней **весь текст стиха** (без разметки; шрифт, гарнитура и стиль читалки, размер 16, интервал 1,5) с **подсветкой** (цвет выделения палитры `hl`) — каждого совпадения того же регулярного выражения `queryRegex(запрос, целые слова)` (§3.5), то есть ровно того, что совпало;
  3) справа вверху строки — значок **«Копировать»** (подсказка «Копировать»): в буфер уходит `"{текст стиха в одну строку}" - {Ин. 3:16}` (кавычки прямые, дефис с пробелами), затем сообщение **«Стих скопирован»**.
- Если в переводе у слова есть номера Стронга, разметка в тексте результата убрана.

### 3.10. Нажатие на результат и на карточку ссылки
- **Результат** (`_open`): запрос → в историю; **закрываются все окна** (`closeToReader`); если результат из перевода, отличного от перевода панели, и этот перевод ещё установлен, — **перевод панели меняется на тот, где найдено** (`setModule`); панель переходит к стиху (`navigate`) **с подсветкой слов запроса и миганием стиха** (`highlight: запрос`, `flash`).
  (Комментарий в коде говорит обратное — «место из другого перевода открывается в этом переводе», — но код переключает панель на перевод результата.)
- **Карточка ссылки** (`_goRef`): запрос в историю, закрытие всех окон, `navigate` к стиху **без** подсветки слов (мигание стиха — по умолчанию).
- Как читалка показывает подсветку: слова запроса длиной > 1 знака (запрос делится по пробелам и знакам препинания, каждое слово ищется как часть слова, `ё=е`) подсвечиваются в стихе 8 с, любое касание текста гасит (`01-reader-settings.md` §4.6; `highlightWords` в `bible.dart`).

### 3.11. Память окна
- `_memo` (в памяти до перезапуска приложения): ключ условий (§3.3 п. 1), список результатов, перевод каждого, сколько показано, позиция прокрутки. Заполняется, когда перебор **закончен**.
- При следующем открытии: поле заполняется сохранённым `searchQuery`; если ключ текущих условий совпал с ключом памяти — результаты, «Показать ещё» и прокрутка восстанавливаются мгновенно, поиск не повторяется. Иначе запускается обычный поиск.
- Кнопка очистки в поле («Очистить»): стирает текст, **сбрасывает память `_memo`**, убирает результаты, карточки; курсор остаётся в поле.
- Опции (`searchScope/Whole/AllModules/Originals`) пишутся сразу при изменении. Запрос — при закрытии окна.

### 3.12. Тексты окна «Поиск» (сводка)
«Поиск» · «Вся Библия» · «ВЗ» · «НЗ» · «Только целые слова» · «Во всех модулях» · «И в оригиналах» · подсказка поля «Слово, Ин 3:16 или G26» · «Очистить» · «Перейти: {ref}» · «В переводе {module} нет такого стиха.» · «Недавние» · «Убрано из истории» · «Отменить» · «Найдено: {n}» · « — попробуйте другую форму слова или отключите «целые слова».» · «Показать ещё ({n})» · «Копировать» · «Стих скопирован» · «Номер Стронга {номер}» · «Статья словаря →» · «Ищу все места…» · «В переводе со Стронгом этого слова нет.» · «В этой части Библии мест нет.».
Пустого состояния «ничего не введено» и «модулей нет» **нет**: страница просто пуста (или показывает историю).

## 4. Окно «Перейти» (`NavigatorSheet`)

### 4.1. Как открывается
Кнопка-плашка места в шапке панели (подсказка «{ref}. Выбрать место», `01-reader-settings.md` §3.2) → `openNavigator(context, номер_панели)`; из инструкции — `openNavigator(context, 0)`. Окно открывается через `showAobSheet(..., scripture: true)` (особенность вида листа, влияет на его высоту/положение относительно читалки **[уточнить по `kit.dart`]**).
Перевод, по которому строится список книг, — **перевод панели на момент открытия** (`panes[pane].moduleId`, не меняется, пока окно открыто). Список книг — `bookList(модуль)` (порядок модуля): `{id, name, short, chapters}`.

### 4.2. Три шага и заголовки
Шаги сменяют друг друга сдвигом (вперёд — новая страница въезжает справа, назад — слева, 220 мс, с затуханием).

| Шаг | Что на экране | Заголовок | Подзаголовок | Стрелка «назад» |
|---|---|---|---|---|
| 1. Книги | поле, недавние, вкладки заветов, разделы с плитками | **«Перейти»** | название перевода (`title`, иначе `name`) | нет |
| 2. Главы | сетка номеров глав | название книги | название раздела книги («Евангелия», «Пятикнижие»…) | к шагу 1 (прокрутка списка возвращается туда, где была) |
| 3. Стихи | кнопка «С начала главы» и сетка номеров стихов | «{книга} {глава}» (для книги из одной главы — только название книги) | название раздела | к шагу 2 (у книги из одной главы — сразу к шагу 1) |

Нажатие на книгу → шаг 2, **но у книги из одной главы сразу шаг 3 (глава 1)**. Нажатие на номер главы → шаг 3. Нажатие на номер стиха → **переход и закрытие окна**.
Кнопка «С начала главы» → переход к стиху 1 этой главы и закрытие окна. Переход — `navigate(pane, VerseRef(книга, глава, стих))` (с миганием стиха, без подсветки слов); затем окно закрывается.

### 4.3. Поле «Книга или ссылка» (шаг 1)
Капсула вверху: слева лупа, поле с подсказкой **«Книга или ссылка: Ин 3:16»** (без автоисправления; клавиатура по умолчанию **не** открывается — «сначала выбирают книгу по сетке»), справа — крестик **«Очистить»** (когда есть текст) и круглая кнопка-стрелка **«Перейти»** (подсвечена акцентом, пока в поле что-то есть; тот же эффект, что клавиша «Перейти» на клавиатуре — `_submit`).
При любом изменении текста красное сообщение об ошибке исчезает.
Режим по тексту (`q` — всё, что в поле):

| Что в поле | Что показано под полем |
|---|---|
| пусто | недавние (§4.4), вкладки заветов, разделы с плитками |
| **«запрос книги»** (только буквы, перед которыми может стоять одна цифра 1–4: `^\s*[1-4]?\s*([^\d\s:.,][^\d:,]*)?$`, т. е. `кор`, `1 ин`, `бытие`, `1`) | **плоский список подходящих книг** плитками без разделов и без вкладок (§4.5), либо серое **«Ничего не найдено.»** |
| иное (есть цифры — ссылка) | если ссылка понятна — **карточка «Перейти: …»** (§4.6); книг, недавних и вкладок **нет** |

### 4.4. Шаг 1: недавние, вкладки заветов, разделы
**Недавние книги**: список id = [текущая книга панели (по живой позиции чтения)] + книги из истории переходов **этой панели** от новых к старым, без повторов, всего **до 8**; показываются те, что есть в переводе. Строка высотой 30: значок часов (подсказка «Недавние») и капсулы с **полным названием книги**, текущая — в акцентном цвете; нажатие → шаг 2. Прокручивается вбок с затуханием.
**Вкладки заветов** — сегмент на всю ширину, **закреплён сверху при прокрутке**: «Ветхий Завет» · «Новый Завет» · «Неканон». Показываются только те, для которых в **этом переводе** есть книги; если вкладка одна — сегмента нет.
Какая книга к какому завету: `Books.meta(id).testament`; но если в переводе **все** книги неканонические/неизвестные (`onlyDc`) — все книги идут одной вкладкой `Неканон`. Книги, неизвестные справочнику, тоже в `Неканон`.
Начальная вкладка — завет текущей книги панели (если вкладка есть), иначе первая.
Переключение: нажатие на сегмент или **горизонтальный свайп по окну** (только на шаге 1 при пустом поле и ≥ 2 вкладках): содержимое тянется за пальцем, при отпускании доезжает до ближайшей вкладки; быстрый свайп (> 250 pt/с) переключает на соседнюю. При смене вкладки список прокручивается к началу.
На iPhone ряд «Недавние» стоит **под** сегментом заветов (если вкладок ≥ 2), иначе — над списком книг.

| Откровение | Rev |
| Другие книги | всё прочее (Ps151, PrAzar, Sus, Bel, 1En, Jub, 12 Заветов, книги неизвестных кодов) |

У каждого раздела свой цвет: слева от заголовка раздела — точка 7 pt этого цвета; заголовок — приглушённый, мелкий. Внутри раздела книги — **в порядке перевода**.
**Плитка книги** (`_BookCell`): минимальная высота 62; крупное **сокращение без завершающей точки** («Ин», «1Кор»; в английском интерфейсе — «John», «1 Cor»), под ним название (одной строкой, затухает); у книг из `_dcIds` справа вверху **«*»**; текущая книга панели — выделена акцентом. Названия — по справочнику на языке интерфейса (§2.2), а **не** из модуля (из модуля — только для неизвестных кодов).
Колонок `floor(ширина / 108)` ограничено 3…8, зазор 8. Нажатие на плитку → шаг 2 (или 3 для однoглавной книги).

### 4.5. «Запрос книги»: сужение списка
Нормализация для сравнения (`_norm`): нижний регистр, `ё` → `е`, удалены пробелы, точки, дефисы и «–». Слова названия (`_words`): разбивка по пробелу, точке, дефису, длиной > 1.
`k = _norm(запрос)`; `alias = findBookId(запрос)` (§2.4). Книга подходит, если: её `id == alias`, **или** нормализованное сокращение начинается с `k`, **или** нормализованное название начинается с `k`, **или** любое слово названия начинается с `k`.
Порядок: книга по точному/однозначному сокращению (`alias`) — **первой**, остальные — в порядке перевода. Плитки — те же, что в §4.4, но без разделов, вкладок и недавних. Пусто — «Ничего не найдено.».

### 4.6. Ссылка в поле: карточка «Перейти: …»
Когда в поле не «запрос книги», а текст с цифрами: `parseHuman` (§2.5); книга должна быть в этом переводе; `1 ≤ глава ≤ число глав книги`. Стих **приводится в границы** `1…последний стих главы` (число стихов — из базы перевода: `SELECT MAX(verse) … GROUP BY chapter`; нет данных — 1).
Карточка: значок «↩», текст **«Перейти: {полное название} {глава}:{стих}»** (название — по языку интерфейса). Нажатие → `_go`: переход и закрытие окна. Нет текста стиха — только адрес.
Карточка видна **сразу при вводе**, не нужно ждать Enter.

### 4.7. Enter / стрелка «Перейти» (`_submit`)
1. `parseHuman(текст)` ≠ `null`:
   - книги нет в переводе → красная строка **«В переводе {название перевода} нет этой книги.»** (используется короткое `name` модуля);
   - глава < 1 или > числа глав → красная строка `В книге «{book}» {n} глав.` (число без склонения: «В книге «Иуды» 1 глав.»);
   - иначе → переход к `(книга, глава, стих в границах)` и закрытие окна.
2. Не разобралось, но это «запрос книги» — **открыть её главы** (шаг 2/3), если: `findBookId` дал книгу, которая есть в переводе, или подходящая книга ровно одна.
3. Иначе — **«Не понял ссылку. Пример: Ин 3:16»**.
Escape (клавиатура) при заполненном поле стирает его, повторное — закрывает окно.

### 4.8. Шаг 2: сетка глав
Номера `1…число глав` плитками (минимум 52 pt шириной, 8 зазор, высота 52); текущая глава (если открыта текущая книга) — залита акцентом. Нажатие → шаг 3. Число глав — из `bookList` модуля.

### 4.9. Шаг 3: стихи
Сверху широкая кнопка **«С начала главы»** (значок раскрытой книги) → переход к стиху 1; ниже сетка `1…N` (N — число стихов главы из базы; текущий стих текущей главы залит акцентом). Если число стихов неизвестно (глава не скачана — перевод по сети) — сетка пуста, остаётся кнопка.

### 4.10. Данные и правила — итог
Входные данные: перевод панели (книги, число глав, число стихов по главам), справочник (названия на языке интерфейса, разделы, завет), история переходов панели, текущая позиция панели (`livePositions`, а при её отсутствии — `ref`).
Выходные: `navigate(pane, VerseRef)`; настройки не пишет.

## 5. Как окна связаны
```
Шапка панели: [место] ───► «Перейти» ───(ссылка/книга/глава/стих)───► читалка (navigate, мигание стиха)
Нижняя вкладка «Поиск» ───► «Поиск» ─┬─ запрос-ссылка ─► карточка ─► читалка (без подсветки слов)
                                      ├─ запрос-Стронг ─► карточка слова ─► статья словаря (full) / место ─► читалка
                                      └─ слово ─► результаты ─► читалка (подсветка слов 8 с, перевод панели = перевод результата)
«Поиск» и «Перейти» — разные окна: ссылка «Ин 3:16» разбирается одним и тем же `Books.parseHuman`, но
в поиске книга должна быть в переводе (иначе это обычное слово), а в «Перейти» стих ещё и приводится в границы главы.
```
- Переход к результату закрывает **все** открытые окна (`closeToReader`); из «Перейти» — только само окно.
- Нижние вкладки остаются на месте; вкладка «Поиск» подсвечена, пока окно открыто.

## Расхождения со Swift

Проверено по: `Views/SearchPage.swift`, `Views/ReaderView.swift` (`GotoSheet`, `ChapterGrid`, `VerseGrid`), `Core/SearchEngine.swift`, `Core/RefParser.swift`, `Core/Books.swift`, `RootView.swift` (вход в поиск), `Core/PanesStore.swift` (`open`, `recentBooks`).

### А. Разбор названий книг и ссылок (`RefParser.swift`, `Books.swift`) — сильное расхождение
1. **Сокращения из справочника и дополнительные сокращения не используются.** `RefParser` строит таблицу только из `name` (начала названий и сокращения по согласным); нет `id` OSIS, нет `short` (Ин., Мф., Пс.…), нет `_extraAliases`, нет английских названий. Расчёт по тому же алгоритму (воспроизведён в Node по `books.json`) показал, что **25 из 96 кратких названий** разбираются в другую книгу или не разбираются:
   - `Ин` → **Иона** (вместо От Иоанна); `Мк` → **1 Маккавейская**; `Иуд` → **Иудифь**; `Ис` → **Исход** (вместо Исаия); `Мф`, `Нав` → не находятся вообще;
   - не находятся: `Иудф., Мол.Ман., Посл.Иер., Пс.151, Песн.отр., Енох, Юбил.` и все 12 `Зав.…`;
   - `John 3:16`, `Gen 1`, `1 Cor 13`, `Rom 8` — не работают (нет английских названий).
   Исправление: перенести `Books.load()` целиком (§2.3: пункты 1–3), в том числе порядок «явные присваивания перекрывают, сгенерированные — `putIfAbsent`, неканонические — после канонических».
2. `findBook` (Swift) ищет по префиксу в `order` — порядок вставки отличается от Flutter (там id/названия/сокращения книг идут первыми, потом дополнительные, потом сгенерированные).
3. Названия книг на языке интерфейса: в Swift `Books.swift` читает только русские `name/short`; **английских названий для нелатинских интерфейсов нет** (`latinNames`, `_en`). Поэтому в английском интерфейсе названия книг в поиске/«Перейти» русские.
4. `parseHuman` во Flutter возвращает без проверок; `RefParser.parse` Swift возвращает ещё `endVerse` (Flutter его отбрасывает) — безвредно.

### Б. Поиск
5. **Номер Стронга**: Swift (`SearchEngine.strongNumber`) понимает только `G`/`H` + цифры (любой длины, без ведущих нулей); нет `Г`/`Н`/`Е`, пробела после буквы, ведущих нулей, ограничения 4 цифры и **голого числа** (две карточки H и G).
   Результат тоже другой: Swift показывает одну строку-ссылку «`G26` — словарная статья» (если есть словари) и **одновременно запускает текстовый поиск стихов** с этим номером в разметке; Flutter карточку слова (лемма, транслитерация, значение ≤ 160 знаков, «Статья словаря →»), «Ищу все места…», ряды фильтров (книги / главы / варианты перевода), места порциями по 200 с подсветкой слов с номером; **обычный текстовый поиск не запускается**; область (ВЗ/НЗ/книга) ограничивает места.
6. **Карточка ссылки**: Swift показывает «Перейти: Ин. 3:16» (короткое название, без текста стиха) для любой разобранной ссылки, **не проверяя, есть ли книга в переводе** и не показывая текст. Flutter: полное название, **текст стиха** под ним, серое «В переводе {module} нет такого стиха.», а если книги нет в переводе — запрос продолжается как текст. Во Flutter ещё обязательна цифра в запросе.
   Нет: открытия по клавише «Поиск»/Enter, когда карточка видна.
7. **Область «Книга»**: Swift — `currentBook = panes.panes.first?.book` (первая панель, книга из `PaneState.book`), подпись `Books.info(...).short`; во Flutter — панель, из которой открыто окно, подпись на языке интерфейса. Область **не сохраняется** (`@State`), во Flutter — `searchScope`.
8. **Память**: нет сохранения запроса между запусками (`searchQuery`; Swift держит `query` в `RootView` только на время процесса), нет восстановления результатов, «Показать ещё» и позиции прокрутки (`_Memo`), нет ключа условий (`_keyOf`) — Swift пересчитывает при каждом `onAppear`.
9. **История**: Swift пишет запрос на `onDisappear` для любого запроса > 1 знака (Flutter — только при наличии результатов последнего поиска, а также по Enter и нажатию на элементы); элемент истории по нажатию не поднимается в начало; есть кнопка «Очистить историю» (на iPhone во Flutter её **нет**); контекстное меню «Убрать из истории» вместо долгого нажатия с вибрацией, **без сообщения «Убрано из истории» и «Отменить»**.
10. **Результаты**: порция 50 (Flutter — 200, «Показать ещё» тоже +200); нет значка «Копировать» в строке и сообщения «Стих скопирован»; метка перевода — `m.name` целиком (Flutter — `shortName`, ≤ 6 знаков); при нескольких переводах Swift **склеивает и сортирует все результаты по порядку Библии** (одно место — переводы подряд), Flutter выдаёт переводы **по очереди** (сначала весь первый, потом второй…).
11. **Переходы из поиска**: Swift открывает место в **первой панели** текущим переводом (`panes.open`), не меняет перевод на тот, где найдено, **не подсвечивает слова запроса** и не вызывает мигание стиха; нет привязки к панели, из которой открыт поиск (при split).
12. **Переводы-цели**: Swift исключает `interlinear` и по умолчанию берёт `store.bibles` (без сетевых); открытый перевод не гарантирован первым (при «Во всех модулях» порядок — как в `store.bibles`, ru первыми); нет перестановки «того же языка вперёд». Оригиналы без галочки «И в оригиналах» исключены, но если открыт сам оригинал, Swift при выключенных переключателях исключает его из «Во всех модулях» (Flutter: открытый — всегда в списке).
13. **Поле и раскладка**: Swift — системное `.searchable` и нижняя панель с кнопкой «назад» (аналог поля внизу есть); подсказка совпадает «Слово, Ин 3:16 или G26»; нет «крестика очистки с сбросом памяти» (системный); нет паузы 260/150 мс (Swift ищет на каждое изменение, отбрасывая устаревшие — допустимо).
14. **Пустые состояния**: Swift показывает «Слово, ссылка вроде Ин 3:16 или номер Стронга, например G26.» (когда нет истории) и «Сначала скачайте перевод Библии: «Ещё» → «Библиотека модулей».» — во Flutter таких текстов нет; текст при 0 результатов: Swift — в подвале «Попробуйте другую форму слова или отключите «только целые слова».», Flutter — в той же строке «Найдено: 0 — попробуйте другую форму слова или отключите «целые слова».». Индикатор «Поиск…» (ProgressView) есть в Swift, во Flutter нет.
15. **Движок**: Swift ищет подстроку по «сложенному» тексту (`fold`: нижний регистр, `ё=е`, без ударений, любые не буквы/цифры → один пробел) — по результату эквивалентно `queryRegex`; подсветка `SearchEngine.highlighted` повторяет `queryRegex` (жёлтый фон 0,4). Совпадает: минимум 2 знака, «целые слова», порядок слов, середина слова.

### В. «Перейти» (`GotoSheet`)
16. **Нет сужения списка книг по вводу** («кор», «1 ин»): поле в Swift — только ссылка (`RefParser` + кнопка-стрелка); нет «Ничего не найдено.»; нет живой карточки «Перейти: …» (проверка только по Enter).
17. **Нет вкладок «Ветхий Завет / Новый Завет / Неканон»** и свайпа между ними (все разделы одним прокручиваемым списком); нет закрепления сегмента.
18. Разделы: порядок и состав совпадают, но у раздела нет цветной точки (цвет раздела — подложка плиток 14 %, а во Flutter плитки нейтральные, цвет только точка); нет «*» у неканонических; текущая книга залита акцентом (так же, как во Flutter).
    В сетках глав и стихов Swift **не выделяет** текущую главу и текущий стих (Flutter заливает их акцентом).
19. Названия и сокращения на плитках — **из модуля** (`ModuleBook.name/short`), а не по справочнику на языке интерфейса; во Flutter модуль определяет названия только для неизвестных кодов.
20. **Недавние книги**: Swift — `panes.recentBooks()`: история **всех панелей**, до 8, без принудительной «текущей книги первой»; Flutter — только своя панель, текущая первой. Расположение под сегментом заветов (iPhone) в Swift невозможно, пока нет сегмента (п. 17).
21. Шаги: у книги из одной главы Swift показывает сетку с единственной главой «1» (Flutter сразу ведёт к стихам); заголовки шагов: Swift — название книги/«{книга} {глава}» без подзаголовка-раздела; кнопка «Читать главу N» (Flutter «С начала главы»); `onPick(0)` — стих 0 (в Swift `verse = 0` у панели означает начало главы, так же как у только что созданной панели; во Flutter — стих 1: различие во внутреннем представлении, не в видимом поведении).
22. Проверка ссылки: Swift при ошибке показывает одну строку «Не нашёл такое место в этом переводе.» (Flutter: «Не понял ссылку. Пример: Ин 3:16» / «В переводе {module} нет этой книги.» / «В книге «{book}» {n} глав.»); стих не приводится в границы главы (`min(max(1,…), последний)` во Flutter); при вводе только названия книги («Ин», «бытие») Swift ошибку показывает, Flutter открывает её главы.
23. Нет стрелки «назад» по шагам внутри листа (используется `NavigationStack` с системной кнопкой — допустимо), нет сохранения прокрутки списка при возврате, нет Escape.
24. Заголовок и подзаголовок: Swift «Перейти» без названия перевода; кнопка «Закрыть» вместо крестика.

### Г. Что совпадает
Состав и порядок 10 разделов (кроме точки и «*»), поле «Книга или ссылка: Ин 3:16», иконка/стрелка «Перейти», переход и закрытие окна по номеру стиха, сетки глав/стихов (число стихов из базы), общие настройки поиска «Только целые слова / Во всех модулях / И в оригиналах» (но ключи `@AppStorage` без префикса `flutter.` и не в JSON-строках), 15 записей истории, минимум 2 знака, список оригиналов `oshb`/`byz-rp2018`.

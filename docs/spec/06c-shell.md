В `help_data.dart` склеены и телефонный, и широкий варианты (например, «Закладки» — 4 шага, «Планы» — 3), а в `tourDefs` для телефона — **3** и **2** шага. Правило: `tourDefs.steps(phone)` (§3).
3. «Что нового: после обновления один раз — записи новее просмотренной; новому человеку — ничего» верно, добавить: показываются **все записи новее** одним списком (без заголовков по датам), а подзаголовок — дата **самой новой**; из меню «Что нового» — **только последняя** запись (§5).

## 1. Порядок запуска и показ окон при старте

### 1.1. `main()`
1. `prefs` (SharedPreferences) → тема системы (`systemDark`) → `Books.load()` (справочник) → `initI18n()` (язык; §7.2) → `ModuleStore.init()` (список модулей, `disabled.json`) → `registerFeatures()` (регистрация функций; в `shell.register()`: установка журнала ошибок, `prepareFirstRun`, добавление заданий запуска) → `runApp`.
2. Смена языка (`onLangChanged`) пересоздаёт регистрации (`Hub.reset()` + `registerFeatures()`): подписи пунктов меню заново.
3. Корень — `ProviderScope`, который можно пересоздать целиком (`Hub.restartApp`; после переноса данных из старого приложения).
4. `home`: **есть хотя бы один перевод → `HomeScreen`, иначе `BootstrapScreen`** (§9). Тема системы и «Повышение контраста»/«Уменьшение движения» подхватываются на лету (на iPhone — через `didChangeAccessibilityFeatures`).

### 1.2. Задания после первого кадра (`Hub.afterStart`, выполняются по очереди, ошибка одного не мешает другим)
Оболочка добавляет одно задание, которое запускает три **независимых** фоновых процесса:
- `_showStartup()` — приветствие или «Что нового»;
- `installStarterModules()` — доустановка стартовых модулей (`06b-library.md` §8);
- `_playUpdateNotice()` — только Android, на iPhone не нужно.

### 1.3. `_showStartup()` — когда показывается окно
1. Ждёт, пока появится хотя бы один перевод (проверка раз в 0,5 с, до 1200 раз; не дождалась — выходит ничего не показав).
2. Пауза 1,2 с.
3. До **20 попыток раз в 2 с**: есть корневой навигатор **и на нём нет открытых окон** (`!canPop()`) →
   - если `welcomePending == true` → `markNewsSeen()` (сохраняет id самой новой записи) и `openWelcome` (§2);
   - иначе `pendingNews()` → если не пусто — `openNews(items)` (§5).
   Показывается **одно** из двух. Выход после показа.
4. За 20 попыток окно не показано (всё время что-то открыто) — не показывается до следующего запуска (флаги не меняются).

### 3.3. Как работает тур (`TourOverlay`, `tourState`)
**Что видит человек.** Поверх приложения (выше нижних вкладок) экран затемнён (чёрный ≈ 50 %), нужное место «вырезано» окошком со скруглёнными углами и **мигающей рамкой** акцентного цвета (3 pt + мягкий ореол, период 1,4 с). Если у шага нет цели (или цель сейчас не найдена) — затемнён **весь** экран, облачко по центру.
Облачко (карточка, ширина `min(520, ширина экрана − 24)`): мелкая строка **«{название урока} · шаг {n} из {всего}»**, ниже **текст шага** (17,3). Если цель есть — у облачка стрелочка к ней.
Панель управления (отдельная карточка, та же ширина): ряд точек-прогресса (текущая — вытянутая 22 pt, остальные 8 pt; пройденные бледнее акцента), справа крестик **«Закончить инструкцию»**; ниже кнопки **«‹ Назад»** (со второго шага) и **«Далее»** (акцентная, на всю оставшуюся ширину); на **последнем шаге** вместо «Далее» — **«Понятно»** (с галочкой).
Для VoiceOver у корня: «Инструкция: {название урока}».
**Расположение.** Подсветка = прямоугольник цели + 6 pt с каждой стороны, обрезанный полями 4 pt. Панель управления — внизу над нижними вкладками (отступ 12); **вверху**, если центр цели ниже 60 % высоты рабочей области или цель доходит до панели. Облачко — под целью (зазор 14), если помещается, иначе над ней, иначе у края; без цели — по центру. Подсветка, облачко и стрелка **следят за целью каждый кадр** и плавно переезжают (коэффициент 0,25).
**Касания.** Затемнение **не перехватывает** касания: нажать можно куда угодно, ничего не блокируется; выполнением шага считается касание **внутри подсвеченной области** (у шагов с `next`) — человек нажимает **настоящую** кнопку приложения.

**Управление шагом.**
- `until` (условие «шаг выполнен сам») проверяется каждый 10-й кадр. При входе в шаг запоминается, верно ли оно уже: **если верно — шаг «вооружается» только после того, как условие станет неверным**; потом, когда оно становится верным — шаг засчитан, переход к следующему без действия.
- «Далее» (`_advance(true)`): если у шага есть `next` и `until` ещё не верно — выполнить `next` (действие за человека); подождать 350 мс (только если `next` есть); перейти к следующему шагу, а после последнего — закончить тур (`stopTour`, **без** сброса экрана).
- Человек сам нажал на подсвеченное место: на отпускании пальца внутри исходного прямоугольника цели шага (только у шагов с `next`) через 350 мс — переход без повторного действия.
- «Назад» — просто предыдущий шаг (изменений на экране не откатывает).
- **«Понятно»** и **крестик** — `reset()` (закрыть все окна, снять выделение первой панели, закрыть карту) и конец тура.
- Вход в шаг: на **шаге 1** сначала `reset()`, через **250 мс** — `before`; на остальных через **80 мс** — `before` («подготовить экран» — открыть нужное окно, выделить стих…). Смена шага запускает тур заново с этого шага.
- Любые окна открываются из тура через общий навигатор приложения (над ним лежит сам тур).
- Один тур за раз; новый `startTour` убирает прежний.

**Помощники шага (`TourApi`).**
- `openSheet(kind)`: `search` → окно «Поиск» (панель 0); `nav` → «Перейти» (панель 0); `plans`, `bookmarks` — планы / закладки; `prefs` — «Настройки»; `settings` — «Оформление»; `library` — «Библиотека модулей»; иначе — пункт «Ещё» с таким id (`sermons`, `maps`).
- `closeSheet()` — закрыть все окна; `reset()` — окна, выделение, карта.
- `click(rect)` — настоящее касание в центр прямоугольника (синтетическое событие).
- `selectVerse()` — если выделения нет, выделить **стих в начале читалки** первой панели (по живой позиции).
- Условия-помощники: «есть выделение первой панели», «есть вторая панель», «открыта карта», «открыт поповер слова» (`_Popover`), «открыт лист «Ещё»» (окно с заголовком «Ещё»), «проигрыватель на экране» (высота > 1), «на экране есть текст X».

**Раскладка** `phoneLayout()`: ширина экрана **< 900** → «телефон» (вкладки внизу, пункты «Ещё»); иначе — широкий вариант (меню ⋮ вверху). На iPhone всегда телефон; для iPad действуют варианты в скобках (§3.5).

Тексты скопированы в `swift/AOBible/Core/NewsData.swift` (генерируется из этого файла).
Ключ `newsSeen` — `id` последней виденной записи.

### 5.2. Что показывать при запуске (`pendingNews`)
- `newsSeen` нет → **только последняя** запись (человек пользовался раньше, но «Что нового» ещё не видел);
- иначе → все записи с `id` **строго больше** (сравнение строк) `newsSeen`, от новых к старым; ничего нет → окно не показывается.
- Первый запуск приложения: `prepareFirstRun` ставит `newsSeen` = самый новый id, поэтому новому человеку «Что нового» не показывается.
`openNews` в момент открытия записывает `newsSeen` = id **самой новой** записи списка (`news.first.id`) — то есть окно считается просмотренным сразу.

### 5.3. Окно
Заголовок **«Что нового»**, подзаголовок **«Обновление от {дата}»** — дата **самой новой показанной записи** («24 октября»: формат «день + месяц словом» из таблицы `monthDayTemplates[язык интерфейса]`, например en «24 October», de «24. Oktober», es «24 de octubre», ja «10月24日»; нет таблицы — русская; id не разбирается — как есть).
Содержимое: **один** общий список пунктов — все пункты показанных записей подряд (без заголовков по датам), с маркером акцента; текст 16 pt. Внизу кнопка на всю ширину **«Понятно»** (закрывает окно).
Из «Ещё» → «Что нового» и «Настройки» → «Что нового» («Последнее обновление») — открывается `openNews(c)` без списка: показывается **только последняя запись** (и `newsSeen` обновляется).
Пунктов-переводов нет в `news_data.dart`: каждая строка проходит через `t(...)` — перевод берётся из словаря интерфейса.

## 6. «Сообщить о проблеме» (`report.dart`)

### 6.1. Где
«Ещё» → «Сообщить о проблеме» (значок «сообщение с !»; показывается вместе с «Инструкцией» по флагу `menu.help`). Отдельного экрана нет.

### 6.2. Что происходит при нажатии (`reportProblem`)
1. Собирается ссылка `mailto:dubossarets@gmail.com?subject=…&body=…` (значения закодированы как компоненты URL).
   - тема: **«AO Bible: проблема»** (переводится);
   - тело: **«Что случилось и что вы делали перед этим:»**, затем три пустые строки (`\n\n\n\n`), строка `— — —` и **блок сведений**; всё тело обрезается до **1800 знаков** (длинные ссылки обрезают почтовые программы).
2. Открывается почтовое приложение (`launchUrl`); человек **видит текст и сам отправляет**. Автоматически ничего не уходит.
3. Не открылось (нет почтовой программы / ошибка) — всплывающее сообщение с адресом: **dubossarets@gmail.com**.

### 6.3. Блок сведений (строки по порядку)
1. `AO Bible {версия} (Flutter)` — для отладочной сборки `(Flutter, debug)`;
2. `{операционная система} {версия}`;
3. `{ширина}×{высота} · {код языка интерфейса}` (физические пиксели: логический размер × плотность, округлено);
4. `modules: {число включённых модулей} — {id первых 40 через запятую}`;
5. `errors:` и ниже по строке `{дата-время} {сообщение}` либо `errors: —`.

### 6.4. Журнал ошибок (`errorLog`)
- Подключается один раз при запуске (`installErrorLog`) поверх уже стоящих обработчиков: ловит ошибки интерфейса (`FlutterError.onError`: первые 2 строки описания) и необработанные ошибки (`PlatformDispatcher.onError`: сообщение + первая строка стека).
- Запись: `{t: "ГГГГ-ММ-ДД ЧЧ:ММ" (локальное время; ISO обрезан до 16 знаков, «T» → пробел), m: сообщение}`; пробельные серии в сообщении → один пробел; **длина ≤ 220 знаков**; подряд идущая такая же ошибка не повторяется; хранится **не более 12** последних (ключ `errorLog`, JSON-список); в «Мои данные» и копии не попадает.
- Для Swift: перехватить необработанные не получится так же; рекомендация — писать в такой же журнал **перехваченные** ошибки (установка модуля, сеть, база) и показывать в письме **[решение за разработчиком]**.

## 8. Формы числа (`tn`, `plural`, `pluralCategory`)

### 8.1. Ключ и значение
Для фраз с числом ключ — русский с тремя формами через `|`: `«{n} шаг|{n} шага|{n} шагов»` (один | несколько | много). В словарях других языков значение — объект с категориями `one/few/many/other`.
`tn(key, n, [params])`:
- значение в словаре — **объект** → `v[категория(язык, n)]`, иначе `other`, иначе первое;
- значение — непустая **строка** → она;
- иначе (русский, нет перевода) → русские формы: категория для `ru` (`one` → 1-я, `few` → 2-я, остальное → последняя); если форм меньше трёх — 1-я для «few».
Затем `{n}` → число и остальные подстановки. `plural(key, n)` из оболочки — тот же `tn` (имя осталось от старой версии), `loadPlurals()` ничего не делает.

### 8.2. Категории (`pluralCategory(язык, n)`)
| Языки | Правило |
|---|---|
| `ru, uk, be, sr` | `one`: n mod 10 = 1 и n mod 100 ≠ 11; `few`: n mod 10 = 2…4 и n mod 100 вне 10…19 (т. е. < 10 или ≥ 20); иначе `many` |
| `pl` | `one`: n = 1; `few`: n mod 10 = 2…4 и n mod 100 < 10 или ≥ 20; иначе `many` |
| `cs` | `one`: n = 1; `few`: n = 2…4; иначе `other` |
| `ro` | `one`: n = 1; `few`: n = 0 или n mod 100 = 2…19; иначе `other` |
| `ja, zh, ko, id` | всегда `other` |
| остальные (en, es, pt, fr, de, it, bg, ka, hy, hi, sw) | `one`: n = 1; иначе `other` |
(n — целое, как у `Intl.PluralRules`.)

### 8.3. Фразы с формами числа (12 — в словарях)
«день подряд|дня подряд|дней подряд» · «день|дня|дней» · «{n} шаг|{n} шага|{n} шагов» · «{n} отрывок|{n} отрывка|{n} отрывков» · «{n} место|{n} места|{n} мест» · «{n} место Писания|{n} места Писания|{n} мест Писания» · «{n} глава|{n} главы|{n} глав» · «{n} раз|{n} раза|{n} раз» · «в {n} стихе|в {n} стихах|в {n} стихах» · «употребление|употребления|употреблений» · «стих|стиха|стихов» · «книга|книги|книг».
В этой области (оболочка) используется только «{n} шаг|…» (подпись урока в списке инструкции). Остальное — планы, «Все места», статистика слова (`02-study.md`, `04-plans.md`).
Замечание: «В книге «{book}» {n} глав.» («Перейти») и «{n} глав» в библиотеке для аудио — **без** форм числа (во Flutter так и есть).

## Расхождения со Swift

Проверено по: `Views/InfoViews.swift` (`WelcomeSheet`, `HelpView`/`HelpLesson`, `AboutView`, `NewsView`, `ReportView`, `MyDataView`), `Core/HelpData.swift`, `Core/NewsData.swift`, `Views/SettingsView.swift` (язык), `Views/MoreView.swift`, `RootView.swift` (запуск, приветствие, язык), `Core/Starter.swift`, `Core/Books.swift`, `Resources/*.lproj/Localizable.strings`.

### А. Запуск и приветствие
1. **Условие показа.** Swift: лист `WelcomeSheet` показывается при `!welcomeSeen` **сразу при запуске** (поверх всего, без ожидания перевода и без проверки «нет открытых окон»). Flutter: только новому человеку (`welcomePending` ← `prepareFirstRun`), после появления перевода + 1,2 с, когда нет открытых окон, до 20 попыток; для установивших поверх Flutter-версии (перенос `flutter.settings`) Swift покажет приветствие снова.
2. **Содержание.** Swift — одна страница: значок книги, «Добро пожаловать в AO Bible», 4 строки-подсказки («Нажмите на слово — откроется его значение.»; «Зажмите стих на полсекунды — появятся действия: заметка, закладка, цвет, перевод рядом.»; «Поиск — по слову, ссылке (Ин 3:16) или номеру Стронга.»; «Планы чтения, аудио и проповеди — в нижнем меню и в «Ещё».»), приписка про бесплатность и кнопка «Начать». Flutter — **3 шага** с кнопками «Пропустить / Назад / Далее / Начать чтение», **ползунком размера шрифта (13…40) и образцом** на первом шаге, точками прогресса, кнопкой **«Открыть инструкцию»** на последнем (§2). Тексты шагов — §2.3.
3. Нет `prepareFirstRun`: запись `primaryModule`, `welcomePending`, `newsSeen` (см. `06b-library.md` §8.3); Swift хранит `welcomeSeen`, `flutterImported`, `lastBuild` — другие ключи.
4. **Нет `Hub.afterStart`-очереди** с `_showStartup`; в Swift `RootView.task` делает: копию данных перед обновлением (`UserData.snapshot`), перенос настроек Flutter, напоминания, `Starter.run`. Это нужное и полезное, но **не показывает** «Что нового» после обновления (§5).

### Б. Инструкция и тур
5. **Тура нет**: `HelpView` — список уроков с поиском и `HelpLesson` — нумерованный список шагов текстом. Нет затемнения, подсвеченной рамки, облачка с «Назад / Далее», условий `until`, действий `next` (§3.3), целей (§3.4). Для переноса нужен слой поверх `TabView`, якоря целей (через `anchorPreference`/`GeometryReader` и пользовательские идентификаторы), набор помощников (`openSheet`, `reset`, `selectVerse`, имитация нажатия) и 16 уроков из §3.5.
6. **Данные уроков** (`HelpData.swift`) скопированы из неиспользуемого `help_data.dart`: «Закладки, заметки, любимые» — **4** шага (телефонный и широкий варианты вместе), «Планы чтения» — **3** (оба варианта); во Flutter на телефоне **3** и **2**. Поэтому текст «Меню ⋮ → «Планы чтения»» и «Здесь все закладки… (широкая)» на iPhone лишние. Остальные уроки совпадают по числу шагов (4, 4, 5, 3, 3, 2, 6, 3, 4, 2, 2, 3, 2, 2) и текстам.

### В. «О приложении»
9. Swift — одна прокручиваемая форма: абзац (**другой текст**: «AO Bible — бесплатное некоммерческое приложение для чтения Библии: переводы, словари, толкования, планы чтения, аудио и проповеди. Во Flutter — главная страница + две отдельные страницы (§4.2), полная политика (§4.4), лицензии **всех** модулей каталога, сгруппированные по видам, с кликабельными лицензиями/источниками (`licenseUrl`), дополнительные строки правообладателей (`_extra`), абзацы про helloao и API.Bible, раздел «Фотографии», 15 записей «Программы и службы».

### Г. «Что нового»
12. ### Д. «Сообщить о проблеме»
15. Swift (`ReportView`): **промежуточный экран** с `TextEditor` («Что случилось?»), подсказкой «Откроется письмо с вашим описанием…» и кнопкой «Отправить письмо» → `mailto`. Flutter — сразу письмо с заготовкой «Что случилось и что вы делали перед этим:».

Если почтового приложения нет, Swift молчит (Flutter показывает адрес).
17. Совпадает: лимит 1800 знаков, разделитель `— — —`, адрес получателя, 40 модулей.

### Е. Язык интерфейса, книги, формы числа
18. **Выбор при первом запуске**: Swift — `interfaceLanguage = "ru"` по умолчанию (перенос из `flutter.lang` один раз), **язык телефона не учитывается**; Flutter берёт первый подходящий из `PlatformDispatcher.locales`.
19. Список 22 языков **совпадает по составу**, порядок другой (Swift по алфавиту кодов: ru, uk, be, bg, cs, de, en, es, …; Flutter — ru, uk, ro, en, es, pt, fr, de, it, pl, be, bg, sr, cs, ka, hy, ko, zh, ja, id, hi, sw); флаги — эмодзи (pt — 🇵🇹, а во Flutter Бразилия), без второй строки «название на языке интерфейса»; выбор — `Picker` в «Настройках» без отдельной страницы, без « · Language» в подписи.
20. **Словарь**: Swift — `Localizable.strings` по `lproj` (сгенерированы из тех же JSON; ключ — русская фраза), язык применяется через `.environment(\.locale)`. **Нет**: механизма `t()` с подстановкой `{имя}` и `@@`-подсказок (Swift использует `%lld`, `%@`), **форм числа** (`tn`, `pluralCategory`; нет `.stringsdict`), поэтому «{n} шагов», «день/дня/дней» и т. п. на языках с несколькими формами будут неверны **[проверить на устройстве]**.
21. **Названия книг на языке интерфейса**: Swift читает только русские `name/short` из `books.json`; английских названий (`_en`) для языков, кроме `ru, uk, be, bg, sr`, **нет** (`Books.swift` не знает `latinNames`).
22. Нет `langDisplayNames` / `monthDayTemplates` (даты и названия языков модулей — только по-русски).

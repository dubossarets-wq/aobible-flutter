## 0. Поправки к `SWIFT_SPEC.md` §11 и §16

1. §11 «статистика (сегодня / за неделю / всего глав / дней подряд…)»: во Flutter это не четыре числа в ряд. Есть **кольцо «N % Библии»**, **серия «N дней подряд»**, строка «Сегодня: N гл. · Глав Библии: N из 1189»
   и **7 столбиков**; число глав «за неделю» на экране **не показано** (только подпись для VoiceOver «За 7 дней: N гл.»). См. §6.
2. §11 «Все дни и настройки»: во Flutter **такой страницы нет**. Любой день плана выбирается лентой кружков 1…7 прямо на карточке плана, удаление — корзина на обложке с подтверждением в два нажатия (§4).
3. §11 «Читать»: во Flutter «Читать» **не открывает отдельный лист**: окно планов закрывается, а в панели чтения вместо читалки появляется страница «План на день» (§9). Листа «Читать весь день» нет.
4. §11 «К плану · N из M — кнопка в читалке»: это капсула **внизу экрана**, над мини-плеером аудио/нижним меню, а не в шапке читалки (§10).
5. §11 «Сохранить» в «Картинке со стихом»: на iPhone во Flutter «Сохранить» **открывает то же системное окно «Поделиться»** (прямая запись в «Pictures/AO Bible» работает только на Android, §12.7).
6. §11 «стих выбирается по дате, текст — основного перевода языка приложения»: точнее — перевод **первой панели**, затем основной (`primaryModule`), затем любые установленные; но только на языке интерфейса
   (если на языке интерфейса переводов нет совсем — любые). Если стиха нет ни в одном, берётся следующий стих списка (до 40 попыток), §3.
7. §16 п. 6–7: «К плану», страница дня с автоотметкой и расширенные напоминания в Swift **не сделаны** (подтверждаю; список — в конце файла).

## 1. Хранение и формат данных

Всё хранится в SharedPreferences (на iPhone — `UserDefaults` с префиксом `flutter.`), **каждый ключ — одна строка с JSON**. Ключи и формат **совпадают с веб-версией**
(`src/core/plans.js`, `planStore.js`, `readLog.js`, `reminders.js`) и входят в файл «Мои данные» (`03-bookmarks.md` §12). Повреждённый или отсутствующий JSON → пустое значение (приложение не падает).

### 1.1. Ключи

| Ключ prefs | Тип JSON | Содержимое |
|---|---|---|
| `plans` | список | активные планы (§1.2). **Новый — в начало.** Пишется целиком при любом изменении. |
| `readLog` | объект | `{"days": {"2026-10-15": ["Gen.1","John.3"], …}}` — дочитанные до конца главы по местным датам; внутри дня **без повторов**, в порядке чтения (§1.7). Прочие поля объекта при записи сохраняются. |
| `planReminder` | объект | `{"on": bool, "time": "08:00", "list": [{"id","time","every","until","days","alarm"?}]}` — напоминания (§5.2). |
| `customPlanMode` | строка в JSON | `"seq"` или `"par"` — режим «Своего плана» (по умолчанию `seq`). |
| `customPlanBooks` | список строк | выбранные «Свои книги» (id книг). |
| `customPlanParMode` | строка в JSON | `"perday"` («Глав в день») или `"period"` («За срок»); по умолчанию `perday`. |
| `customPlanParDays` | число | срок для «Параллельно → За срок», **7…730**, по умолчанию 90. |
| `customPlanStreams` | объект | `{"ot":1,"ps":2,"nt":1}` — включённые разделы → глав в день **1…10**; по умолчанию `{ot:1, nt:1, ps:1}`. |
| `widgetDay` | строка | служебная метка «виджет уже получил стихи сегодня» — только Android (§13). |
| `lastBuild`, `settings`, `panes` и др. | — | не этой области. |

Не сохраняются между запусками (только в памяти): выбранный раздел `_scope` («Что читать», по умолчанию **«Новый Завет»**) и число дней `_days` (по умолчанию **90**) последовательного плана; открытая строка каталога; выбранный день на карточке плана;
режим плана в панели (`planMode`) и кнопка возврата (`lastPlans`).

### 1.2. План (одна запись списка `plans`)

```json
{"uid":"mh3k2x9a","planId":"mcheyne","name":"План М'Чейна","readings":[["Gen.1","Matt.1","Ezra.1","Acts.1"], …],
 "calendar":true,"start":"2026-10-15","year":2026,
 "done":{"0":1760512345678},
 "parts":{"1":{"Gen.2":1760512345678,"Matt.2":1760512399999}},
 "history":{"2025":212}}
```

| Поле | Тип | Правило |
|---|---|---|
| `uid` | строка | `DateTime.now().millisecondsSinceEpoch` в системе по основанию 36, на момент «Начать». Используется для всех ссылок на план. |
| `planId` | строка | `id` из каталога (`mcheyne`, `bible-year`, `nt-90`, `ps-prov-31`, `gospels-30`) или `"custom"`. По нему подбирается обложка (§7) и помечается «идёт». |
| `name` | строка | у готового — `name` из файла плана; у своего — составленное (§8.6), **уже переведённое** на язык интерфейса в момент создания. |
| `readings` | `[[string]]` | по дню — список отрывков (§1.5). **Копия из файла плана**: после «Начать» интернет не нужен. Плохие записи (не список) отбрасываются. |
| `calendar` | bool | `true` только у календарного плана (М'Чейн). У готовых планов поле пишется (`true/false`), у своих — **отсутствует** (читается как `false`). |
| `start` | `"ГГГГ-ММ-ДД"` | **местная** дата нажатия «Начать». У календарного плана после смены года — `"{год}-01-01"`. |
| `year` | int | только у календарных: год, к которому относятся `done`/`parts` (§1.6, смена года). |
| `done` | `{"день": ms}` | **день закрыт**; ключ — индекс дня от 0, строкой; значение — время отметки (мс Unix). Число закрытых дней = `done.length`. |
| `parts` | `{"день": {"ключ отрывка": ms}}` | прочитанные отрывки дня (ключ — `ReadingUnit.key`, §1.5). До первой отметки поля нет; после — может быть пустой словарь дня. |
| `history` | `{"год": число}` | у календарных: сколько дней было закрыто в прошлые годы. **Нигде в интерфейсе не показывается.** |

При старте нового плана (`_add`) записывается: `{planId, name, readings, calendar}` (+ `uid`, `start = сегодня`, `done = {}`, у календарного `year = текущий год`). Остальные поля файла плана
(`description`, `source`, `license`, `versification`) в план **не попадают**. Неизвестные поля при чтении сохраняются (план — это `Map`).

### 1.4. Какой день сегодня; календарный план; пропущенные дни

- Дата — **по местному времени**: `localDate()` = `ГГГГ-ММ-ДД`. Разница дней — по календарю (`daysBetween`, округление часов/24, переход на летнее время не сбивает).
- **Обычный план:** `todayIndex = clamp(0, дней−1, daysBetween(start, сегодня))`. После конца плана «сегодня» остаётся **последним днём** (плана «вышел за пределы» нет).
- **Календарный план (`calendar: true`, М'Чейн):** день плана = **день года, 0-based**: `i = дней от 1 января до сегодня`. В **високосный** год при `i ≥ 59` делается `i −= 1`, то есть **29 февраля чтений нет — читается 28 февраля (день 58)**, а 1 марта — день 59 как в обычном году.
  Итог ограничен `min(364, i)`. Примеры: 1 января → 0; 28 февраля → 58; 1 марта (любой год) → 59; 29 февраля 2028 → 58; 31 декабря → 364 (и в високосный тоже).
  Поле `start` на выбор дня **не влияет**, оно нужно только для «пропущенных» и для года.
- `dayDone(p, d)` = в `done` есть ключ `d`.
- **Пропущенные дни (`behindDays`)** = дни `i` от `from` до `сегодня−1` включительно, где день не закрыт. `from` = `0` у обычного плана; у календарного — `min(сегодня, индекс дня года от start)`: то есть
  у календарного плана, начатого 15 октября, пропущенными считаются дни **с 15 октября**, а не с 1 января. Сегодняшний день пропущенным не считается.
- **Смена года у календарного плана (`applyNewYear`)** выполняется **при загрузке списка** (при запуске приложения, когда впервые читается `plans`), не в фоне при открытом приложении:
  для календарного плана `py = year ?? первые 4 цифры start ?? текущий год`. Если `py == текущий год` — план не меняется (если поля `year` нет, оно дописывается). Иначе: `history["{py}"] = done.length`, `year = текущий`,
  `start = "{текущий}-01-01"`, `done = {}`, `parts = {}` (история остаётся); список сразу сохраняется. Обычные планы год не затрагивает.

### 1.5. Отрывки (`readings`) и «единицы» (`ReadingUnit`)

Отрывок — строка в синодальной нумерации с точками:

| Строка | Смысл | Единицы (`ReadingUnit(book, chapter, from, to, key)`) |
|---|---|---|
| `Gen.1` | глава целиком | одна: `Gen,1,from=1,to=null`, `key="Gen.1"` |
| `Ps.119-120` | несколько глав | по одной на главу: `key="Ps.119"`, `key="Ps.120"`, `to=null` |
| `Ps.9.1-21` | стихи одной главы | одна: `Ps,9,from=1,to=21`, **`key` = вся строка** `"Ps.9.1-21"` |
| `Zech.13.1` | один стих | одна: `from=to=1`, `key="Zech.13.1"` |
| `Gen` | глава не указана | глава 1 |

Разбор: `p = split('.')`; книга `p[0]`; если есть непустой `p[2]` — это стихи (`a-b`, при отсутствии/нуле `b` берётся `a`); иначе `p[1]` — глава или диапазон глав `a-b` (пусто → 1).
`to == null` означает «до конца главы»; именно такие единицы (`_whole`) при автоотметке пишутся в историю чтения как дочитанные главы (§9.5).

- `dayUnits(p, день)` = единицы всех отрывков дня (пусто, если день вне диапазона).
- `unitDone(p, d, key)` = день закрыт (`done[d]`) **или** есть `parts[d][key]`.
- `readingDone(p, d, r)` = **все** единицы отрывка `r` отмечены.
- **Подпись отрывка `readingLabel`** (короткая): сокращённое название книги из справочника языка интерфейса **без конечной точки** + пробел + номер: `«Быт 1»`, `«Пс 9:1–21»` (дефис диапазона заменяется на «–»), `«Пс 119–120»`.
- **Полная подпись** (`_fullLabel` в окне планов; `planReadingLabel(full: true)` на странице дня): полное название книги (на странице дня — из списка книг **перевода панели**, иначе из справочника): `«От Матфея 5»`, `«Псалтирь 9:1–21»`.
- `readingTarget(r)` = первая единица: (`книга`, `глава`, `from`) — куда перейти.

### 1.6. Как отмечаются отрывки

**`markUnits(uid, день, [ключи])`** (общая функция; используется автоотметкой страницы дня, кнопкой «Отметить прочитанным» и засчётом при обычном чтении):

1. Нужный план по `uid`. Если день уже закрыт (`done[d]`) — **ничего не делать**.
2. Из переданных ключей оставить те, которых ещё нет в `parts[d]`. Если пусто — ничего не делать.
3. Всем им поставить `now` (мс); `parts[d] = {старые + новые}`.
4. Если теперь **все единицы дня** есть в `parts[d]` — `done[d] = now`, и результат «день завершён этим» = `true`.
5. Список сохраняется (`plans`), после чего вызывающий пересобирает напоминания.

**Переключатели на карточке плана** (§4) — свои правила, они **снимают** отметки:

- `Отметить день` (`_toggle`): день закрыт → удалить `done[d]` **и `parts[d]`**; не закрыт → `done[d] = now` (`parts` не трогаются).
- `Отметить отрывок` (`_togglePart(день, i)`): «текущие отметки» = если день закрыт — **все ключи дня** с временем закрытия, иначе `parts[d]`. Если отрывок `i` прочитан — убрать его ключи, иначе поставить `now`.
  Затем: **все ключи дня отмечены** → `done[d] ??= now` (если ещё не было), иначе **`done[d]` удаляется**. `parts[d]` записывается всегда (может стать пустым). То есть снятие отметки у отрывка в закрытом дне **открывает день**, остальные отрывки остаются отмеченными.

**Засчёт главы при обычном чтении (`creditChapterIn`)** — для каждого плана по порядку списка:

- кандидаты-дни: `[сегодня] + пропущенные` (по возрастанию);
- первый незакрытый день, в котором есть **не отмеченная** единица этой книги и главы, берётся для отметки: `markUnits(план, день, [ключи])`. Подходят и целые главы (`Gen.1`), и **диапазоны стихов той же главы** (`Ps.9.1-21`): дочитанная целиком глава засчитывает и их (сравниваются книга и номер главы, а не ключ);
- **на один план засчитывается не больше одного дня**; найденные планы собираются в `credited` (по названию), завершившие день — в `finished`.

### 1.7. Учёт прочитанного (`readLog`) и статистика

- `logChapter(книга, глава)`: ключ `Книга.Глава`; если сегодняшняя дата уже содержит этот ключ — `false`, иначе дописывается в конец списка дня и `readLog` сохраняется.
- **Сколько секунд нужно (`minSeconds(n)`)** на отрывке из `n` стихов = `max(8, min(120, n × 2,5))`: n=1…3 → 8 с; 10 → 25 с; 31 → 77,5 с; 48 и больше → 120 с.
- `readStats(log, now)`:
  - `days7` — 7 пар (дата, число глав за день) от «6 дней назад» до сегодня;
  - `today` — число записей за сегодня; `week` — число записей за последние 7 дней (с повторами одной главы в разные дни);
  - `total` — число **разных** глав за всё время (множество по всем дням);
  - `streak` — серия подряд идущих дней с хотя бы одной главой; **начинается с сегодня, если сегодня есть чтение, иначе со вчера** (пустое сегодня серию не обрывает);
  - `recent` — последние 30 записей, **новые первыми** (дни от нового к старому; внутри дня — от последней прочитанной).
- Расчёт статистики на экране делается **один раз при открытии окна** (не обновляется, пока окно открыто).

### 1.8. Стих дня (данные)

Список из **366 ссылок** `Книга.Глава.Стих` в синодальной нумерации (`verse_list.dart` = `swift/AOBible/Resources/verses_of_day.txt`, первый `Gen.1.1`, последний `Rev.21.5`).
`dayOfYear(дата)` = число дней от 1 января до даты (0-based, 365 у 31 декабря високосного); **индекс = (dayOfYear × 151 + (год mod 366) × 59) mod 366**. 151 взаимно просто с 366 — за год все стихи без повторов.
Проверочные значения: 2026-01-01 → индекс 218 `Mark.10.27`; 2026-11-08 → 331 `2Tim.1.7`; 2026-12-31 → 282 `1Cor.13.7`; 2028-02-29 → 95 `Ps.106.1`.

## 3. «Стих дня» (`VerseOfDayCard`)

### 3.1. Что видно

Карточка во всю ширину на фоне фото, с затемнением. Сверху вниз:

1. подпись **«Стих дня»**;
2. **текст стиха** (шрифт читалки из настроек, полужирность 500, межстрочный 1,38, **без кавычек**; размер = `clamp(0,056 × ширина экрана, 20,8…28)`), по центру свободного места карточки;
3. короткая белая черта и **ссылка с полным названием книги** (`selectionLabel([ref], full: true)`): «От Иоанна 3:16»;
4. внизу ряд кнопок: **«Читать»** (главная, на долю ширины), **«Картинка»**, круглая кнопка-значок **«Поделиться»** (подсказка «Поделиться»).

Минимальная высота карточки — `min(320, 42 % высоты экрана)`. Автор и лицензия фото на карточке **не показаны** (они в «О приложении → Лицензии»).
Если подходящего стиха нет ни в одном переводе, **карточки нет вовсе** (и сообщения нет). Фон: тёмно-синий градиент, поверх — фото дня, затемнение сильнее для светлых фото (`tone: light` — 0,40…0,78 вместо 0,28…0,70 сверху вниз).

### 3.2. Какой стих и какой перевод

1. Ключ по дате (§1.8).
2. Список переводов-кандидатов `verseModules(перевод первой панели, primaryModule)`: сначала перевод панели 0, затем основной, затем все остальные установленные Библии (без повторов, только `type == bible`); оставляются **те, чей язык = язык интерфейса**;
   если таких нет совсем — берутся все.
3. Для `k = 0…39`: ссылка `список[(индекс + k) mod 366]`; для каждого кандидата читается `SELECT text FROM verses WHERE book,chapter,verse`, текст очищается от разметки (`plainText`), обрезается; **первый непустой** побеждает.
   Если ничего не нашлось — карточки нет.
4. Фото: `images/verse-bg/index.json` → `images[dayOfYear mod число_фото]`; нет списка/сети — остаётся градиентный фон.

| Элемент | Что происходит |

| «Картинка» | поверх окна планов открывается «Картинка со стихом» (§12) для одного стиха и **того перевода, из которого взят текст**. |
| «Поделиться» | системное окно «Поделиться» с **текстом** `"текст стиха" - Ин. 3:16` (кавычки прямые `"`; подпись — **сокращённое** название книги, пробелы в тексте сжаты). |

## 4. Карточка активного плана (`_ActivePlan`)

### 4.1. Расположение (сверху вниз, один блок на план)

1. **Обложка** (высота 104): фото плана (§7, таблица обложек; свой план — фото `08`; нет фото — однотонный запасной фон) с затемнением к низу. Слева внизу: **название плана** (до 2 строк) и под ним
   **«{done} из {total} дн. · {pct}%»** (`pct = round(done / total × 100)`; `done` — число закрытых дней). В правом верхнем углу — **корзина** «Удалить план» (подсказка).
2. **Полоса прогресса** плана на всю ширину (4 pt), доля = `done/total`.
3. **Лента дней**: слева стрелка «‹» («Предыдущий день»), посередине **до 7 кружков с номерами дней**, справа «›» («Следующий день»). Окно кружков: первый номер = `max(0, min(день − 3, всего − 7))`, то есть выбранный день стоит
   по возможности **четвёртым** и лента не выходит за 1…всего; если дней меньше 7 — столько, сколько есть. Стрелки неактивны на крайних днях.
   Вид кружка: **закрытый** — приглушён; **пропущенный** (в `behindDays`) — оранжевый; **сегодняшний** — в кольце акцента; **выбранный** — тёмный. Подпись для VoiceOver: «День N», затем «, сегодня» и «, прочитано».
4. **Строка выбранного дня**: слева **«День N»**, плюс « · сегодня» (если это сегодняшний день) или « · пропущен» (оранжевым, если день в `behindDays`); справа — **«прочитано»** (зелёным, если день закрыт) либо **«{done} из {total} отрывков»**.
5. **Строка пропущенных** (показывается, если есть пропущенные и выбранный день **не** первый пропущенный): оранжевая точка, **«Пропущено дней: N»** и справа **«Догнать ›»** (минимальная высота 36).
6. **Список отрывков дня** (белый/«вложенный» список): у каждой строки слева **кружок-отметка** (22 pt в зоне 48 × 46), справа от него **полное название отрывка** («От Матфея 5», «Псалтирь 9:1–21») и «›».
   Прочитанный отрывок — зелёный кружок с галочкой, название приглушено. **Не больше 5 строк**; если отрывков больше 5, внизу строка **«Ещё N»** (N = лишних) со стрелкой вниз; по нажатию показываются все, строка меняется на **«Свернуть»**.
   Раскрыт может быть только один день (запоминается день; на другом дне список снова свёрнут).
7. **Две кнопки в ряд**: широкая **«Читать»**/**«Продолжить чтение»**/**«Перечитать»** (значок книги) и **«Отметить»**/**«Прочитано»** (значок галочки; высота по содержимому).

Если в плане **нет ни одного дня** (повреждённая запись), вместо карточки — одна строка: название и корзина «Удалить план» (окно не падает).

### 4.2. Какой день показывается первым и состояние выбора

При создании карточки `_day = сегодня`; пока этот день **закрыт** и он не последний — `_day += 1`. Итог: если сегодняшнее прочитано (в том числе заранее прочитаны следующие), карточка открывается на **первом непрочитанном дне после сегодняшнего**.
Выбор дня на ленте (кружок, стрелки, «Догнать») меняет только вид (не записывается). «Догнать» → первый пропущенный день. Карточка помнит выбранный день, пока окно открыто (ключ карточки — `uid`).

### 4.3. Что происходит при действиях

| Действие | Результат |
|---|---|
| Нажатие на кружок отрывка | `_togglePart` (§1.6): поставить/снять отметку отрывка; все отмечены → день закрывается сам; снял у закрытого дня → день открывается. Затем `plans` сохраняются и **пересобирается расписание напоминаний**. Уведомления нет. |
| Нажатие на название отрывка/«›» | «Читать» с этим отрывком: `onRead(план, день, i)` (ниже). |
| «Читать» / «Продолжить чтение» / «Перечитать» | подпись: **день закрыт** → «Перечитать»; иначе **есть хоть один прочитанный отрывок** → «Продолжить чтение»; иначе «Читать». Действие: `onRead(план, день, at)`, где `at` = **0**, если день закрыт или все отрывки прочитаны, иначе **индекс первого непрочитанного**. |
| `onRead` | если день/отрывок вне плана — ничего. Иначе: **окно планов закрывается** (`Navigator.pop`) и в панели окна открывается страница «План на день» (`openPlanDay(панель, uid, день, at)`, §9) — с прокруткой к отрывку `at`. |
| «Отметить» | `_toggle(день)` (§1.6): день не закрыт → закрыть целиком (`done[d] = now`); закрыт → открыть и **сбросить отметки отрывков**. Подпись кнопки при закрытом дне — **«Прочитано»** (главный цвет), подсказка «Снять отметку дня»; при открытом — «Отметить», подсказка «Отметить весь день прочитанным». Затем пересборка напоминаний. |
| Корзина | **двухшаговое подтверждение**: первое нажатие превращает значок в красную кнопку **«Удалить»**, через 3 с (если не нажали) возвращается обратно; второе нажатие — план удаляется (`remove(uid)`), расписание пересобирается. Отмены нет, сообщения нет, **подтверждающего текста нет**. |
| Кружок дня, «‹»/«›», «Догнать» | только смена выбранного дня. |

### 4.4. Новый план — как он появляется

После «Начать» (§7, §8) новый план — **первым в списке**, и окно **прокручивается**, чтобы его карточка встала вверху (если карточка ещё не построена — сначала к началу окна, затем к карточке; 350 мс, плавно).
Окно планов при этом **не закрывается**.

## 5. Напоминания

### 5.1. Карточка «Напоминать о чтении» (`_ReminderCard`) — видна только при наличии планов

Сверху вниз:

1. Строка с подписью **«Напоминать о чтении»**, рядом значок «!» (пояснение по нажатию) и **переключатель** справа. Текст пояснения (одним облачком, два абзаца):
   «Уведомление с отрывками на сегодня — сколько угодно напоминаний, в любое время или промежутком» и «Не приходят уведомления? На Xiaomi, Huawei и других телефонах разрешите приложению автозапуск и работу в фоне без ограничений.» (второй абзац относится к Android).
2. Если переключатель **включён** — раскрывается список; иначе его нет. (Android: при выключенном «Будильники и напоминания» сверху ещё плашка «Чтобы напоминания приходили вовремя, разрешите приложению «Будильники и напоминания».» с кнопкой «Разрешить»; **на iPhone её нет**.)
3. **Карточка каждого напоминания** (минимум одна; по порядку списка):
   - большое **время** (32 pt, `ЧЧ:ММ`); для **промежутка** (`every > 0`) — время «с», тире «–» и время «до»;
   - таблетка **«Напоминание»** (значок колокольчика) ⇄ **«Будильник»** (значок будильника) — нажатие переключает (`alarm`); подсказки: «Напоминание: тихое уведомление» / «Будильник: звонит, пока не выключите»;
   - справа **«×»** («Удалить напоминание») — **только если напоминаний больше одного** (последнее удалить нельзя; чтобы отключить — выключатель);
   - нажатие на время открывает под ним **колёсики часов и минут** (24 и 60 значений, по кругу: после 23 снова 00; выбранное — в полосе посередине); одновременно открыто **одно** колёсико на всё окно (идентификатор «id:time»/«id:until»).
     Новое время сохраняется, когда колёсико **остановилось 450 мс**, либо при закрытии колёсика (даже если не дождались);
   - строка **«Повтор»** с меню: **«Один раз»** (`every=0`), **«Каждые 30 мин»**, **«Каждый час»**, **«Каждые 2 ч»**, **«Каждые 3 ч»**, **«Каждые 4 ч»**, **«Каждые 6 ч»** (`0, 30, 60, 120, 180, 240, 360`); текущее значение показано справа со стрелкой;
   - **дни недели** — 7 таблеток «Пн Вт Ср Чт Пт Сб Вс» (на языке интерфейса; таблица `weekdayShort`) в ряд: **ничего не выбрано = каждый день** (все таблетки светлые); нажатие на включённую выключает её (если это последняя — **игнорируется**),
     на выключенную — включает; когда выбраны все 7, в данные пишется **пустой список**.
4. Под списком две ссылки: **«Добавить напоминание»** (значок «+») и **«Добавить будильник»** (значок будильника с «+»). Новое время = **время последнего напоминания (для промежутка — его «до») + 1 час**, минуты те же (часы ограничены 23); у нового `every = 0`, `until = 20:00`, `days = []`, `alarm` — по ссылке.
   (Если списка нет совсем, стартовое время 07:00; на практике список всегда есть.)

### 5.2. Действия и сообщения

| Действие | Результат |
|---|---|
| Переключатель → **вкл** | сначала запрос разрешения на уведомления (iOS: alert, badge, sound). Нет разрешения → переключатель остаётся **выключенным**, сообщение **«Уведомления запрещены — разрешите их в настройках телефона»**. Разрешили → `on = true` сохраняется, расписание пересобирается, сообщение: **«Напомню в {time}»** (если единственное напоминание — «один раз»; `time` — его время) иначе **«Напоминания включены»**. |
| Переключатель → **выкл** | `on = false`, расписание очищается. Сообщения нет. |
| Любое изменение времени/повтора/дней/типа/добавление/удаление | сохраняется `planReminder`, расписание пересобирается. При включённом `on` разрешение запрашивается снова (обычно оно уже выдано); если его отозвали в настройках телефона, **изменение не сохраняется** и показывается то же сообщение «Уведомления запрещены — разрешите их в настройках телефона». Иначе сообщения нет. |
| «Напоминать о чтении» из сообщения после «Начать» | см. §7.3. |

### 5.3. Формат `planReminder`

```json
{"on":true,"time":"08:00","list":[
  {"id":"r1","time":"08:00","every":0,"until":"20:00","days":[]},
  {"id":"kq2a0z","time":"09:00","every":120,"until":"19:00","days":[1,2,3,4,5],"alarm":true}]}
```

- `time` верхнего уровня = время **первого** напоминания (для прежних версий). Прежний формат `{on, time}` без `list` читается как одно напоминание `r1` с этим временем.
- Элемент: `id` — строка (для новых — `microsecondsSinceEpoch` в системе по основанию 36; по умолчанию `r1`), `time` и `until` — `"ЧЧ:ММ"`, `every` — **минуты**, `0` = один раз; `days` — дни недели **1…7 (пн…вс, `DateTime.weekday`)**, пусто = каждый день; `alarm` пишется **только если `true`**.
- По умолчанию (`getReminder()` без данных): `on = false`, список из одного элемента `{id:"r1", time:"08:00"}`.
- **Моменты одного напоминания (`times`)**: `every ≤ 0` → одно время `time`; иначе от `time` до `until` **включительно** с шагом `every` минут, но **не больше 48 моментов**; если `until ≤ time` — только `time`.

### 5.4. Расписание уведомлений (`reminderSchedule`) — алгоритм

Вызывается (пересобирается) при: запуске приложения; «Начать» план; изменении/отметке/удалении плана; автоотметке на странице дня; засчёте главы при обычном чтении; любом изменении напоминаний. Только на телефоне (`Android`/`iOS`).

1. Все прежние уведомления приложения с id `7000…7199` отменяются. Если `on = false` или планов нет — **больше ничего**.
2. На **14 дней вперёд** (`k = 0…13`, от сегодняшней даты), пока всего не набралось **200** уведомлений (`_max`):
   - для дня `день`: для каждого напоминания, у которого `days` пусто или содержит `день.weekday`, берутся все `times`; по каждой минуте дня запоминается `alarm = ИЛИ(alarm напоминаний на этот момент)` — **если напоминание и будильник совпали по времени, звенит будильник**;
   - моменты сортируются; оставляются те, что **не раньше, чем через 60 секунд от «сейчас»**; нет моментов — день пропускается;
   - **текст дня**: для каждого плана `d = planDayOn(план, день)` — индекс дня плана на эту дату (календарный: `calendarIndex(день)`; обычный: `дней от start`; вне `0 ≤ d < всего` → `null`); пропускаются `null` и **закрытые** дни; строка
     **`{название плана}: {подпись1}, {подпись2}, …`** (короткие подписи отрывков через запятую, §1.5); строки разных планов — через `\n`. Нет ни одной строки — день **пропускается** (напоминаний нет);
   - на каждый момент создаётся уведомление: id = `7000 + порядковый номер`, время, тот же текст, признак будильника.
3. Состояние «закрыт ли день» берётся **на момент пересборки**; поэтому после чтения пересборка нужна (она вызывается).

### 5.5. Вид уведомлений

- Заголовок всегда **«Чтение на сегодня»**; текст — строки из п. 5.4 (`«План М'Чейна: Быт 1, Мф 1, Езд 1, Деян 1»`); полный текст раскрывается (Android — BigText).
- Нажатие на уведомление (`payload = "plans"`) **открывает окно «Планы чтения»** в панели 0; работает и при холодном запуске приложения уведомлением.
- **Обычное** — обычное уведомление (в подсказке карточки названо «тихим») с настройками по умолчанию; Android: канал «Напоминание о чтении».
- **Будильник**: Android — отдельный канал «Будильник для чтения», звук будильника по громкости будильника, **повторяется, пока не выключат** (флаг `FLAG_INSISTENT`), кнопка в уведомлении **«Выключить»**. **iPhone:** звук один раз (повторять iOS не даёт), но уровень прерывания **`timeSensitive`** — приходит и в режиме «Фокус»;
  кнопки «Выключить» нет.
- **Ограничение платформы (не из кода Flutter):** iOS хранит не больше **64** ожидающих локальных уведомлений (остальные отбрасывает); Flutter-код берёт до 200 (число выбрано под Android, лимит 500). Для Swift — резать расписание до 64 ближайших **[уточнить решение]**.

## 6. «Сколько прочитано» (`_ReadHero`)

Одна карточка, данные — §1.7 (считаются при открытии окна).

1. **Кольцо** слева: доля = `total / 1189` (число глав Библии 1189), внутри крупно **«{N}%»** (если процент больше 0, но меньше 1 — `<1%`, иначе целое округлением) и ниже мелко **«Библии»**.
2. Справа от кольца, сверху: значок пламени (оранжевый при серии > 0, серый при 0), **число серии** и подпись формой числа **«день подряд»/«дня подряд»/«дней подряд»** («0 дней подряд» при нуле).
3. Ниже мелким серым: **«Сегодня: {n} гл. · Глав Библии: {total} из 1189»** и значок «!» с пояснением: «Глава засчитывается, когда дочитана до конца — по плану или просто так. Столбики — главы за каждый день, с повторами; «Глав Библии» — сколько разных глав прочитано хоть раз.»

5. Если `recent` непустой — ниже **плашки последних глав**: по умолчанию **3** («Мф 5» + мелко «15 окт.» — подпись главы и дата чтения), и плашка **«ещё…»**, если записей больше 3; её нажатие показывает **до 30** и скрывается.
   Нажатие на плашку: окно закрывается до читалки, панель окна переходит на **главу, стих 1**.

Пустое состояние (нет данных): кольцо «0%», «0 дней подряд», «Сегодня: 0 гл. · Глав Библии: 0 из 1189», 7 серых полосок, плашек нет. Отдельного текста нет.

## 7. Готовые планы («Ещё планы» / «Выберите план»)

### 7.1. Список

Одна карточка со строками (по порядку `index.json`), разделённых линиями. **Строка:** слева миниатюра 64 × 64 (фото плана, затемнение и значок раздела белым), посередине — **название** (`t(name)`), под ним **`short`** (`t(short)`, если есть), ниже **«{N} дн.»** и,
если такой план уже идёт (`plans.any(planId == id)`), плашка **«идёт»**; справа стрелка вниз (поворачивается). Нажатие на строку **раскрывает её на месте** (одновременно раскрыта только одна; повторное нажатие сворачивает).

**Раскрытая часть:** описание (`t(description)`, если есть), строка **«до {дата}»** — дата окончания, если начать **сегодня** (`planEndText(дней)`: `сегодня + дней − 1`, формат «24 января»; если год другой — с годом),
и кнопка **«Начать»** (значок «+») на всю ширину. Пока идёт загрузка плана — вместо неё неактивная кнопка «Начать» с вращающимся индикатором; на это время все кнопки «Начать» всех строк неактивны.
Для календарного плана подпись «до {дата}» выводится так же (как для обычного) — это упрощение Flutter **[уточнить: дата для М'Чейна не имеет смысла, план идёт по календарю]**.

Обложки и значки разделов (`_looks`):

| `planId` | Фото (`images/verse-bg/NN.jpg`) | Значок раздела |
|---|---|---|
| `mcheyne` | `10` | вся Библия |
| `bible-year` | `06` | вся Библия |
| `nt-90` | `01` | Новый Завет |
| `ps-prov-31` | `07` | Псалтирь |
| `gospels-30` | `02` | Евангелия |
| любой другой (`custom`) | `08` | «искры» (на карточке плана значка нет) |

Значки разделов («Что читать»/каталог): вся Библия — открытая книга, Ветхий Завет — свиток, Новый Завет — книга с крестом, Евангелия — латинский крест, Псалтирь — нота, «Свои книги» — список с галочками.

### 7.2. «Начать» (`_start`)

1. Строка помечается занятой. Загружается `plans/<file>.json`. Ошибка сети → сообщение **«План не загрузился»**; пустой `readings` → тоже **«План не загрузился»**.
2. Создаётся план `{planId: файл.id, name: файл.name, readings, calendar: файл.calendar == true}` и добавляется (§1.2, §4.4).
3. **Повторный запуск того же плана разрешён**: строка «идёт» «Начать» не блокирует — можно завести второй такой же план. Проверки на дубликаты **нет**.

### 7.3. Сообщение после «Начать» (`_add`)

- Всегда пересобирается расписание напоминаний.
- Если на устройстве напоминания поддерживаются и **выключены** (`on = false`): внизу **сообщение с кнопкой** (≈ 5 с): **«План «{name}» начат — нажмите «Читать»»**, кнопка **«Напоминать о чтении»**.
  Кнопка → `setReminder(on: true)` (запрос разрешения); успех → сообщение «Напомню в {time}» (`time` — первое напоминание), отказ → «Уведомления запрещены — разрешите их в настройках телефона».
- Иначе (напоминания уже включены) — то же сообщение **без кнопки**: «План «{name}» начат — нажмите «Читать»» (≈ 4 с).

## 8. «Свой план» (`_customPlan`)

### 8.1. Расположение

Карточка (внизу окна): значок «календарь с плюсом» в плитке, заголовок **«Свой план»**, подзаголовок зависит от режима:

Ниже сегментный переключатель **«Последовательно | Параллельно»** (режим запоминается в `customPlanMode`). Затем содержимое режима (§8.2/§8.3), внизу кнопка **«Начать»** (значок «▶», на всю ширину).

Кнопка: подпись **«Выберите книги»** вместо «Начать», если режим «Параллельно» без «За срок» и не получилось ни одного дня (`_parDays == 0`); неактивна (серая), если идёт создание, либо выбраны «Свои книги», а книг нет (`needOwn`), либо `_parDays == 0` в «Параллельно → Глав в день».
Во время создания — кнопка «Начать» с вращающимся индикатором (создание выполняется с задержкой 30 мс, чтобы индикатор успел отрисоваться).

### 8.2. «Последовательно»

1. Подпись **«Что читать»** и плитки (6): **«Вся Библия»** (на всю ширину), затем по две в ряд **«Ветхий Завет»**, **«Новый Завет»**, **«Евангелия»**, **«Псалтирь»**, и **«Свои книги»** (на всю ширину). Выбранная плитка выделена; по умолчанию **«Новый Завет»**.
   Состав: Вся Библия = все книги, кроме `testament == 'AP'` и **неканонических (`dc`)**; Ветхий Завет — `OT` без неканонических; Новый Завет — все `NT`; Евангелия — `Matt, Mark, Luke, John`; Псалтирь — `Ps`; Свои книги — выбор (§8.4).
2. При «Свои книги» — раскрывается **сетка книг** (§8.4).
3. Блок **«За сколько дней»** (§8.5).

### 8.3. «Параллельно»

1. Сегмент **«Глав в день | За срок»** (запоминается в `customPlanParMode`).
2. Подпись: **«Разделы и глав в день»** (режим «Глав в день») или **«Разделы»** («За срок»).
3. **6 строк-разделов** в библейском порядке: **«Ветхий Завет»**, **«Псалтирь»**, **«Притчи»**, **«Евангелия»**, **«Новый Завет»**, **«Свои книги»**. В каждой: галочка-флажок и название; для включённого раздела (в режиме «Глав в день») справа
   **«− {N} гл. в день +»**: `N` от **1 до 10**; кнопка «−» неактивна при 1, «+» — при 10; включение раздела ставит `N = 1`. Состояние пишется в `customPlanStreams` при каждом нажатии (`{ключ: N}`).
   Ключи: `ot`, `ps`, `prov`, `gospels`, `nt`, `own`; короткие названия для имени плана: **«ВЗ», «Псалтирь», «Притчи», «Евангелия», «НЗ», «Свои книги»**. ВЗ и НЗ — «широкие» (из них исключаются книги включённых узких разделов).
4. Если включены «Свои книги» — раскрывается **сетка книг** (§8.4).
5. Режим **«За срок»**: ниже блок **«За сколько дней»** (§8.5), срок хранится отдельно (`customPlanParDays`, 7…730). Режим **«Глав в день»**: строка **«Первый день: {Быт. 1–2 · Пс. 1 · Мф. 1}»** (полужирным; пересчитывается при каждом изменении; пусто — строки нет) и пояснение:
   **«Псалтирь и Притчи читаются по кругу, остальные разделы — один раз. Чтобы все разделы закончились в один день, выберите «За срок».»**

**Книги разделов без повторов (`streamList`):** из ВЗ/НЗ исключаются книги включённых узких разделов (Псалтирь, Притчи, Евангелия, Свои книги); в «Своих книгах» остаются только те, которых нет в Псалтири/Притчах/Евангелиях. Порядок разделов в дне —
по **первой книге** в Библии (устойчивая сортировка): ВЗ, Псалтирь, Притчи, Евангелия, НЗ; «свои» — по месту их первой книги. Подпись «кроме: Псалтирь, Притчи» (`streamExcluded`) в коде есть, но **нигде не показывается**.

**Первый день (`firstDayText`)**: для каждого раздела первые `N` глав: одна → «Быт. 1»; несколько в одной книге → «Быт. 1–2»; в разных → «Быт. 50 – Исх. 1»; разделы через « · ». Названия — сокращённые **с точкой**.

### 8.4. Сетка «Свои книги» (`_BookPicker`)

Два заголовка — **«Ветхий Завет»**, **«Новый Завет»**, под каждым сетка плашек с **сокращённым названием без точки** (от 54 pt шириной, промежуток 6, нажатие — выбрать/снять; подсказка — полное название). Показываются только книги, **которые есть в Библии «плана»**
(модуль `rst-plus`, иначе первый установленный; если модуля нет — все): неканонические — только если они есть в этом модуле. Внизу, если выбрано что-то: **«Выбрано книг: {n}»**. Выбор пишется в `customPlanBooks` сразу (порядок — библейский).

### 8.5. Блок «За сколько дней»

1. Подпись **«За сколько дней»**.
2. **Капсула**: кнопка «−» («Уменьшить»), по центру **крупное число** (его можно **вписать** клавиатурой; под ним подпись «день/дня/дней») и кнопка «+» («Увеличить»). «−» и «+» меняют на 1; все значения ограничиваются **7…730**. Вписанное
   число принимается при вводе (пустое/нецифровое → 90), «нормализуется» (7…730) при «Готово». Внутри `_days` может быть вне диапазона, но используется всегда `clamp(7, 730)`.
3. **Строка нагрузки** по центру: **«≈ {per} гл. в день · до {дата}»**, где `d = min(дней, число глав)` (глав меньше, чем дней — дней столько, сколько глав), `per = round(глав / d)` (минимум 1), дата = сегодня + `d − 1`. Если читать придётся больше часа в день
   (`round(стихов / d × 8 / 60) > 60` минут, ~8 секунд на стих) — строка красным. Нет глав (книг не выбрано / нет модуля) — строки нет. В «Параллельно → Глав в день» этого блока нет.
4. Две строки **быстрых сроков** по три плашки поровну: **«Неделя»** (7), **«2 недели»** (14), **«Месяц»** (30); **«3 месяца»** (90), **«Полгода»** (180), **«Год»** (365). Плашка, равная текущему сроку, выделена.

### 8.6. «Начать» — как составляется план

Книги глав берутся из модуля `rst-plus` (иначе первый установленный) запросом `SELECT chapter, COUNT(*) FROM verses WHERE book = ? GROUP BY chapter ORDER BY chapter`; результат запоминается на сеанс (`ключ = модуль|версия каталога|книга`).

**Последовательно** (`makeCustomPlan = splitChapters`): `total` = сумма стихов всех глав; `per = total / дней`; глава с `n` стихами идёт в день `min(дней − 1, floor((накоплено + n/2) / per))`; пустые дни **выбрасываются**
(глав меньше, чем дней → дней столько, сколько глав). Нет книг → **«Выберите книги»**; план пуст → **«Не удалось составить план»**.
Имя: **`{раздел} за {n} дн.`**, `n` = фактическое число дней, `раздел` — название раздела (переведённое) или для «Своих книг» — список (`_ownLabel`: до двух названий через «, » или **«{книги} и ещё {n}»**, полные названия).

**Параллельно**, «Глав в день» (`makeParallelPlan` без `period`): для каждого раздела `x` с `perDay` и главами `ch`; длина плана = **по самому длинному из «читаемых один раз»** (все, кроме `ps`, `prov`): `ceil(глав / perDay)`; если выбраны только Псалтирь/Притчи — по ним; потолок **3650**.
День `d`: для каждого раздела главы с индексами `d × N … d × N + N − 1`; у «по кругу» (`ps`, `prov`) индекс берётся `mod` длины (читаются снова с начала), у остальных закончившийся раздел **просто пропадает** из дней. Дубликаты ссылок внутри дня убираются (множество).
Имя: **`{ВЗ + Псалтирь + НЗ} параллельно`** (короткие названия через « + », «Свои книги» → список). Нет дней → **«Выберите книги»**.

**Параллельно**, «За срок» (`period = 7…730`): каждый раздел делится на `period` дней **поровну по числу стихов** (`splitChaptersRaw`); день — объединение кусков; дни, где пусто у всех разделов, выбрасываются; все разделы кончаются в последний день.
Имя: **`{названия через « + »} за {n} дн.`**, `n` = число полученных дней.

Все свои планы получают `planId: "custom"`, **без** `calendar`. `start` = сегодня.

## 9. Страница «План на день» (`PlanView`, `PlanHost`)

### 9.1. Где живёт

Это **не отдельное окно**, а режим панели чтения. Когда у панели в `planMode` задано `{uid, day}`, главный экран рисует **вместо читалки** страницу плана; верхняя шапка панели, нижняя вкладочная панель и панель выделения стихов остаются.
Режим у каждой панели свой; в памяти (при перезапуске приложения панель вернётся в обычное чтение). Ключ страницы = `uid | день | перевод панели | номер открытия`: смена перевода панели **перестраивает страницу тем же днём другим переводом** (из плана это не выводит);
новое открытие (`openPlanDay`/`returnToPlan`) тоже строит заново и прокручивает к месту.

Любой другой переход в панели (поиск, «Перейти», закладка, история, ссылка) **выводит из режима плана** и включает кнопку «К плану» (§10).

### 9.2. Расположение (сверху вниз)

1. **Закреплённая строка плана** (высота 42, под шапкой панели, поверх ленты): слева **«День N · {сделано}/{всего}»** (число прочитанных отрывков дня / число отрывков), затем **горизонтально прокручиваемый ряд вкладок-отрывков**
   (краям ряда — плавное затухание) и справа **«×»** (подсказка «Выйти из плана»). Вкладка = подпись отрывка (`readingLabel`, «Быт 1»), у прочитанного — галочка слева и приглушённый текст; **текущий** отрывок (тот, что сейчас вверху экрана) — полужирный с подчёркиванием.
   Нажатие на вкладку прокручивает ленту к началу этого отрывка (анимация 350 мс, если в настройках включены анимации, иначе прыжком); вкладка текущего отрывка при прокрутке сама **центруется** в ряду. VoiceOver: «Отрывки плана на день».
2. **Лента** (общая для всего дня; текст и ширина как в читалке — `textWidth × размер шрифта`, снизу запас под панель):
   - **шапка дня**: название плана, «День {n} из {total} · {k отрывок/отрывка/отрывков}» и подсказка **«Читайте подряд — отрывок отметится сам.»**;
   - по каждому отрывку: **заголовок** — полное название («От Матфея 5», «Псалтирь 9:1–21») крупно; если отрывок прочитан, рядом «✓ Прочитано» (зелёным); у отрывков, кроме первого, над заголовком пунктирная черта;
   - если отрывок — несколько глав (`Ps.119-120`), перед каждой главой подзаголовок **«Псалом {n}»** (для книги `Ps`) или **«Глава {n}»**;
   - **стихи** — те же строки, что в читалке (`VerseView`): слова, выделение, закладки, заметки, любимые, «Часть стиха», комментарии работают как обычно; для диапазона стихов показываются только стихи диапазона (заголовки раздела между ними тоже);
   - если книги **нет в переводе панели**: карточка **«В переводе {перевод} нет книги «{книга}». Выберите другой перевод вверху.»**;
   - в конце каждого отрывка — **карточка завершения** (§9.4).
3. Нет плана или такого дня (план удалён, индекс вне диапазона): вместо ленты строка **«Этот план удалён или в нём нет такого дня.»** и маленькая кнопка **«Обычное чтение»** (= выйти из плана).

### 9.3. Куда прокручивается при открытии и что запоминается

- Откуда пришли: «Читать» с карточки плана → `at` = номер отрывка (0 = с начала страницы, шапки дня; `>0` — к заголовку отрывка `at`).
- Возврат кнопкой «К плану» → если запомнен отрывок `at` — к нему, иначе к **стиху, на котором ушли** (`ref`).
- Нет ни того, ни другого → к последнему месту панели (`livePositions`/`ref` панели): ищется первый стих ленты с этой книгой/главой/стихом; не нашёл — к началу.
- Пока человек листает, **верхний видимый стих** ленты записывается как положение панели (`livePosition`, `panes.remember`): поэтому «выйти из плана» оставляет в обычном чтении **то же место**.
- Текущий отрывок (`_cur`) = отрывок верхнего видимого элемента ленты.

### 9.4. Карточка в конце каждого отрывка (`_end`)

Сверху вниз:

1. Если отрывок прочитан — строка **«✓ {подпись} — прочитано»** (зелёным); если нет — небольшая контурная кнопка **«Отметить прочитанным»** (значок галочки).
2. Затем **ровно одно из трёх** (по месту отрывка в дне):
   - **не последний отрывок** → главная кнопка **«Дальше: {подпись следующего}»** со стрелкой вниз → прокрутка к началу следующего отрывка;
   - **последний отрывок и все отрывки дня прочитаны** → крупная строка со значком праздника **«План на сегодня выполнен»** и кнопка **«Готово»** (= выйти из плана); если день не последний в плане — ниже контурная кнопка
     **«Читать день {N+1}»** со стрелкой вправо (`openPlanDay(панель, uid, день + 1)`, с начала);
   - **последний отрывок, но есть непрочитанные** → «Осталось:» и плашки подписей непрочитанных отрывков (нажатие — прокрутка к ним).
3. **«Читать дальше — вне плана»** (пунктирная кнопка, две строки): **«Читать дальше: {Книга} {глава}»** и под ним мелко **«не входит в план»**. Показывается, если есть что читать после этого отрывка
   (`planNextAfter`: после диапазона стихов — следующий стих той же главы, подпись «Книга глава:стих»; после главы — следующая глава, подпись «Книга глава»; последняя глава книги — первая глава следующей книги **перевода**; последняя книга — кнопки нет)
   и **это место не входит в сегодняшний день плана** (следующая глава и так есть среди отрывков дня — кнопки нет). Названия книг — из списка книг перевода панели. Нажатие:
   - запоминается «куда вернуться» (`planReturnAt`): следующий отрывок (`i + 1`), а для последнего — первый непрочитанный, иначе этот же;
   - панель переходит на это место **без мигания** (`navigate(..., flash: false)`), что выводит её из режима плана и включает кнопку «К плану · N из M» (§10).

### 9.5. Автоотметка отрывка (раз в секунду)

Таймер 1 с. Тик **пропускается**, если приложение не на экране (не `resumed`) или поверх открыто окно (страница не текущий маршрут). Дальше:

1. Берутся **видимые на экране** элементы ленты (хоть частично: `trailing > 0 && leading < 1`); из тех, что принадлежат отрывку/главе (стихи и подзаголовки глав), собирается множество видимых **ключей единиц** (`unit.key`).
2. Для каждого ключа, **ещё не отмеченного** (`unitDone`): ведётся запись `{t, end}`. `end` становится `true` (и **остаётся**), если среди видимых элементов есть **последний стих этой единицы** и его нижний край на экране (`≤ 1,02` высоты ленты). `t` += 1 за каждый тик, пока единица видна.
3. Единица **отмечается**, когда `end == true` и `t ≥ minSeconds(число стихов единицы)` (§1.7). Секунды копятся суммарно (не обязательно подряд), накопление не сбрасывается при прокрутке, но живёт только пока открыта эта страница.
4. Для отмеченных единиц: если единица — **целая глава** (`to == null`) — глава пишется в `readLog` (`logChapter`) и засчитывается **во все активные планы** (`creditChapter`, §1.6) — это же правило, что при обычном чтении;
   затем текущий план/день отмечается (`markUnits(uid, день, ключи)`); пересобираются напоминания.
5. Сообщения (`Hub.toast`, ≈ 2,6 с, снизу над нижней панелью):
   - день закрыт этой отметкой → **«План на сегодня выполнен 🎉»**;
   - иначе, если отметка завершила **весь отрывок** (все его единицы) → **«✓ Прочитано: {подпись}»** (короткая: «Быт 1»);
   - иначе (отрывок из нескольких глав и пока отмечена не последняя) сообщения нет.

   **Особенность Flutter (вероятный недочёт):** для целой главы сначала срабатывает `creditChapter`, и если этот же день плана (сегодняшний или из пропущенных) закрывается им, то `markUnits` потом возвращает «день уже закрыт», и вместо
   «План на сегодня выполнен 🎉» показывается «✓ Прочитано: …». Для Swift лучше показывать «План на сегодня выполнен 🎉» всегда, когда день закрылся.

### 9.6. «Отметить прочитанным» вручную

Кнопка в карточке отрывка (§9.4): для каждой единицы отрывка — если это целая глава, пишется в `readLog` (`logChapter`, но **без** `creditChapter` в другие планы); `markUnits` по всем единицам отрывка; пересборка напоминаний;
если день закрыт — **«План на сегодня выполнен 🎉»**. Снять отметку на этой странице **нельзя** (снятие — только на карточке плана, §4).

## 10. «К плану · N из M» и выход из плана (`plan_mode.dart`, `plan_return.dart`)

### 10.1. Выход из плана

Способы: «×» в закреплённой строке; «Готово» в карточке завершения; «Обычное чтение» (ошибка); **любой переход** панели (изменился `nav`, а не перевод): поиск, «Перейти», закладка, стих дня, кнопки истории, «Читать дальше — вне плана».
Выход ставит `planMode[панель] = null`. Явный выход («×», «Готово», «Обычное чтение») **сбрасывает** кнопку возврата; выход «по переходу» **запоминает** план: `LastPlan(uid, день, at | ref)`.

### 10.2. Кнопка возврата

Капсула **«↩ К плану · {done} из {total}»** (значок «возврат», `done` — число прочитанных отрывков дня, `total` — число отрывков) и маленькое **«×»** («Скрыть кнопку возврата к плану»).
Стоит **внизу экрана, над мини-плеером аудио/нижней панелью** (колонка в слое `Hub.audioBar`, одна капсула на каждую панель с запомненным планом). Показывается только пока:
план ещё существует и **день не закрыт**.

- Нажатие на капсулу: `returnToPlan(панель)` — запомненное `at`/`ref` передаётся странице, режим плана включается заново, запись «последнего плана» сбрасывается (кнопка исчезает).
- «×»: запись сбрасывается (план остаётся доступным через окно планов).
- Сбрасывается и при `openPlanDay`.
- Пока у панели включён сам режим плана, кнопки нет.

## 11. Засчёт при обычном чтении (`planChapterRead`)

В читалке (`reader_pane.dart`) каждую секунду для каждой видимой главы копится время:

- глава «видна», если на экране есть хоть одна строка с её стихами; время на главе (`_dwell[глава]`) **накапливается суммарно**, не сбрасывается прокруткой; работает только при `resumed`;
- условие засчёта на тике: **последний стих главы сейчас виден** (нижний край ≤ 1,02 экрана) и накоплено ≥ `minSeconds(число стихов главы)`; за сеанс глава засчитывается **один раз** (`_done` — «книга.глава» в памяти панели).

Тогда (`planChapterRead(книга, глава)`):

1. `logChapter` — глава пишется в `readLog`, если за сегодня её там нет (никакого сообщения не даёт).
2. `creditChapter` (§1.6): если глава попала в какие-то планы — сохраняются отметки и пересобираются напоминания (сегодняшний день мог закрыться).
3. Сообщение (`toast`, ≈ 4 с, внизу):
   - день закрыт → **«План «{название}»: на сегодня всё ✓»** (первый из завершивших);
   - иначе → **«Засчитано в план «{название}»: {Книга} {глава}»** (подпись — сокращённая, без «:1»; первый из засчитанных);
   - не засчитана ни в один план — сообщения нет (только история).

Страница «План на день» (§9) этим путём не идёт: пока она включена, читалка панели не строится, и считает сама страница (§9.5). Вторая панель обычного чтения считает как обычно.

## 12. «Картинка со стихом» (`VerseImageSheet`)

### 12.1. Вход

- Стих дня → «Картинка» (одна ссылка);
- панель выделения → меню «⋯» → **«Картинка со стихом»** (любое число выделенных стихов, `refs` по порядку Библии, **перевод панели**).

Окно поверх остальных, почти на всю высоту; заголовок **«Картинка со стихом»**, подзаголовок — подпись выбранных стихов с **полными** названиями (`selectionLabel(refs, full: true)`: «От Иоанна 3:16–18» / «От Иоанна 3:16, 18» / «…; …»).
Содержимое — колонкой не шире `textWidth × размер шрифта` читалки.

### 12.2. Расположение (сверху вниз)

1. **Предпросмотр** картинки по центру (ширина не больше 340, у формата «История» — не больше 250, с боковыми полями 20; пропорции выбранного формата). Пока фон/фото не готовы — индикатор загрузки вместо картинки.
2. Горизонтальная **полоса фонов** (на всю ширину, края затухают): плитки 52 × 64, выбранная — рамка акцента. Порядок: **своё фото** (если выбрано; подсказка «Своё фото»), **фото с сайта** (по порядку `index.json`, подсказка — название фото, миниатюра `thumb`), затем **6 градиентов** (подсказка — название).
3. Кнопка на всю ширину **«Своё фото»** (значок картинки с плюсом).
4. Сегмент **форматов**: **«Квадрат»** | **«Пост»** | **«История»**.
5. Подсказка по центру: **«Двигайте текст пальцем, размер — двумя пальцами.»**
6. Строка **«Размер текста»**: слева подпись; справа (если масштаб ≠ 1 или текст сдвинут) подчёркнутая ссылка **«как было»**, затем кнопки **«−»** («Мельче») и **«+»** («Крупнее»).
7. Два равных по ширине действия: **«Поделиться»** (главная, значок «поделиться») и **«Сохранить»** (значок «скачать»). Неактивны, пока картинка грузится или идёт работа.
8. Внизу мелко (если выбрано фото сайта): **«Фото: {название} — {автор} ({лицензия})»** (автор — если есть).

### 12.3. Форматы и размеры файла

| Формат (подпись) | Ключ | Размер файла (пикселей) | Пропорция |
|---|---|---|---|
| Квадрат | `square` | 1080 × 1080 | 1 : 1 |
| Пост | `post` (по умолчанию) | 1080 × 1350 | 4 : 5 |
| История (с пояснением «формат картинки: вертикальная, для «историй» в соцсетях») | `story` | 1080 × 1920 | 9 : 16 |

Смена формата **пересчитывает базовый размер букв**, масштаб и сдвиг **не сбрасываются**.

### 12.4. Фоны

- **Фото сайта** (12 штук): растягивается «заливкой» (cover) на весь холст; поверх вертикальное затемнение чёрным (сверху/середина/низ): для светлых фото `0,45 / 0,55 / 0,67`, для тёмных `0,28 / 0,38 / 0,50`. Текст — **всегда белый** с лёгкой тенью.
- **Своё фото**: выбирается из галереи (`pickBgImage`), затемнение как у тёмных фото; хранится **только** на время этого окна, никуда не сохраняется.
- **Градиенты** (`id`, название, три опорные цвета сверху-слева → вниз по диагонали, тон): `g-dawn` «Рассвет» `3B2A4D → C0705A → F1C27D` (тёмный); `g-sea` «Море» `0F2F45 → 1F6D86 → 7FB7C4`; `g-olive` «Олива» `2C3523 → 5D6B3C → A3A46B`;
  `g-night` «Ночь» `0B1020 → 1D2440 → 3B3F66`; `g-paper` «Бумага» `F6EFE1 → EFE3C8 → E5D3AD` (светлый, **текст тёмный `2D2418`, без тени**); `g-stone` «Камень» `2B2A28 → 4A4741 → 6D675C`. Диагональ идёт не по углам, а под углом ≈ 0,4 ширины.
- Первый выбранный фон при открытии — **первое фото из списка** (когда список пришёл); пока списка нет, выбран `g-dawn`. Фото не загрузилось (нет сети/кеша) — **тот же текст на градиенте `g-dawn`** без сообщения.

### 12.5. Текст на картинке

- Текст = тексты стихов выбранных ссылок (из **перевода панели/стиха дня**, без разметки), через пробел, пробелы сжаты; стихов нет — пропускаются. Выводится в «ёлочках» **«…»**, по центру, шрифт **PT Serif**, межстрочный 1,38, максимальная ширина **78 %** холста.
- **Базовый размер букв** (`fit`): начинается с **74** и уменьшается шагом 2, пока высота текста не станет ≤ **62 %** высоты холста (у «Истории» — **55 %**) или размер не дойдёт до **26**. Итоговый размер = `max(14, базовый × масштаб)`.
- **Ссылка** под текстом: короткая белая черта 80 × 3 по центру (непрозрачность 0,75), под ней подпись выбранных стихов (**полные** названия) шрифтом **PT Sans** полужирным размера `max(18, размер текста × 0,6)`. Весь блок (текст + черта + ссылка) центруется по вертикали:
  высота блока = высота текста + `размер_ссылки × 2,2`; верх = `(H − блок)/2 + dy × H`; центр по горизонтали `W/2 + dx × W`.
- Запасные шрифты, если PT Serif / PT Sans недоступны: для текста Georgia, затем системный serif; для ссылки Segoe UI, затем системный sans-serif.

### 12.6. Жесты и размер

- **Один палец** — сдвиг текста: `dx`, `dy` — доли ширины и высоты предпросмотра, диапазон **−0,45…+0,45**.
- **Привязка к центру**: если `|dx| < 0,025` — `dx = 0` (то же для `dy`); в момент «залипания» срабатывает лёгкая вибрация (`selectionClick`), пока текст ведут и он прилип, показывается **тонкая белая направляющая** (вертикальная и/или горизонтальная, 140 мс).
- **Два пальца** — масштаб (`стартовый × scale`), диапазон **0,4…2,2**; пальцы одновременно сдвигают текст.
- Кнопки «−» / «+»: шаг **0,1** (с округлением до сотых), те же границы. «как было» сбрасывает масштаб в 1 и сдвиги в 0 (ссылка показана, только если что-то менялось).

### 12.7. «Поделиться» и «Сохранить»

Обе действуют, только когда картинка готова и нет другой работы; оба рисуют **PNG** нужного формата (1080 пикселей по ширине) во временный файл с именем **подписи (полной) с заменой пробелов и двоеточий на `_`** (например, `От_Иоанна_3_16.png`).

- **«Поделиться»** — системное окно «Поделиться» с файлом (`image/png`) и заголовком = подпись.
- **«Сохранить»** — Android: копия файла в **«Pictures/AO Bible»** и сообщение **«Картинка сохранена»**; если общая папка недоступна (в том числе **iOS**) — то же системное окно «Поделиться» (оттуда можно «Сохранить изображение»). На iOS прямой записи в «Фото» нет **[Swift: решить, делать ли запись в Фото; ее нет и во Flutter]**.

  └ «Свой план» ─ «Начать» ─► makeCustomPlan/makeParallelPlan ─► plans.add ─► scheduleReminders()
PlanView (режим панели; planMode[pane]={uid,day})
  ├ автоотметка (1 с) ─► readLog + creditChapter(все планы) + markUnits ─► toast (Hub.toast) ─► scheduleReminders()
  ├ «Дальше» / вкладки строки плана ─► прокрутка

  ├ «Читать день N+1» ─► openPlanDay(pane, uid, день+1)

## Расхождения со Swift (что нет / что иначе)

Проверено по: `Views/PlansView.swift` (PV), `Views/PlanDayView.swift` (PD), `Views/CustomPlanView.swift` (CP), `Views/VerseImageView.swift` (VI), `Core/PlanLogic.swift` (PL), `Core/PlanStreams.swift` (PS),
`Core/PlansStore.swift` (ST), `Core/Reminders.swift` (RM), `Views/ReaderView.swift` (RV, строки 365–380, 535–560), `RootView.swift` (RT).

### А. Данные и логика

1. **Совпадает:** формат `Plan` (все поля Flutter), `calendarIndex`, `todayIndex`, `behindDays`, `readingUnits`, `unitDone`, `readingDone`, `markUnits`, `creditChapter`, `applyNewYear`, `minSeconds`, подсчёт серии/недели/всего, `splitChapters`, потоки и их правила
   (PL, PS), список стихов дня (366, `Resources/verses_of_day.txt`) и формула (ST `VerseOfDay`). Импорт данных Flutter: `flutter.plans`/`flutter.readLog` (ST init).
2. Хранение: Swift — файлы `plans.json`, `readlog.json` в «Application Support» (ST), Flutter — ключи prefs `plans`/`readLog`. «Мои данные» (`exportEntries`) отдаёт только `plans` и `readLog`: **нет** `planReminder`, `customPlan*` (Swift держит их в `reminderOn`, `reminderTime`, `cp.*` через `@AppStorage`). Файл Swift, восстановленный во Flutter, **сбросит** напоминания и настройки «Своего плана»; файл Flutter в Swift их игнорирует.
3. **Нет операции «снять отметку»**: в ST только `mark` (добавляет). Кружок отрывка в карточке (PV `PlanCard`) при повторном нажатии ничего не делает; снять отметку дня/отрывка нельзя нигде (во Flutter §1.6 `_toggle`/`_togglePart`). Нужны `toggleDay`, `togglePart` и `replace(plan)`.
4. `PlansStore.add` **запрещает дубликаты** (`has`: тот же готовый план или тот же свой набор) и показывает «Этот план уже добавлен» / «План уже добавлен»; Flutter допускает любое число одинаковых планов (§7.2). Каталог в Swift помечает начатые галочкой; Flutter — плашкой «идёт» и не блокирует «Начать». Решить, какое поведение оставить.
5. Нет `ReadStats.recent` (последние 30 глав для плашек, §6 п. 5) — PL `stats` его не считает.
6. `PlanLogic.readingLabel` берёт `Books.info(...).short` — **только русские** сокращения из `books.json`; Flutter — справочник языка интерфейса (подписи в картах, уведомлениях, на странице дня). Названия своих планов в Swift тоже всегда по-русски (CP `create`: «за … дн.», «параллельно», «и ещё» зашиты строками).
7. Нет кеша сайта на диске (§1.3): `Net.json`/`AsyncImage` каждый раз идут в сеть; без интернета нет каталога, обложек, фото дня и фонов картинки. Нужен кеш `plans/index.json`, файлов планов и `images/verse-bg/*`.

### Б. Окно «Планы» (PV)

8. Состав и порядок блоков другой. Swift: Стих дня → **Статистика → Напоминание (всегда)** → планы → каталог → «Свой план» (строкой-ссылкой). Flutter: Стих дня → планы → **Напоминание (только при планах)** → Статистика → «Ещё планы»/«Выберите план» → каталог → карточка «Свой план» (§2).
9. **Статистика** (PV `StatsCard`): четыре числа + столбики без кольца «% Библии», без серии с пламенем, без строки «Сегодня … Глав Библии … из 1189», без подсказки «!» и **без плашек последних глав** (нажатие → переход к главе). Нет VoiceOver-подписи «За 7 дней».
   Число глав «за неделю» Swift показывает, Flutter — нет (§0 п. 1). Букву дня недели Swift берёт всегда по-русски (`Locale("ru")`).
10. **Карточка активного плана** (PV `PlanCard`): нет обложки с фото, строки «{done} из {total} дн. · N%» (есть только круговое кольцо 48 pt), полосы прогресса, **ленты дней 1…7**, выбора другого дня, строки «День N · сегодня/пропущен», «Догнать ›» (в Swift «Пропущено дней: N» — просто текст), счётчика «{done} из {total} отрывков», ограничения «5 + Ещё N / Свернуть», кнопок «Продолжить/Перечитать/Отметить/Прочитано».
    Показывается всегда **сегодняшний** день (`planToday`), не «первый непрочитанный после сегодняшнего». Есть то, чего нет во Flutter: «День N из M» и ссылка «Все дни и настройки» (PV `PlanDetailView`).
11. **«Читать»**: Swift — кнопка «Читать весь день» открывает **лист** `PlanDayView` (§В); отдельные отрывки открывают место в **обычном чтении** через `openVerse` (вкладка «Библия»), страница плана в панели не включается. Во Flutter — режим панели (§9).
12. **Удаление плана**: Swift — в `PlanDetailView` (кнопка «Удалить план» → диалог «Удалить план «…»? Отметки прочитанного пропадут.» с «Удалить»/«Отмена»); Flutter — корзина на обложке и красная «Удалить» на 3 с, без диалога (§4.3). Выберите единый вариант.
13. **Каталог**: Swift — `NavigationLink` на `PlanPreview` (описание, «Длительность», «Отрывков всего», «В день», «Чтения по дням» полным списком, кнопка «Начать план»); Flutter — строки раскрываются на месте: миниатюра с фото и значком раздела, `short`, «N дн.», «идёт», описание, «до {дата}», «Начать». В Swift нет миниатюр, значков разделов, «до {даты}» и индикатора загрузки «Загружаю планы…»;
    ошибка — кнопка «Не удалось загрузить список планов. Повторить» (Flutter: красный текст «Список планов недоступен», повтор при повторном открытии окна).
14. Нет сообщения-предложения «Напоминать о чтении» после «Начать» и текста «…— нажмите «Читать»» (Swift: «План «X» начат» без хвоста, сообщение 2,5 с сверху; Flutter — снизу ≈ 4 с, с кнопкой 5–6 с). Нет автоматической прокрутки к новой карточке.
15. **Стих дня** (PV `VerseOfDayCard`): фото берётся `AsyncImage` с `Net.bases[0]` (без кеша), нет затемнения по `tone` (всегда 0,15…0,6); шрифт фиксирован (24 pt serif), а не шрифт/размер читалки (20,8…28 по ширине экрана); подпись берёт имя книги из модуля — совпадает;
    «Поделиться» отдаёт `«текст» — От Иоанна 3:16 (Перевод)`, Flutter — `"текст" - Ин. 3:16` (§3.3); если стиха нет — показывается текст «Скачайте перевод Библии, чтобы увидеть стих дня.», Flutter карточку скрывает; кандидатов-переводов Swift собирает из `panes.primaryModule` и по языку интерфейса, исключая подстрочники
    (Flutter — перевод первой панели, основной, потом остальные; подстрочники отдельно не исключаются) **[уточнить, что даёт `panes.primaryModule`]**. Проверка: на 2026-11-08 должен выходить `2Tim.1.7`.
16. Нет открытия окна планов по нажатию на уведомление (в RT/RM нет делегата `UNUserNotificationCenterDelegate`); вкладка «Планы» в Swift есть (RT), пункт в «Ещё» на iPhone не нужен (во Flutter он только на широком экране).

### В. Страница «План на день» (PD)

17. Swift — **лист** на `ScrollView` с отрывками подряд (заголовок «{план} · день N», «Закрыть», «Прочитано», кружок у каждого отрывка), текст — упрощённый (`Text(num) + Text(Markup.plain)` без `VerseView`): **нет** слов/Стронга, выделения, закладок, заметок, панели выделения, «Части стиха».
    Перевод — `panes.primaryModule` (не перевод панели).
18. **Нет**: закреплённой строки плана («День N · done/n», вкладки-отрывки, «×»), шапки дня, подзаголовков «Псалом/Глава», заголовков с «✓ Прочитано», **автоотметки** (отметка только кнопками), карточки завершения («Отметить прочитанным», «Дальше: …», «План на сегодня выполнен», «Готово», «Читать день N+1», «Осталось:»), «Читать дальше — вне плана», пояснения «Читайте подряд…», сообщения «Книги нет в переводе», прокрутки к отрывку `at`, запоминания места.

21. Нет пояснения «Книги нет в переводе»: вместо него `ContentUnavailableView("Нет перевода или плана")` для обоих случаев.

### Г. Свой план (CP, PS)

22. **Совпадает по логике:** режимы «Последовательно»/«Параллельно», «Глав в день»/«За срок», шесть разделов, 1–10 глав в день, «Первый день», нагрузка «≈ N гл. в день · до …» (красным при > 60 мин), быстрые сроки (6 плашек), диапазон 7…730, сетка «Свои книги», `makeParallelPlan` (в том числе по кругу и дедупликация).
23. Расположение: Swift — **отдельная страница** `NavigationLink`/`Form`, после «Начать» страница закрывается (`dismiss`); Flutter — карточка внизу окна планов, окно остаётся, список прокручивается к новому плану.
24. Хранение выбора: Swift запоминает ещё **раздел и срок** (`cp.scope`, `cp.days`) — Flutter нет (при каждом открытии «Новый Завет», 90 дней); ключи `cp.*`, а не `customPlan*` (§А п. 2); «Свои книги» — отсортированный список через запятую.
25. Ввод числа дней: Swift — системный `Stepper` (шаг 1, с 60 — шаг 10), **вписать число нельзя**, под числом нет подписи «день/дня/дней»; Flutter — капсула «− [число] +» с вводом и склонением, шаг всегда 1.
26. `scopeBooks("all")`/`("ot")` и `PlanLogic.streamBooks("ot")` берут все книги `t == "OT"` — в `books.json` это 69 книг, из них ~30 **неканонических** (`dc`: Товит, Премудрость, 1 Еноха, Юбилеи, Заветы…); Flutter их исключает (`!b.dc`). Сетка «Свои книги» (CP `BookPicker`) показывает все книги Завета,
    а не только те, что есть в переводе плана (Flutter — `planBookIds`). Поле `dc` из `books.json` Swift-модель `BookInfo` не читает — добавить **[проверить, что в `Resources/books.json` оно есть]**. **[проверить на устройстве]**: «Вся Библия» и «Ветхий Завет» не должны включать неканонические книги, даже если они есть в модуле (в сетке «Свои книги» их оставлять можно, как во Flutter, — только если они есть в переводе).
27. Кнопка: Swift меняет подпись на «Выберите книги» и при `needOwn`; Flutter — только при `_parDays == 0`. Мелочь.
28. Кнопка «Начать»: Swift в режиме «Параллельно → За срок» без единого раздела делает кнопку **неактивной** (`canStart`); Flutter её не блокирует, а после нажатия показывает «Выберите книги». Мелочь.

### Д. Напоминания (RM, PV)

29. Swift: **одно** ежедневное напоминание (DatePicker, по умолчанию 20:00); Flutter — любое число напоминаний (по умолчанию 08:00), промежуток «с … до … каждые N», дни недели, будильник, колёсики времени, «Повтор», плашка разрешений (§5). Не хватает: модели `ReminderItem`, хранения `planReminder`, экрана настройки, расписания по алгоритму §5.4.
30. Расписание Swift — **7 дней**, id `reminder-i`, заголовок «AO Bible», текст «Время читать Библию.» либо **только первого** подходящего плана: `«{план}: Быт 1 · Мф 1»` через « · »; Flutter — **14 дней**, заголовок «Чтение на сегодня», текст `«{план}: Быт 1, Мф 1»` (по строке на каждый план, через запятую), и **только непрочитанные дни** на каждую дату.
31. Swift при `i > 0` не проверяет, закрыт ли будущий день (читали вперёд — всё равно напомнит); после окончания плана `planToday` держится на последнем дне, поэтому напоминания по закончившемуся плану продолжаются (Flutter: `planDayOn` → `null`, напоминаний нет). Календарный план на дату `day` считается верно.
32. Swift показывает переключатель напоминаний **всегда** (даже без планов) и при отсутствии планов шлёт «Время читать Библию.»; Flutter карточку скрывает без планов и уведомлений не создаёт.
33. `Reminders.schedule` делает `removeAllPendingNotificationRequests()` — снимает **все** запланированные уведомления приложения, а не только свои (Flutter отменяет id `7000…7199`); идентификаторы Swift — `reminder-0…6`. Лимит iOS 64 уведомлений при 14 днях × N моментов нужно обрабатывать (§5.5).
34. Нет: делегата уведомлений (нажатие открывает приложение, но не «Планы»), будильника (`interruptionLevel = .timeSensitive` + entitlement), показа в «Фокусе», предложения включить напоминания после «Начать».
35. При включении напоминания Swift не показывает сообщения об успехе («Напомню в {time}» / «Напоминания включены»); при отказе в разрешении текст «Уведомления запрещены — разрешите их в настройках телефона» совпадает.

### Е. Учёт при обычном чтении (RV, ST)

36. **Условие засчёта другое.** Swift: после появления в конце главы невидимого маркера (`Color.clear.onAppear`) запускается таймер `minSeconds(стихов)` **подряд**; уход маркера с экрана (`onDisappear`) его отменяет, так что глава считается, только если конец главы
    остаётся на экране `minSeconds` без перерыва (для главы в 30 стихов — 75 секунд на последнем экране). Flutter: время **копится по всей главе**, пока она видна (в сумме), а условие — последний стих **виден** на тике, когда накопленное время достигло порога (§11). Нужно перенести правило Flutter, включая «только приложение на экране» (`resumed`)
    и дедупликацию за сеанс.
37. Сообщение при засчёте: Swift «Засчитано в план «X»» (без подписи главы) и «План «X»: на сегодня всё ✓», сверху на 2,5 с; Flutter — «Засчитано в план «X»: Ин. 3» и то же второе, снизу ≈ 4 с (§11). После засчёта Swift не пересобирает напоминания отдельно (но `savePlans` их пересобирает).
38. Нет автоотметки на странице дня (см. В) и нет «Отметить прочитанным» без перехода.

### Ж. «Картинка со стихом» (VI)

39. Фоны: Swift — **4** градиента (`g-stone`, `g-night`, `g-dawn`, `g-paper` с **другими цветами**), Flutter — **6** (`g-dawn`, `g-sea`, `g-olive`, `g-night`, `g-paper`, `g-stone`, §12.4). Порядок плиток Swift: «Своё фото», градиенты, фото; Flutter: своё фото (после выбора), **фото**, градиенты. Кнопка «Своё фото» в Swift — первая плитка полосы (`PhotosPicker`), Flutter — отдельная кнопка на всю ширину под полосой.
    Первый выбранный фон: Swift — первое фото (после загрузки списка, пока `g-stone`), Flutter — первое фото (пока `g-dawn`). Нет выделения плитки **своего** фото в полосе и его миниатюры.
40. Форматы: названия «Квадрат», «4:5», «9:16» (Flutter — «Квадрат», «Пост», «История»); размеры файла эквивалентны (1080 × 1080 / 1350 / 1920). Предпросмотр фиксирован 330 pt (Flutter ≤ 340, «История» ≤ 250).
41. Размер текста: Swift `baseFont` — по **длине текста** (`0,04…0,085` ширины), без подгонки по высоте (Flutter `fit`: 74 → 26 шагом 2, ≤ 62 %/55 % высоты). Масштаб Swift 0,5…2,5 (слайдер, «как было»), Flutter 0,4…2,2 (кнопки «−»/«+» шаг 0,1, «как было» видна только при изменениях); у Swift нет кнопок «Мельче»/«Крупнее».
    Жесты: сдвиг пальцем есть; **нет** ограничения ±0,45 и привязки к центру с вибрацией и направляющими; щипок есть (`MagnifyGesture`).
42. **Цвет текста**: Swift делает текст **тёмным (`2A1A12`)** на светлых фото (`tone == light`) и белым на тёмных; Flutter всегда белый на фото (светлые фото затемняются сильнее, 0,45…0,67), тёмный `2D2418` только у «Бумаги» без фото. Затемнение Swift — плоское 0,28.
    Тень: Swift `radius 8` при фото; Flutter — тень у всех, кроме «Бумаги».
43. Текст и ссылка: Swift — стек «ёлочки + ссылка» с отступами `baseFont × 0,7`, без черты 80 × 3; шрифты `PT Serif`/`PT Sans`; ссылка `ref`, пришедшая от вызывающего (стих дня — `имя книги + глава:стих`; читалка — `bookName + chapter:range`) — формат подписи нужно привести к `selectionLabel(full)` (§2 `03-bookmarks.md`).
44. **Нет «Сохранить»** (есть только «Поделиться» в панели инструментов, `ShareLink`), нет блокировки кнопок и индикатора при загрузке (есть `ProgressView` вместо кнопки), нет подписи «Фото: …» — **есть** (совпадает), нет имени файла из подписи, нет сообщения «Картинка сохранена».
45. Рендер: Swift готовит картинку с задержкой 0,35 с после любого изменения (`ImageRenderer`); Flutter рисует по запросу «Поделиться»/«Сохранить» (задержки в UI нет).
46. Нет входа «Картинка со стихом» из **панели выделения** в нескольких стихах из разных глав; в Swift вход есть из меню «⋯» читалки (RV, строка 824: текст объединяется через пробел; `ref` строится как «{книга} {глава}:{диапазон}») — согласовать формат подписи.

### З. Не относится к iPhone / отложено

47. Виджет «Стих дня» (§13) — Android; для iOS нужен WidgetKit **[отдельная задача]**.
48. Запись PNG в «Pictures/AO Bible» — Android; на iPhone Flutter тоже ведёт в «Поделиться» (§12.7).

### И. Что совпадает

Формат `plans`/`readLog` и их ключи; логика дня, календарного плана (29 февраля), пропущенных дней, смены года, `markUnits`/`creditChapter`/`applyNewYear`/`minSeconds`/серии/недели/всего; `splitChapters`, потоки, `parallelDays`, `makeParallelPlan`, `firstDayText`, нагрузка «≈ N гл. в день · до …»;
